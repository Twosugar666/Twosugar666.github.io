学习笔记｜DENSE：把无结局标签的轨迹蒸馏成证据接地的嵌套 Shortcut 树

2026-09-22 · 收藏夹：Harness / Agent · 学习笔记
论文：Liu, Yu et al.（Fudan / Meituan Longcat）· DENSE: Distilling Agent Trajectories into Evidence-Grounded Shortcut Trees for Self-Refinement · arXiv:2609.21423。 交叉： Context Compaction、 Ralph Loop、 RIR、 Harness Design Study、 T1。

背景与动机

线上 Agent 不断吐出长轨迹：试错、局部修好、还有没收口的交付物。 离线评测可以挂隐藏 verifier 或人工标签；线上同规模监督成本扛不住。 问题变成：没有 post-hoc 结局标签时，轨迹里还剩什么可复用？

DENSE 的设定叫 post-hoc outcome blindness：反馈只能来自任务描述 + 已完成执行轨迹； 禁止 post-hoc reward、隐藏 verifier、参考答案、人类对错标签。 轨迹里执行期看见的公开测试输出仍可用——那是过程观察，不是事后判决。

一句话：嵌套子任务树 → 压缩成 shortcut（死路 + 可行路径 + 证据）→ 跨层用恢复证据和解问题 → 完成枝摘要 / 未完成枝展开；REFIT 下四模型 strict pass 相对 run0 +7.12–15.64 pp，token −19–43.6%（作者自报）。

机制拆解

① REFIT：公平比「反馈有没有用」

# REFIT（示意）
run0 = A(task, feedback=None, env=e0)          # 共享源轨迹
f_g  = g(task, tau0)                          # 各方法只看 task+tau0（outcome-blind）
run1 = A(task, feedback=f_g, env=reset(e0))   # 环境 + 模型上下文全重置
# 反馈是 run0→run1 的唯一信息通道
U(g) = E[ strict_pass(run1) − strict_pass(run0) ]
约束含义
共享 run0各反馈方法吃同一源轨迹，避免「源质量」混淆
重置 env + context历史文件/进程不在；不能「报告旧 CSV 当新交付」
Outcome blindness生成反馈时看不到事后 reward / 隐藏测
VF 单独标 privileged带事后 verifier 的上界参考，不与非特权方法混排冠军

与站内 Ralph Loop 对照：Ralph 是拦退出、清窗重注目标的外环续跑；REFIT 测的是「从旧轨迹抽出的反馈」在全新尝试上的效用。 与 RIR 对照：RIR 回滚环境状态并保留反思记忆；DENSE 不回滚源轨迹，而是蒸馏后交给重置后的 run1。

② DENSE 两阶段

阶段操作产出
嵌套子任务树 按时间队列找语义边界；叶子=(动作,观察)；自底向上挂父节点并做局部诊断 带目标作用域的层次结构
Shortcut + 和解 + 渲染 同父下连续尝试压成 shortcut；跨层用恢复证据关问题；完成枝短摘要、未完成枝展开证据 有界反馈：可复用路径 ↔ 剩余义务 
# Shortcut 保留什么（示意）
shortcut = {
  dead_ends:   [...],   # 已证实走不通的路
  working_path:[...],   # 观察支持的可行做法
  evidence:    [...],   # 源动作/观察引用
  open_issues: [...]    # 未满足要求（未完成枝）
}

# 跨层和解：子问题被后继子任务修好 → 父层关掉；根仍保留未交付物
# 例：summary.json 已写回校验 → 关「缺 JSON」；chart.png 仍缺 → 根保留

关键纪律：局部恢复 ≠ 父任务完成；历史上成功 ≠ 重置后当前已交付。 反馈必须显式绑定「证据支持了什么」和「下一轮还要做什么」。

⑤ MiniMax 案例：别把历史 CSV 当成当前交付

Verifier Feedback 把「run0 已通过」的测试报告塞进反馈后，recipient 可能零工具调用直接声称 /app/summary.csv 已写好——重置环境里文件并不存在。 DENSE 把完成范围标成 trajectory-local，并保留构造脚本的 key-action；recipient 在新环境重跑分析脚本、读回 CSV，才真正过测。 工程含义：privileged 结局信号若缺少「必须重建」的作用域，会强化历史成功误用。

实践建议

  • 线上轨迹先当证据库，再谈标签。 没 verifier 也能抽 dead-end / working-path / open-issue；REFIT 式 A/B 用重置后的 strict pass 量反馈效用。
  • 反馈模板强制写作用域。 「历史上完成」≠「当前环境已有文件」；开头就写 fresh-env 重建义务（论文 recipient wrapper 同向）。
  • 完成枝摘要、未完成枝展开。 全量回放轨迹费 token 且易淹没交付步骤；与 Compaction「先规则裁再摘要」同哲学。
  • 跨层和解要证据，不要口头关掉问题。 子任务修好 JSON 才能关父层「缺 JSON」；否则 open-issue 漂移。
  • 别只贴 reward=1。 MiniMax 案例显示 privileged 报告可诱导零工具「假完成」；保留构造过程往往比贴结局更稳。
  • 与 Ralph / RIR 分工。 同会话续跑 → Ralph；环境回滚+反思 → RIR；跨次重置复用旧轨迹 → DENSE。日志里分开记通道。

思考题

1. Post-hoc outcome blindness 允许哪些信息、禁止哪些？

允许：任务说明、轨迹中的动作/观察（含执行期公开测试输出）。禁止：事后 reward、隐藏 verifier 诊断、参考答案/参考轨迹、人类对错标签。目的是逼反馈方法从轨迹证据本身提炼可迁移物。

2. 为什么环境与上下文都要重置？

若不重置，run1 可能直接读旧文件「续命」，测的是状态残留而非反馈信息量。重置后反馈是唯一转移通道，U(g) 才归因到蒸馏质量。

3. Shortcut 里同时留 dead-end 与 working-path 的理由？

Working-path 给可复用做法；dead-end 避免重复无效探索。只留成功摘要会丢「别再试 pandas/错误分隔符」这类负样本，run1 容易重踩同一坑。

4. 消融里去掉 hierarchy 或 S&R 后，准度与 token 如何变化？

作者自报 GPT-5.5：full 75.66% / 179.9K；无 S&R 72.28 / 228.6；无层次 72.66 / 199.2。两者都掉点，且完整管线最省 token——层次压缩与问题和解共同提高反馈信噪比。

5. DENSE、Ralph、Compaction、RIR 各管哪类失败？

Compaction：窗内防 overflow。Ralph：退出后清窗续跑。RIR：回滚环境+保留反思。DENSE：无结局标签下把旧轨迹炼成重置后仍可用的嵌套证据反馈。可叠加，指标分开。
