学习笔记｜ORPO：用 Odds Ratio 把偏好罚项并进 SFT（无 reference model）

2026-09-22 · 收藏夹：算法 / RL · 学习笔记
经典：Hong, Lee, Thorne · ORPO: Monolithic Preference Optimization without Reference Model （EMNLP 2024）· arXiv:2403.07691。 交叉： DPO、 SimPO、 KTO、 KL 散度、 GRPO。

背景与动机

常见对齐管线是两段：先对 chosen 做 SFT，再挂冻结的 π_ref 跑 DPO / RLHF。 SFT 单独训 chosen 时，rejected 风格的似然也会跟着抬——交叉熵只抬标签 token，不罚「不该说的话」。 于是需要第二阶段显式拉开胜负。

ORPO（Odds Ratio Preference Optimization） 把弱惩罚直接并进 SFT： 同一阶段、同一模型，对 chosen 做 NLL，同时用 odds ratio 压低 rejected—— monolithic、reference-free，省掉单独对齐阶段与参考模型前向。

一句话：L_ORPO = L_SFT(x,y_w) + λ · (−log σ(log OR(y_w,y_l)))；用 odds 比概率比更温和地区分风格，单阶段完成域适应 + 偏好。

机制拆解

① Odds 与 Odds Ratio

# 序列平均 log 似然（作者记号；实现对 response token 求和/平均需一致）
log P_θ(y|x) = (1/m) Σ_t log P_θ(y_t | x, y_<t)

# Odds：生成 y 相对「不生成 y」的倍率
odd_θ(y|x) = P_θ(y|x) / (1 − P_θ(y|x))

# Odds ratio：chosen 相对 rejected 有多「更像会被生成」
OR_θ(y_w, y_l) = odd_θ(y_w|x) / odd_θ(y_l|x)

直觉：odd=k 表示「生成该回复」比「不生成」大约 k 倍可能；OR>1 表示模型更偏向 y_w。 相对直接用概率比 P(y_w)/P(y_l)，odds 在并进 SFT 时对比度更温和，不易把 rejected token 压到退化（作者对比 PR vs OR）。

② ORPO 目标

# 单阶段目标
L_ORPO = E_{(x,y_w,y_l)} [ L_SFT(x, y_w) + λ · L_OR ]

# SFT：对 chosen 的因果 LM NLL（最大化 P(y_w|x)）
# Odds-ratio 罚项：
L_OR = − log σ( log OR_θ(y_w, y_l) )
     = − log σ( log odd(y_w|x) − log odd(y_l|x) )

# λ：偏好罚项相对 SFT 的权重（作者在 Phi-2/Llama-2/Mistral 上用约 0.1–0.25）
符号作用
L_SFT域适应 / 指令跟随：抬高 chosen
L_OR拉开 odd(y_w) 与 odd(y_l)；σ 包 log OR 便于最小化
λ罚项强度；过大易过拟合 chosen 风格、伤硬答案类题
π_ref不出现——无参考模型前向

梯度直觉（作者）：当 OR 已够大时惩罚项权重变小；对低似然一侧的梯度被 1/(1−P) 放大——chosen 还不够像时加速适应，rejected 仍高时加速打压。

③ 与 DPO / SimPO / KTO

Reference要 π_ref不要不要 常要 KL 项

核心项β log(π/π_ref) + BTβ·avg logprob + margin γNLL(y_w) + λ(−log σ(log OR)) 前景理论效用

SimPO 也是 reference-free，但仍是「偏好优化目标」本身，通常接在 SFT 之后； ORPO 显式保留 L_SFT，把偏好做成 SFT 的附加罚项。 KTO 解决无配对；ORPO 仍要 (y_w, y_l)。 与 KL：DPO 的 π_ref 来自 KL 约束最优解；ORPO 用 odds 罚项代替显式 KL 锚。 可验证任务仍优先 GRPO / PPO，不要硬替。

实践建议

  • 想要一阶段 SFT+对齐、且显存紧 → 优先试 ORPO。 省 π_ref 前向；仍需成对偏好。
  • λ 从小扫。 作者常用约 0.1–0.25；λ 过大易过度贴 chosen、伤 math/抽取等硬答案（作者 MT-Bench 消融同向）。
  • P(y|x) 实现要统一。 公式用序列级概率（常取长度归一的似然）；与 token NLL 混用会导致 OR 尺度乱跳。
  • 仍要高质量偏好对。 Monolithic 不降低标签噪声敏感度；y_w≈y_l 时 OR 信号弱，需过滤。
  • 与 SimPO/DPO 对照时写清阶段。 比的是「SFT+DPO 两段」还是「ORPO 一段」；算力与数据预算要对齐。
  • 有执行奖励别硬换 ORPO。 代码/数学可验证场景用 GRPO；ORPO 主场是偏好风格对齐。

思考题

1. 为什么纯 SFT chosen 还会抬高 rejected 风格？

交叉熵只对标签 token 施压；非标签 token（含 rejected 风格里的词）没有直接负梯度。域适应时对话/指令分布整体抬升，rejected 回复的似然常同步上升，偏好未被编码。

2. Odds ratio 相对概率比 P_w/P_l 在「并进 SFT」时有何好处？

作者认为 OR 对比度更温和：用 PR+log-sigmoid 时，为压低 loss 往往更极端地打压 rejected，在模型尚未适应域时易过度抑制、甚至退化。OR 在拉开偏好的同时更利于保留 SFT 域适应。

3. ORPO 为何不需要 reference model？

偏好信号来自同一 π_θ 上 y_w 与 y_l 的 odds 对比，再叠加对 y_w 的 NLL；不依赖「相对 SFT 参考策略的 KL 最优重参数」。代价是失去显式 KL 锚，需靠 λ、数据与早停托底。

4. ORPO 与 SimPO 同是 reference-free，选用差异在哪？

SimPO：偏好阶段用长度归一平均 logprob + margin，通常接在 SFT 后。ORPO：把偏好罚项写进 SFT 目标，强调单阶段。显存都省 ref；是否已有稳定 SFT checkpoint、以及想不想合并阶段，决定选型。

5. λ 过大可能出现什么现象？

过度拉大 chosen/rejected 间隔，模型贴训练集 chosen 文风；开放生成或被偏好裁判喜欢，但 math/reasoning/extraction 等硬答案项变差（作者 λ 消融）。应按能力榜与对齐榜联合选 λ。
