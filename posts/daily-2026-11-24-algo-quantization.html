学习笔记｜量化三岔路：GPTQ 用逆 Hessian 逐列补偿（OPT-175B 3-bit PPL 8.68 vs RTN 7.3e3、单卡约 4 GPU 小时）、AWQ 放大 1% 显著通道（PPL 23.54→11.92）、SmoothQuant 把激活离群迁到权重（W8A8 最高 1.56×，530B 单节点）

2026-11-24 · 收藏夹：算法 / Infra · 学习笔记
经典来源：Elias Frantar、Saleh Ashkboos、Torsten Hoefler、Dan Alistarh（IST Austria & NeuralMagic / ETH Zürich）· GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers（arXiv:2210.17323，ICLR 2023）； Ji Lin、Jiaming Tang、Haotian Tang、Shang Yang、Wei-Ming Chen、Wei-Chen Wang、Guangxuan Xiao、Xingyu Dang、Chuang Gan、Song Han（MIT / SJTU / NVIDIA / Tsinghua / MIT-IBM Watson AI Lab / UMass）· AWQ: Activation-aware Weight Quantization for LLM Compression and Acceleration（arXiv:2306.00978，MLSys 2024 Best Paper，本文引用 v6（2026-04-25））； Guangxuan Xiao、Ji Lin、Mickael Seznec、Hao Wu、Julien Demouth、Song Han（MIT / NVIDIA）· SmoothQuant: Accurate and Efficient Post-Training Quantization for Large Language Models（arXiv:2211.10438，ICML 2023）。 论文数字均来自原文表格 / 正文；「box 小验证」一节为本文用纯 Python 构造的玩具张量实跑，不是论文复现。 交叉： 今日一线：DisSparse、 今日 Harness：RAA、 混合精度训练、 KV cache 分层、 Batch Invariance、 专家并行。

背景与动机：三条量化路线，优化的不是同一个东西

LLM 量化先要分清两条轴：W8A8 把权重和激活都压到 INT8，目标是让 GEMM 直接吃整数算术、省显存也提吞吐；低比特 weight-only（W4A16 / W3A16）只压权重，因为自回归 decode 是访存受限，权重搬一次就决定延迟。两条轴的共同敌人是离群值：激活里极少数通道幅值比其它通道大几十倍，per-tensor INT8 的量化步长被它们撑大，普通通道几乎被量化成 0；权重侧的少数显著通道又承担了不成比例的输出贡献。

方法量化对象核心动作要解决的问题论文硬件收益

这一篇把三篇放在一起讲，是因为它们恰好对应三个不同的“等价变换”：GPTQ 变换权重数值来补偿误差，AWQ 变换通道 scale来保护少数权重，SmoothQuant 把量化难度在激活与权重之间重新分配。理解变换的等价性，比记住论文名字更重要。

GPTQ：把 OBQ 的贪心顺序去掉，换来三个数量级

① 从 OBQ 的目标函数出发

逐层量化要最小化输出扰动 ||W X − Ŵ X||²。OBQ 把未量化集合记为 F，用 H = 2XXᵀ + λI，量化第 q 个权重后的最小增量误差为 e = w_q² / [H⁻¹]_{qq}，因此贪心选误差最小的权重先量化，再沿高斯消元更新逆矩阵： 

H_inv_minus_q = (H_inv − H_inv[:,q] @ H_inv[q,:] / H_inv[q,q]) 去掉第 q 行列

e_q = w_q² / [H_inv]_{qq}          # OBQ 的贪心评分
δ = −(w_q − quant(w_q)) · H_inv[q,:] / [H_inv]_{qq}   # 误差补偿到剩余权重

问题在复杂度：OBQ 对每个权重都更新一次逆矩阵，O(d_row·d_col³)；论文提到它量化 25M 参数的 ResNet-50 要约 1 小时。175B 模型完全不可行。

② 三个工程化步骤

步骤洞察效果
任意顺序大模型里贪心顺序相对固定顺序的优势很小；所有行按同一列序量化，H_F⁻¹ 只依赖 X_F、与权重无关，因此每列更新一次而非每权重一次O(d_row·d_col³) → O(max{d_row·d_col², d_col³})，加速 min(d_row,d_col) 倍
惰性批量更新某列的舍入只受本列更新影响，先把更新限制在 B=128 列窗口内，块处理完再全局更新把“低算术强度、被显存带宽卡住”的操作变成大块更新，实测一个数量级加速
Cholesky 重参数化大模型上反复更新会让 H_F⁻¹ 失去正定性，误差补偿方向错误；只需逆矩阵每行从对角线起的元素，可预先用稳定 Cholesky 算出配合 λ=平均对角线 1% 的 dampening，175B 也能稳定量化

完整算法（论文 Algorithm 1）的块内循环就是“量化 → 记误差 E=(W−Q)/[H⁻¹]_{jj} → 用 E·H⁻¹[j,j:] 更新块内剩余列 → 块结束再更新块外所有列”。校准数据只有 128 段 × 2048 token 的 C4 文本，单张 A100-80GB 一次加载一个 Transformer block（6 层）量化，整个 175B 约 4 GPU 小时。

AWQ：显著通道由激活决定，保护方式用等价缩放

① 1% 的显著通道

AWQ 先做一个反直觉实验：INT3-g128 量化时，把一小部分权重通道保留 FP16。Table 1（WikiText PPL，越低越好）：OPT-1.3B 的 FP16 是 14.62、纯 RTN 是 119.00；按激活幅值选 0.1%/1%/3% 保留 FP16 分别是 25.03/16.91/16.68，而按权重幅值选是 108.71/98.55/98.08，随机选是 119.76/109.38/61.49。OPT-6.7B 同样：FP16 10.86、RTN 23.54、按激活 1% 为 11.39、按权重 1% 为 22.37。也就是说，判断重要性要看激活分布，哪怕做的是 weight-only 量化。

但混合精度硬件不友好。AWQ 的推导（Eq. 1–3）说明为什么放大通道 scale 能保护它：设量化步长 Δ，Err(Q(w)x)=Δ·RoundErr(w/Δ)·x；把 w 放大 s 倍、x 缩小 s 倍后，输出数学等价，而 RoundErr 的期望不变（≈0.25）、单个显著通道通常不改变组内最大值（Δ′≈Δ），于是相对误差约为 (Δ′/Δ)·(1/s)，s>1 就变小。

s 太大时 Δ′ 上升，非显著通道的误差被 Δ′/Δ 放大。因此最终不做手工固定 s，而是按 Eq. 4 搜索每个输入通道的 scale：s* = argmin_s ||Q(W·diag(s))·diag(s)⁻¹X − WX||，用一小段校准集上的激活统计量、无反向传播、无重建，因而不会像 GPTQ 那样对校准分布过拟合。Table 3 给出 OPT 全系列 INT3-g128 的 PPL：1.3B 119.47→16.32，6.7B 23.54→11.39，30B 18.80→9.77，接近“1% FP16”混合精度但硬件友好。

系统侧 TinyChat 用 on-the-fly dequantization、SIMD-aware weight packing 和 kernel fusion 把 4× 内存下降兑现成实测速度：桌面 / 笔记本 / 移动 GPU 上相对 HuggingFace FP16 平均 3.2–3.3×；笔记本 RTX 4070 8GB 上 13B 模型做到 30 tokens/s，Jetson Orin 64GB 上部署 Llama-2-70B。

SmoothQuant：把量化难度从激活搬到权重

① 等价变换与迁移强度 α

对每个输入通道 j 取 scale s_j，令 Y = X·diag(s)⁻¹、W′ = diag(s)·W，则 YW′ = XW 在数学上不变。纯把难度推给权重（s_j=1/max|W_j|）或全推给激活（s_j=max|X_j|）都会崩；用一个超参 α 分配： 

s_j = max(|X_j|)^α / max(|W_j|)^(1−α)

α=0   → 全部难度留在激活
α=1   → 全部难度迁到权重
α=0.5 → 权重 / 激活对应通道的最大幅值相近，同量化器难度相当（OPT / BLOOM）
GLM-130B 约 30% 离群通道 → α=0.75；LLaMA 系激活离群较轻 → α=0.8

校准在预训练数据上离线完成，推理时激活不再额外缩放。量化粒度从 O1（per-token dynamic activation）到 O3（per-tensor static activation）逐步激进，O3 可以直接用现成 INT8 GEMM。

box 小验证：等价缩放真的能降误差吗

两个纯 Python 玩具，用论文里的公式、自己构造的张量（seed 20261124）：

# C1：16 通道 INT3 分组量化，第 15 通道 w=0.38 但 x=40（显著）
step = max(|w_i| for i != salient) * 2 / 7
q_i  = round((w_i * s_i)/step) * step / s_i
MSE  = Σ (q_i − w_i)² * x_i²

BOX C1 输出：s=1.0 → 24.1539；s=1.5 → 3.2095；s=2.0 → 0.0168；s=3.0 → 2.4433

# C2：4 通道 per-tensor INT8，ch0 激活离群 30、ch1 权重离群 20（95% 普通值 + 5% 离群）
s_j  = Xmax_j^α / Wmax_j^(1−α)
dx   = max_j(Xmax_j / s_j),  dw = max_j(Wmax_j * s_j)
量化 x/s_j 用 dx/127，量化 w*s_j 用 dw/127，再乘回去

BOX C2 输出：α=0.0 → 0.002344；α=0.3 → 0.001629；α=0.5 → 0.001567；
            α=0.7 → 0.001645；α=1.0 → 0.002352

读法：AWQ 玩具里 s=2 把显著通道的输出误差降了三个数量级，s 再大反而回升——对应论文 Table 2 的 11.92（s=2）vs 12.36（s=4）。SmoothQuant 玩具里两端都差、α=0.5 最好，对应论文“OPT / BLOOM 取 0.5 平衡”的经验。玩具的绝对数值没有意义，只有方向与机制对标论文；真正的 PPL / 吞吐必须看论文表格。

三篇放在一起怎么选

  • 只要省显存、端点侧 decode：AWQ / GPTQ 这类 weight-only。AWQ 不做重建、跨模态泛化更稳；GPTQ 在有校准数据时精度更强，尤其是 3-bit。
  • 要现成 INT8 GEMM 的吞吐：SmoothQuant。它把难度摊平后可以直接用 per-tensor static 量化，避免 LLM.int8() 的混合精度分支开销。
  • 要继续压到 2-bit：GPTQ 论文也给了 2-bit / 三值结果，但依赖更细的分组；精度边界要按模型单独验。
  • 和本站其它主题的关系：量化改变每个 token 的字节数，KV cache 分层 改变 token 放在哪层，二者正交；量化与稀疏选择叠加时要重新校准 top-p 阈值；Batch Invariance 则提醒我们，核函数按 batch 换分块策略会引入新的数值漂移。

思考题

1. GPTQ 的“任意顺序”洞察为什么在大模型上成立，在小模型上却不一定？

OBQ 的贪心顺序优先舍入误差小的权重，减少“高误差权重在后期无可用补偿”的概率；但大模型层宽、参数高度冗余，两种顺序的最终平方误差差距很小，作者解释为早期多量化的低误差权重与末期缺少补偿的高误差权重相互抵消。小模型自由度少，这个平衡不成立，所以论文 Table 2/附录里 GPTQ 在 3-bit 小模型上略逊于最精确的 OBQ/AdaRound 类方法。

2. AWQ 为什么“按权重范数挑显著通道”几乎和随机挑一样差？

量化误差对最终输出的影响是 Err(Q(w)x) = Δ·RoundErr(w/Δ)·x，包含激活 x 这个乘子。幅值大的权重若对应的输入通道激活很小，它对输出扰动贡献有限；反过来，中等幅值权重配一个巨大激活才是真正的显著项。Table 1 里 OPT-1.3B 按权重选 1% 是 98.55 PPL，随机是 109.38，而按激活选 1% 是 16.91，差距非常直观。

3. SmoothQuant 的 α=0.5 是普适最优吗？

不是。它是“权重与激活用同一种量化器（per-tensor static）”时让两边最大幅值相近的经验平衡点。论文对 GLM-130B 用 0.75（约 30% 激活离群，需要多迁一些到权重），LLaMA 用 0.8（激活离群较轻，但实验用 per-token 激活量化）。α 的选择应在目标模型上按校准集扫一遍，看 PPL / 下游任务，而不是抄默认值。

4. 三篇都说“训练-free / 无反向传播”，但 GPTQ 需要校准重建，AWQ 只需要激活统计。这会带来什么实际差异？

GPTQ 在校准过程中按层用真实输入依次量化并回传已量化块的激活，逐列误差补偿会拟合这批校准样本；AWQ 只统计通道激活幅值并搜索 scale，不做权重重建，论文因此认为它更少过拟合、对域外与多模态更稳（并给出代码 / 数学 / 多模态基准佐证）。代价是 GPTQ 在合适的校准集上精度通常更强，尤其低比特。实践上：同域、能拿到代表性校准数据时用 GPTQ；跨域、多模态、希望流程简单可复用时用 AWQ。

5. （开放题）把 AWQ 的“显著通道”思想和 SmoothQuant 的“难度迁移”叠加，会得到什么？

两者都在做通道级等价缩放，但目标不同：AWQ 保护 weight-only 下的显著权重，SmoothQuant 平衡 W8A8 下的量化难度。叠加时可先用 SmoothQuant 的 α 把激活离群摊平，再在得到的权重分布上按激活统计量找 AWQ 的显著通道放大 s；但两个 scale 会共同改变每组的 Δ，必须联合搜索，否则 AWQ 的 Δ′≈Δ 假设会被破坏。另一个角度是低比特权重 + INT8 激活（W4A8），此时显著通道同时影响两边，需要一个新的目标函数把两类误差一起最小化——论文都没有给出这个组合的结论，不能假定“叠加必然更好”。
