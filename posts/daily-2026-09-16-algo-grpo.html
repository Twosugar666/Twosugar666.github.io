学习笔记｜GRPO：用组内相对奖励省掉 Critic（DeepSeekMath → R1）

2026-09-16 · 收藏夹：算法 / RL · 学习笔记
经典：Shao 等 · DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models · arXiv:2402.03300； R1 用法：Guo 等 · arXiv:2501.12948。 交叉： PPO、 DAPO、 GSPO、 REINFORCE、 Importance Sampling、 TRPO、 GRPO 实践笔记。

背景与动机

PPO 在 LLM 对齐里长期是默认起点：clipped surrogate + 价值网络（critic）估 advantage，再加对 reference 的 KL。 Critic 要额外一套与策略同量级的参数，还要对付价值估计偏差、长 CoT 上的 bootstrap 噪声——算力与调参成本都不低。

DeepSeekMath 提出的 GRPO（Group Relative Policy Optimization） 走另一条路：对同一 prompt 采样一组 completions，用组内相对奖励直接当 advantage，不再训 value model。 后续 DeepSeek-R1 把同一套 critic-free、组内相对的思路推到大规模推理 RL，使 GRPO 成为开源后训练栈里最常见的默认算法之一。 站内已有 实践向笔记；本篇补「正式课」：公式骨架、与 PPO/TRPO/REINFORCE 的位置、以及 DAPO/GSPO 如何在其上打补丁。

一句话：同一 prompt 采一组输出，用组内均值/方差标准化奖励得 advantage，塞进 PPO 式 clipped surrogate，并对 ref 加 KL——无 critic，用组内相对性代替价值基线。

机制拆解

① 从 PPO 到「组内相对」

PPOGRPO
Advantage常靠 GAE + V_φ（critic）同 prompt 组内 reward 标准化
额外网络要 value model不要
Surrogateclipped importance ratio同族 clipped surrogate
KL对 π_ref（常见）对 π_ref（常见）
采样形态可单条 / 多条每 prompt 一组 completions 是一等公民

谱系上：REINFORCE 给似然比骨架 → TRPO 用 KL 信赖域 → PPO 用 clip 近似 → GRPO 保留 clip，但把 baseline/advantage 换成「组内相对奖励」。 与 Actor-Critic 对照：AC 显式学 V；GRPO 用同组样本的经验均值当基线，是一种无参数、prompt-条件的 baseline。

② Advantage：组内均值 / 方差标准化

# 对固定 prompt x，采样一组 completions {y_1 … y_G}
# 每条有标量奖励 r_i（规则 / RM / 可验证成功 …）

mean_r = (1/G) Σ_i r_i
std_r  = sqrt( (1/G) Σ_i (r_i − mean_r)^2 ) + ε

A_i = (r_i − mean_r) / std_r     # 组内相对优势

# 典型：把 A_i 广播到 y_i 的每个 token（或按实现做 token 掩码）
# 再进 clipped surrogate（示意）
ratio_t = π_θ(token_t | …) / π_old(token_t | …)
L_clip  = − min( ratio_t · A_i ,
                 clip(ratio_t, 1−ε, 1+ε) · A_i )

# 常再加：
L = L_clip + β · KL( π_θ(·|x) ∥ π_ref(·|x) )

直觉：不需要知道「绝对回报该是多少」；只需知道在同一题上，这条比同组其它条更好还是更差。 标准化后 A 近似零均值、单位方差，梯度尺度跨 prompt 更可比——这也是「Group Relative」一名的来源。

③ 和 DAPO / GSPO 的接口

变体相对 GRPO 改了什么站内笔记
DAPO Clip-Higher、Dynamic Sampling、Token-level Loss、Overlong 惩罚等训练细节 DAPO
GSPO 重要性采样提到序列级，稳住 MoE 等设定 GSPO
IS 工具箱 ratio / clip / truncate 的一般理论 Importance Sampling

读现代栈时建议分层：GRPO 定「无 critic + 组内相对」；DAPO 修长 CoT 训练病理；GSPO 改 IS 粒度。不要把三者当成互斥品牌，而是同一主干上的不同旋钮层。

④ 实践坑：组大小、全零/全一、length bias

现象机制常见处理
组内奖励全相同（全对 / 全错） std→0，A≈0，该组无梯度 Dynamic Sampling（DAPO）、过滤零方差组、增大 G / 调温度
G 过小 均值/方差估计噪，相对排序不稳 数学/代码常用较大组；与算力折中
Length bias 奖励与长度相关时，标准化仍可能偏爱冗长或极短 长度惩罚、overlong mask、按 token 归一奖励
广播到每 token 终局标量信用糊在长链上 接受为基线；或接步级方法（AHEAD/GACA 等）

实践建议

  • 可验证奖励优先：数学/代码/agent 终局成功最适合 GRPO；主观偏好更常走 RM+PPO 或 DPO/KTO。
  • 把「零方差组比率」做成一等监控：长期接近 1 说明难度或采样温度失配，算法再对也推不动。
  • π_old 与采样策略对齐：off-policy 过大时 clip 救不动；异步 rollout 要管好版本与 IS。
  • KL 系数与 clip 范围分开扫：KL 管「离 ref 多远」，clip 管「单步更新多猛」；混成一个旋钮会归因混乱。
  • 先读通本页再读实践笔记：公式与坑在这里；多智能体/工程配方见 grpo-notes。

思考题

1. GRPO 的组内均值 baselining，与 Actor-Critic 的 V(s) 有何同构与差异？

同构：都在减一个「期望回报」估计以降方差。差异：V_φ 是学出来的状态函数，可泛化到未见 prompt；组内均值只依赖当前组样本，无参数、但方差受 G 限制，且不能外推到组外状态。

2. 为什么全对或全错的组会让 GRPO「没学到东西」？

相对优势需要组内分化。奖励常数 ⇒ 标准化后 A≈0 ⇒ clipped surrogate 梯度消失。这是相对方法的结构性代价，不是实现 bug。

3. GRPO 还需要 importance sampling ratio 吗？

需要——只要用 π_old 采样、π_θ 更新，就有 off-policy 修正；clip 正是对 ratio 的保守处理。组内相对只替换了 advantage 来源，不取消 IS。

4. 把 GRPO 的 A_i 广播到每个 token，与「过程奖励 / 步级优势」差在哪？

广播假定终局相对好坏均匀归因到所有 token，长链上信用糊。过程奖励或步级方法试图区分关键步，但要额外标注或估计器；GRPO 用简单换可扩展性。

5. 何时应回到带 critic 的 PPO，而不是死磕 GRPO？

当难以对同一 prompt 采够大组、奖励极度稀疏且需跨状态泛化的 baseline、或已有可靠 value 模型可复用时，PPO/AC 可能更稳。组采样便宜、可验证奖励清晰时，GRPO 通常更香。
