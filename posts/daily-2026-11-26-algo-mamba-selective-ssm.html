学习笔记｜Mamba 与选择性状态空间：让 Δ / B / C 随输入变化，扫描替代卷积——状态维 N 从 1 到 16 只多 1% 参数却降 1.02 ppl，序列 >2K 后快过 FlashAttention-2，推理 4–5× 吞吐

2026-11-26 · 收藏夹：算法 / Infra · 学习笔记
经典来源：Albert Gu（Machine Learning Department, Carnegie Mellon University）、Tri Dao（Department of Computer Science, Princeton University）· Mamba: Linear-Time Sequence Modeling with Selective State Spaces（arXiv:2312.00752，v1 2023-12-01 / v2 2024-05-31；代码）；前作 S4：Gu / Goel / Ré（arXiv:2111.00396，ICLR 2022）。 论文数字按正文 Tables 1–10、§4.5 抄录；「box 小实验」为本文在 box 上写的纯 Python 选择性扫描，不冒充论文结果。 交叉： Gated DeltaNet、 FlashAttention、 MQA / GQA / MLA、 KV cache 的一生、 RoPE、 激活重计算。

背景与动机

Attention 强在「上下文里任意两个位置直接路由信息」，代价是训练 O(L²)、推理要显式保存整段 KV cache（KV cache 的一生）。结构化状态空间模型（SSM / S4）走另一条路：把历史压进固定大小的状态 h，训练可用卷积并行、推理每步常数时间；但它是 LTI（linear time-invariant，参数不随位置变），无法按内容决定「记住谁、忘掉谁」。

论文用两个合成任务把这一点钉死：

  • Copying：输入/输出间距固定。LTI 的全局卷积只要造一个长度刚好的核就能解，不需要看数据内容。
  • Selective Copying：要记的 token 位置随机，中间夹噪声。固定卷积核没有内容感知，间距又随机，LTI 失败；需要模型按当前 token 决定是否更新状态。
  • Induction Heads：见过「Harry Potter」后再遇到「Harry」要输出「Potter」。这是 ICL 能力的关键机制，同样要求「等到对的上下文再取值」。

Mamba 的核心主张：序列建模的效率—效果权衡，本质是「把上下文压缩进多小的状态」。Attention 干脆不压缩（所以准而慢），RNN/SSM 状态有限（所以快但弱）；出路不是把状态做大，而是让压缩过程有选择性（selection）。

机制拆解

① 从连续 SSM 到 S4：离散化 + 递推 / 卷积对偶

经典连续系统用 (Δ, A, B, C) 四个参数把 x(t)∈ℝ 经隐状态 h(t)∈ℝN 映射为 y(t)：

h'(t) = A h(t) + B x(t)        y(t) = C h(t)                      (1)

ZOH 离散化（式 4）：
  Ā = exp(Δ A)
  B̄ = (Δ A)^{-1} (exp(Δ A) − I) · Δ B

离散后有两种等价算法：
  递推  h_t = Ā h_{t−1} + B̄ x_t ,  y_t = C h_t                    (2)   O(BL D N)
  卷积  K = (C B̄, C Ā B̄, …, C Ā^k B̄, …) ,  y = x * K             (3)   O(BL D log L)

对角化 A 时 (A,B,C) 各只需 N 个数；D 个通道独立作用，
完整隐藏状态是 (B, L, D, N) —— 这就是「状态扩展」的内存瓶颈。

以前所有高效 SSM 都保持 (Δ,A,B,C) 随时间不变，才能用全局卷积绕开 (B,L,D,N) 的显式物化；代价正是没法按内容选择。S4 的来龙去脉见 S4 原文。

② S6：让 Δ、B、C 依赖输入

论文 Algorithm 1 → Algorithm 2 的差异只有几行，但把「时不变」变成了「时变」，卷积路径随之失效：

参数S4（Algorithm 1）S6 / selective（Algorithm 2）作用
A(D, N) 可学习参数(D, N) 可学习参数结构化状态转移（对角）
B(D, N) 参数(B, L, N) ← sB(x)输入如何进入状态
C(D, N) 参数(B, L, N) ← sC(x)状态如何读出
Δ(D) ← τΔ(Parameter)(B, L, D) ← τΔ(Parameter + sΔ(x))步长/门控，控制记与忘
离散化结果(D, N)(B, L, D, N)不能再卷积，只能 scan
 
具体选择：s_B(x) = Linear_N(x)，s_C(x) = Linear_N(x)
          s_Δ(x) = Broadcast_D(Linear_1(x))，τ_Δ = softplus
          先投影到 1 维再广播：要忽略一个 token 时，所有 D 通道一起忽略

Theorem 1（N=1, A=−1, B=1 时）：
  g_t   = σ(Linear(x_t))                       # 就是 RNN 门
  h_t   = (1 − g_t) h_{t−1} + g_t x_t           # 选择性 = 门控的推广
  Δ 大 → 重置状态、关注当前输入；Δ 小 → 保留状态、忽略当前输入
  B/C 选择性 → 更细粒度地控制「输入进状态」「状态出输出」

论文还指出三种机制性效果：变间隔过滤（跳过的「嗯、啊」可直接 ignore）、过滤无关上下文（必要时重置状态，理论上上下文越长不会越差）、边界重置（文档拼接、RL episode 边界，Δ→∞ 相当于清状态）。这与 Gated DeltaNet 讨论的「标量衰减整体淡出 vs 按内容定点遗忘」是同一条线索：DeltaNet 用 delta rule 做定点写入，Mamba 用输入依赖的 Δ 做门控。

③ 硬件感知扫描：kernel fusion + parallel scan + recomputation

时变之后回到递推式，会遇到两个老问题：串行、以及 (B,L,D,N) 状态太大。论文的工程解法是经典三件套：

  • Kernel fusion：不把 (B,L,D,N) 的 scan 输入写进 HBM，而是把 (Δ,A,B,C) 从 HBM 直接读进 SRAM，在 SRAM 里完成离散化与递推，只把 (B,L,D) 的输出写回 HBM。
  • Parallel scan：关联扫描（Blelloch 1990 / Hillis-Steele）把 O(L) 深度压到 O(log L)，保持 work-efficient；递推虽然非线性，但结合律成立。
  • Recomputation：反向不存中间状态，随输入从 HBM 再读进 SRAM 时重算（激活重计算同款思路）。最终 fused selective scan 层的显存与 FlashAttention 优化实现相当。

FLOPs 账也要算清：朴素递推 O(BL D N)、卷积 O(BL D log L)，前者常数因子更小，N 不太大、L 很长时反而更省 FLOPs——真正的问题是内存 IO，不是算术。

④ Mamba block：把 H3 与 MLP 合成一个同质块

输入 x ─┬─ 线性投影（扩展 E=2）─┬─ Conv ─ SSM(S6) ─┐
        └─ 门控分支（SiLU / Swish）────────────────┴─⊗─ 线性投影 → y

H3 块（SSM 夹在两个门之间）+ Gated MLP 块 → 合成一个 Mamba 块，同质堆叠
参数账：E=2 时投影占 3 E D² = 6 D²；两层 Mamba block ≈ 12 D²，
        正好对齐 Transformer 的 MHA + MLP 两层
激活用 SiLU/Swish，让 gated MLP 变成常见的 SwiGLU；可选 LayerNorm；无 attention、无独立 MLP 块

⑤ 速度：扫描在 2K 之后反超 FlashAttention-2

§4.5 / Figure 8（A100 80GB，状态扩展 N=16）：fused SSM scan 在序列长度超过 2K 后快过 FlashAttention-2，比 PyTorch 标准 scan 快 20–40×；端到端推理吞吐比同尺寸 Transformer 高 4–5×（摘要写 5×），因为不用 KV cache 可以开更大 batch；未训练的 Mamba-6.9B 推理吞吐高于小 5 倍的 Transformer-1.3B。注意这是 2023 年的硬件/实现对照，不能外推到今天的全部推理栈。

读法：(1) 固定门 g=0.2 时，三个信号按 0.8 的距离指数衰减，末态只剩 0.0029，选择性门几乎完全忽略噪声、末态精确为 1；(2) 关联扫描与串行递推逐位一致（误差 1.1e−16），证实「递推非线性但仍可并行」；(3) 取论文 §4.5 的 N=16 与 B=1、L=4096、D=4096，展开状态是输入的 16 倍、1024 MB——这正是必须在 SRAM 里融合、不能写入 HBM 的原因。这里只验证机制与量级，不是论文 benchmark。

实践建议与局限

  • 先问数据模态：选择机制解决了文本/DNA 这类离散信息密集数据的痛点，但论文自己指出「没有免费午餐」——LTI 擅长的连续信号（音频）上需要复数参数化才能拿回效果。
  • Δ 优先：若做简化实现，先把 Δ 变成输入依赖并做 1 维投影广播，再考虑 B/C；N 的加大只有在 B/C 也选择性时才值钱。
  • IO 比 FLOPs 更关键：递推本身比卷积省算术，真正优化点是「不物化 (B,L,D,N)」；和 FlashAttention 是把 IO 当一等公民的思路同源，只是 Mamba 融合的是 scan 而不是 softmax。
  • 生态尚不完整：论文的 scaling 只到 ≈1B（远低于当时 7B 开源模型），微调、适配、prompting、ICL、指令微调、RLHF、量化这些 Transformer 生态属性尚未验证；Gated DeltaNet 一系的线性注意力同样面临这个问题。
  • 与位置编码的关系：Mamba 靠递推本身编码顺序，不需要 RoPE；但「文档拼接/边界重置」相当于显式的位置边界管理，设计 packing 策略时要参考 §3.5.2。

思考题

1. 为什么 LTI SSM 可以用卷积并行训练，而选择性 SSM 不行？

式 (3) 的卷积核 K=(CB̄, CĀB̄, …, CĀkB̄, …) 要求 (Δ,A,B,C) 在所有位置相同，才能把递推展开成与位置无关的全局卷积核。S6 让 B、C、Δ 依赖 xt，(B,L,D,N) 的转移每步都不同，K 不再存在。替代方案是关联扫描：递推 ht=atht−1+bt 的仿射变换可结合（(a₁,b₁) 后接 (a₂,b₂) 得 (a₂a₁, a₂b₁+b₂)），Hillis-Steele / Blelloch 可在 O(log L) 深度内算出全部前缀，work 仍是 O(BL D N)。box 里两者误差 1.1e−16。

2. Theorem 1 为什么重要？它把 Δ 与 RNN 门控联系起来的意义是什么？

取 N=1、A=−1、B=1、sΔ=Linear(x)、τΔ=softplus 时，选择性 SSM 的递推化为 gt=σ(Linear(xt))、ht=(1−gt)ht−1+gtxt，正是经典 RNN 门控。这说明 Δ 不是新造的技巧，而是连续系统离散化视角下的广义门：Δ 大 → 以当前输入为主、重置旧状态；Δ 小 → 保留旧状态、忽略当前输入。相应地，作者把 Δ 投影到 1 维再广播到 D 个通道——要跳过一个无关 token 时所有通道一起跳过。这也解释了 Table 7：只让 Δ 选择性就把 ppl 从 10.93 降到 9.81。

3. 为什么「加大状态维 N」在 B/C 不选择性时几乎无用，选择性时却值 1.02 ppl？

Table 10：B/C 固定时 N=1→16 只从 9.88 到 9.81；B/C 也选择性时从 9.73 到 8.71，参数只多 1.2%（367.1M→371.5M）。直觉是：状态维数决定「能存多少」，选择性决定「存进去的是不是该存的」。LTI 下更大的状态只是把同样的无差别历史摊到更多维，噪声一起被卷进去；有了 B/C 的内容门控，额外维度才能用来区分不同 token 的信息。引言把这点上升为「效率—效果权衡由压缩质量决定」，而不是维数竞赛。

4. Mamba 的「恒定时间推理」是否等于没有显存开销？与 KV cache 路线比较一下。

每一步只需按递推更新固定大小状态、不需要保存历史 token，因此单步 FLOPs 与缓存占用不随已生成长度线性增长，batch 可以开大——这是 4–5× 吞吐的来源。但状态本身是 D×N 的张量（每层每通道 N 维隐状态），N≈10–100，不是零；训练时若物化 (B,L,D,N) 更会爆显存（box 算出 L=4096、D=4096、N=16 时 1 GB fp32），必须靠 SRAM 融合与重计算。相比之下 Transformer 的 KV cache 随长度线性增长，但有 GQA / MLA、PagedAttention 等成熟压缩手段。两条路线的真实吞吐取决于实现与硬件，不能只看复杂度。

5. 这篇 2023 年的经典论文，与最近线性注意力/门控DeltaNet 类工作怎么衔接？

Mamba 的贡献是「输入依赖的选择 + 硬件友好 scan + 去 attention/MLP 的同质块」；Gated DeltaNet 则从线性注意力的联想记忆角度看问题：纯外积记忆有 collision，Mamba2 的标量衰减只能整体淡出，DeltaNet 的门控 delta rule 能定点覆盖旧值。可以把 Mamba 的 Δ 门控理解为「以标量为单位的写入/遗忘控制」，delta rule 是「以 key 为单位的写入控制」；两者都在回答同一个问题：固定大小状态里，按内容决定写什么、忘什么。Mamba 论文 §5 也坦诚未覆盖 RLHF、量化等生态属性，这正是后续工作补的坑。
