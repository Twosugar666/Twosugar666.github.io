学习笔记｜EvoHarness-RL：把 Belief / Progress / Experience 当成可学的 harness 策略（退火 + 演化）

2026-09-11 · 收藏夹：Harness / Agent / RL · 学习笔记
论文：Ning, Fu, Wei, Zeng et al. · EvoHarness-RL: Learning Self-Evolving Runtime Harness for Long-Horizon LLM Agents （LLA@COLM 2026）· arXiv:2608.05446。 交叉： Harness 运行时、 Context Compaction、 Ralph Loop、 Harness-RL、 GRPO。

背景与动机

长程 LLM agent 越来越依赖外部执行支持：记状态、追子目标、调工具、验结果、跨 episode 复用经验。 但「怎么从嘈杂轨迹形成外部状态」和「运行时何时读写这些状态」常常仍靠 prompt / 启发式 / 领域约定——workspace 与其用法策略都是人肉工程。

EvoHarness-RL 把问题立成 harness policy learning：离线学会 harness 策略，在线部署时构造与更新外部 harness 状态。 核心抽象是面向策略的三态 BPE = Belief / Progress / Experience，再用四个紧凑 meta-action 与之交互。

一句话：BPE 外置状态 + {track, commit, recall, note}；SFT 教会动作语义，cost-aware GRPO 教会「什么时候值得花一步去碰 harness」——训练中出现 harness annealing 与 experience 演化。

机制拆解

① BPE：三种功能角色

状态时间尺度存什么
Belief B_tepisode 内从交互推断的任务相关事实：物体状态、位置、关系
Progress P_tepisode 内子目标–状态记录 (g_i, σ_i)：已做 / 待做 / 卡住
Experience E_t跨 episode可复用技能、失败模式、搜索先验、策略摘要

BPE 是策略面接口，不是固定内部 schema。领域差异由 environment adapter 吸收：adapter 维护内部存储、渲染 (B_t, P_t, E_t)，并落地四个 harness 动作。

② Meta-actions：与环境动作共享步数预算

A_bpe = { track, commit, recall, note }
A     = A_env ∪ A_bpe

# 每步：
a_t ~ π_θ(· | o_t, H_t, c_t)   # H_t 为渲染后的 harness 视图

# 语义（ALFWorld 落地示意）
track  [object|world]  → 读 Belief（默认可不全量暴露，按需查询）
commit [subgoal]       → 写 Progress（外置当前执行步骤）
recall [query]         → 读 Experience（并更新使用计数）
note   [insight]       → 写临时笔记缓冲，epoch 边界再 consolidate 进技能库

关键：harness 动作与环境动作抢同一 interaction budget。于是「要不要碰 harness」本身就是策略优化对象，而不是免费旁路。

③ 两段训练：SFT → cost-aware GRPO

# 1) Supervised harness fine-tuning
# 教师轨迹：同一 BPE 接口上的成功示范
# 格式：<think>...</think><action>...</action>
# action ∈ ALFWorld 命令 ∪ BPE harness 动作
# 基座：Qwen3-8B；教师 rollout 也初始化后续技能库

# 2) Cost-aware GRPO（轨迹级奖励，示意）
R(τ) = R_succ(τ)                 # 主信号：任务成功（稀疏）
     + λ_eff  R_eff(τ)           # 效率 bonus
     + λ_div(u) R_div(τ)         # 动作多样性
     − λ_spam R_spam(τ)          # 刷 harness / spam 惩罚
     − λ_inv  R_inv(τ)           # 格式非法惩罚

奖励设计的意图很明确：既要成功，也要学会自适应、省步数的 harness 协调，而不是把 BPE 当免费草稿纸狂写。

④ ALFWorld 数字与消融（论文报告）

设定结果
EvoHarness-RL · seen96.9% success
EvoHarness-RL · unseen86.6%
Qwen3-8B ReAct · unseen50.0%
仅 prompt-time BPE · unseen77.6%（外置状态已有收益）

去掉 Experience（消融）整体平均成功落到约 48.6%（最低）

消融还显示：去 Belief 伤 Clean/Cool 这类要定位与验状态的任务；去 Progress 伤 Pick2 等长依赖子目标；三者是协同接口，不是三个独立 memory 插件。

⑤ 两个共演化动态

动态发生在哪一侧现象
Harness annealing 策略侧 SFT 初期频繁调 harness；GRPO 中用量快速下降并稳定在约 1 次/episode——常规脚手架行为内化进策略，外部访问只在期望收益 > 步成本时保留
Harness evolution Experience 库侧 早期技能库扩张（general / task-specific / mistakes / search priors），后期合并冗余、驱逐冷门、保留高召回条目——变成紧凑的任务自适应状态基底

实践建议

  • 先统一策略面接口，再谈领域存储：内部可以是 world-state tracker / 子目标表 / 技能库，但暴露给 π 的应是稳定的 BPE 角色与少量 meta-action。
  • 把 harness 调用计入步数预算：不计成本就会出现「每步都 track/recall」的 spam；奖励里要有 spam / format / efficiency。
  • SFT 只解决「会用」，RL 解决「何时用」：论文 unseen 上 SFT 反不及纯 prompt BPE，说明模仿教师调用频率会过拟合 seen 模式。
  • Experience 要有 consolidate + forget：append-only 日志不是 harness evolution；epoch 边界做 add/update/remove 才像可维护的技能库。
  • 与 compaction / Ralph Loop 对照：compaction 压缩上下文窗；Ralph 靠 hook 续跑；EvoHarness 学的是外置认知工具的协调策略——三者可叠，但优化目标不同。

思考题

1. 为什么 harness 动作必须与环境动作共享同一动作空间？

若 harness 是免费旁路，策略没有动机节约访问；共享预算后，「读/写外部状态」成为有机会成本的决策，才能用 RL 学 cost-aware 协调。

2. Belief 为何默认不全量塞进上下文，而要用 track 查询？

全量暴露会膨胀上下文并鼓励被动依赖；选择性查询迫使策略判断「此刻缺哪条事实」，也更接近真实系统里的按需检索。

3. annealing 是否意味着最终可以删掉 harness？

不是。用量降到约 1 次/episode 说明常规模式已内化，但策略仍保留选择性访问；删掉 BPE 会失去处理新状态与跨任务先验的通道（消融已显示组件缺一不可）。

4. Experience 的「两段时间尺度」分别解决什么？

episode 内：recall/note 服务当前任务；跨 episode：consolidate 把笔记与轨迹摘要并入技能库。前者保在线可用，后者做长期演化与遗忘。

5. 和站内 Harness-RL / HarnessEvolve 怎么分工理解？

Harness-RL 侧重多 agent 接口与 Action–Args；HarnessEvolve 侧重参考轨迹修自演化信用；EvoHarness-RL 侧重BPE 状态抽象 + 可学的访问策略与退火。都是「harness 可训练化」谱系上的不同切面。
