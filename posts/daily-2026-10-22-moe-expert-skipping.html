一线追踪｜Don't Skip the Baseline：MoE 动态跳专家在同等实测算力下打不过「静态把 k 调小」——Qwen3 / Gemma4 / Qwen3-VL 上 NAEE、DiEP、MoDES、Ada-K 最多领先 2.6 个点，校准出来的 Keff 到测试时能偏 6 倍

2026-10-22 · 收藏夹：Infra · 一线追踪
来源：Jakob Steimle、Thomas Elsken、Daniel Ehrhardt、Lukas Rinder、Daniel Cremers、Xi Wang（TUM / Tensordyne / ETH Zurich / Ulm）· Don't Skip the Baseline: A Controlled Comparison of Dynamic Expert Skipping in MoEs（arXiv:2610.28369，2026-10-20 提交）。 文中数字均为论文自报（单卡 A100 80GB、lm-eval / LMMS-Eval / vLLM + GuideLLM），作者称会开源全部重实现代码，本文写作时尚未看到仓库。 交叉： MoE 路由与负载均衡、 Spectral-MoE、 KV Cache、 今日 Harness：Cache Engineering。

背景与动机

主流 MoE（Qwen3、DeepSeek、Gemma4）都是每 token 固定激活 k=8 个专家，总专家 128~512。这个 k 是训练时定的，推理时能不能再省？过去两年出了一串「dynamic expert skipping」方法：按路由分数的累计质量截断（NAEE）、加专家冗余度（DiEP）、加层重要性和模态阈值（MoDES）、用 PPO 训一个预测 k 的 allocator（Ada-K）。它们各自报告「砍掉 50%~80% 专家、质量几乎不掉」，但校准数据、操作点、评测集各不相同，彼此没法比。

这篇论文做的事情很朴素：把四种方法放到同一把尺子上——测试时实测的平均激活专家数 Keff——然后和一个谁都想得到、但很少被认真当成对照组的 baseline 比：所有层、所有 token 统一把 top-k 的 k 调小。结论标题已经说了：这个 baseline 很难被稳定打败。对做推理系统的人来说，这是一篇「先别上复杂方案」的证据型文章，也顺带提醒了 MoE 推理加速的天花板在哪。

机制拆解

① 四种方法放进同一张分类表

方法额外信号决策规则可调参数单个操作点校准耗时（A100，自报）
softmax top-k（baseline）只用 gate 权重保留 top-kk0

注意两个实验设计上的「去混杂」：一是 NAEE、DiEP 原文都把跳专家和静态剪枝（永久删掉部分专家）绑在一起报告，这里只评跳专家本身；二是 NAEE / DiEP 原代码只支持 Mixtral 这种 k=2 的粗粒度 MoE，作者扩展到 k=8；Ada-K 没开源，作者按论文用 PPO 重训（γ=0.99、clip 0.2、2 个 PPO epoch、λ ∈ {0.0003…0.08} 每个值单独训一个 allocator）。每个方法原本只有一两个操作点，作者扫参数画出完整的「质量—算力」前沿，并在附录里复现了原文报告的操作点（MoDES 复现误差 ≤ 0.6 分）。

② 尺子：实测 Keff，而不是校准时的 Keff

# K_eff = 所有 token、所有层上实际激活专家数的平均
K_eff = (1 / (T·L)) · Σ_t Σ_l k_{t,l}

# 静态 top-k：K_eff ≡ k（构造上精确）
# 动态方法：阈值只在校准集上「达标」，换数据分布 K_eff 会漂
#   calibrated K_eff  —— 方法论文通常报这个
#   measured  K_eff   —— 本文用这个（GSM8K / HumanEval 连 decode 步也算进去）

为什么 Keff 是合理代理：大 batch 时专家 FFN 是 compute-bound，matmul FLOPs 与 Keff 线性；但它不计路由决策开销、负载不均、通信，所以真实成本只会比 Keff 暗示的更高——这一项偏差天然对动态方法有利，作者明确说他们的比较是「偏向动态方法的」。

③ 文本结果：最多 2.6 pp，而且出现在模型已经坏掉一半的区间

  • Qwen3-30B-A3B、Gemma4-26B-A4B（都是 k=8），评测 HellaSwag、ARC-C、5-shot GSM8K、HumanEval；校准集是 C4 en/zh + open-web-math + python 代码的混合（模拟真实部署时校准与评测不一致）。
  • NAEE 基本贴着 baseline 前沿走，偶有微小领先；Allocator 在 Qwen3 的 Keff≈1 附近有改进。相对插值 baseline 的最大优势约 2.6 pp，但那时模型已经丢了 50%~65% 的原始能力。
  • DiEP 和 MoDES 多数点低于 baseline。MoDES 唯一独占的是 Keff<1 区间（某些 token 整个 MoE 块被跳过），baseline 构造上到不了。
  • Keff ≤ 2.5 时，Gemma4-26B-A4B 上最好的策略平均还不如 dense 的 Gemma4-E4B（有效参数少 85%）——作者的说法是：砍到 Keff≈3 以下，不如直接换小模型。
  • 多选题随 k 下降平滑跌向随机猜测；GSM8K 在模型相关的阈值（Qwen3 约 Keff≈2）以下断崖式崩，HumanEval 类似。平均分在低 Keff 区间是被生成任务主导的，安全操作点应由生成类 benchmark 决定。
  • 用 benchmark 自己的 train 集做「最佳情况」校准，DiEP 和 Allocator 明显变好，但仍然没有稳定超过 baseline。

④ 多模态：模态感知是真信号，但静态版就够了

Qwen3-VL-30B-A3B，六个 benchmark（ChartQA、TextVQA、MME、DocVQA、InfoVQA、OCRBench），MoDES 和 NAEE 都按 MoDES 原文的 GQA 协议校准（给 MoDES 最有利的条件）。

设置平均相对质量下降（自报）备注
ktext=8，kvision=2< 1.8%静态、零校准
ktext=8，kvision=1≈ 4.1%实测 Keff 1.08，激活专家减少约 85%
ktext=8，kvision=019.1%视觉 token 完全不过专家，仍保留 80%+ 质量

MoDES 大幅领先 NAEE 和模态无关 baseline，但追不上 per-modality 静态 baseline；把 MoDES 的专家分配按模态拆开看，它几乎就是在「文本保持 k=8、视觉狠砍」——和静态 per-modality 的形状一样。唯一例外是 MME-Cognition 子任务，MoDES 稳定领先。

两个漂移来源：工作负载里图像 / 文本 token 的比例；评测数据的路由分数分布和校准集不同。最极端的是 VL 模型跑纯文本 prompt（现实中很常见——多模态模型经常被当通用模型用）：校准时说 Keff=1.2，实际 7.96，跳专家等于失效，省算力的承诺全部蒸发。per-modality 静态方案也会随负载漂，但有上界：纯文本时就是 ktext=6，用比 MoDES 实际少 25% 的专家换 2.7 pp（68.8% vs 71.5%）。

⑥ 天花板：Keff 从 8 砍到 1，端到端只快 1.2~1.4 倍

场景（Qwen3-30B-A3B，vLLM，单卡 A100）Keff 8 → 1 的变化（自报）
同步 bs=1（带宽瓶颈）TTFT / ITL 各降约 18%；输出吞吐 111 → 135 tok/s（1.22×）
吞吐 bs=256（算力瓶颈）TTFT 降约 30%、ITL 降约 25%；输出吞吐 ~1.9k → ~2.65k tok/s（1.39×）

这是静态把 k 改小测出来的，等于任何跳专家方法在该 Keff 下能拿到的速度上界（没有路由决策开销、没有参差不齐的 per-token 分配）。专家计算降 8 倍，端到端只有 1.2~1.4 倍，因为 attention、KV cache 读写、非专家权重都不受影响——这和 KV Cache 一文里 decode 被 KV 读主导的账是一致的。几个 pp 的方法差异，在这个速度天花板下更不值钱。

实践建议

  • 默认操作点：k=8 的模型，纯文本先试 k=6（作者称「可测的加速、轻微质量损失」）；多模态试 ktext=6、kvision=1~2。作者在完全没参与选点的 MVBench（视频）上验证：kvision=1、ktext=6 得 69.95 vs 全模型 71.40（相对 −2.0%，实测 Keff 1.19）；GLM-4.6V（带 shared expert）上平均 −4.2%，主要掉在 MME-Cognition。
  • vLLM / SGLang 落地：静态 k 是一个 config 改动，不破坏 per-token 计算均匀性，EP 下的负载均衡和延迟保证都保住。动态方案要改 kernel 处理 ragged 分配，还要每次前向多一个决策。
  • 守住生成类 benchmark：调 k 时用 GSM8K / HumanEval 这类会断崖的任务确定下限，别看多选题平均分。
  • 审稿 / 自评自己的方法：对照组必须是「同等实测 Keff 的静态 k」，并且对照组要用上你的方法利用的结构信号（比如模态）。只报校准 Keff 的结果直接打折。
  • 想再快：Keff≈3 以下与其跳专家，不如换小模型或在 attention / KV 侧下手（量化、MLA、KV 分层）。

思考题

1. 为什么说「按 Keff 对齐比较」本身就偏向动态方法？

Keff 只数专家激活次数。动态方法另外付出：每层每 token 的跳过决策计算（Ada-K 还要跑一个 allocator）；ragged 的 per-token 专家数导致 grouped GEMM 填充不满、EP 下各卡负载不均、all-to-all 消息大小不可预测；这些都不进 Keff。静态 top-k 在同 Keff 下没有这些开销，所以同 Keff 打平其实意味着静态方案实际更快。

2. Router 是用 top-8 训练的，直接改成 top-6 推理为什么损失不大，而降到 top-2 时 GSM8K 会崩？

softmax 后的 gate 权重通常长尾：前几个专家拿走大部分质量，第 7、8 个专家的贡献（权重 × 输出）很小，去掉相当于对 FFN 输出做一个小扰动，残差流里能被吸收。降到 1~2 个时去掉的质量变大，且每层误差在几十层里累积；多选题只需比较几个候选的相对对数似然，误差下仍能保持排序，生成任务要自回归几百步、错一步后续全错（数学推理的链式依赖），所以呈断崖。可思考：是否该对去掉专家后的 gate 权重重新归一化？（这会改变输出尺度，是另一个需要对照实验的设计选择。）

3. MoDES 在 VL 模型跑纯文本时 Keff 从 1.2 漂到 7.96，根因是什么？对线上服务意味着什么？

阈值是在 GQA（图像 token 占大头）上校出来的，节省主要靠视觉 token；纯文本请求里没有视觉 token，而文本 token 的路由分数分布在阈值下几乎不触发跳过，于是回到全专家。线上影响：容量规划按校准 Keff 估算的吞吐会严重高估；流量构成（图文比）变化就能让集群算力需求翻数倍。静态 per-modality 的好处是算力上界可预测。

4. 与 MoE 路由与负载均衡 一文联系：训练期的负载均衡损失 / bias 调整，会如何影响推理期跳专家的效果？

负载均衡（aux loss 或 DeepSeek-V3 的 bias 法）推动 gate 分布更平、专家更「平等」，这会让 top-k 内部权重差距变小——尾部专家贡献不再可忽略，基于分数差/累计质量的跳过（NAEE 类）判据更难区分，静态砍 k 的损失也可能更大。反过来，如果模型训练时就用可变 k（论文背景提到的 MoD、动态 k 训练方法），推理期跳专家才与训练分布一致，这也是作者指出「训练期方案尚未被主流开源模型采用」的意义。

5. （开放题）Ada-K 用 PPO 训 allocator，奖励 = 质量 − λ·专家数。在这篇的结论下，RL 方法要在什么条件下才可能超过静态 baseline？

至少需要：（1）奖励里的质量信号与最终 benchmark 对齐（next-token loss 对 VL 模型的视觉 token 根本没有监督信号，这也是作者没在 VL 上跑 Ada-K 的原因）；（2）把真实运行时成本（ragged 开销、通信）放进代价项，而不是只罚专家数；（3）allocator 的输入要包含静态 baseline 拿不到的信息（如 token 难度、上下文位置），否则它最多学到一个分模态 / 分层的常数策略——那就是静态 baseline。可以进一步讨论 per-layer 静态 k（无需校准分布，只需一次离线搜索）是否是更强的中间对照组。
