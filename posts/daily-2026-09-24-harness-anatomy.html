学习笔记｜Harness Engineering：十一套生产 Coding Agent 的源码解剖（七子系统 / 29 模式）

2026-09-24 · 收藏夹：Harness / Agent · 学习笔记
论文：Barbaste / Darrigol / Vu / Wiltberger（Inclusive Brains / Wavestone AI Lab）· Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents — A Source-Code Study of Eleven Systems · arXiv:2609.00006。 交叉： Harness Runtime、 mini-SWE-agent、 OpenHands V1、 组件消融、 HEART。

背景与动机

Agent = Model + Harness。模型提供智能；harness 用 loop、工具、上下文、安全、编排与扩展面把智能接到仓库与终端。 2026 上半年「Harness Engineering」从口语变成学科，但缺一份钉死到生产源码的参考解剖—— Barbaste 等这篇 83 页研究填的就是这个空：十一套生产 coding harness + Omnigent 作为 meta-harness 对照， 不排名、不刷榜，只描述怎么造。

十一套：Claude Code、Codex CLI、Gemini CLI、Mistral Vibe、OpenHands、Aider、Mini-SWE-Agent、Hermes、Pi、OpenCode、OpenClaw； 对照点 Omnigent（Databricks）把多家 harness 当成可互换后端。快照钉在 2026-07；其中八套与 2026-04 版形成纵向 diff。

一句话：约 4M LOC 里找不到 LangChain/LangGraph/AutoGen 导入，也找不到向量检索—— 全是手写 async loop + ripgrep/tree-sitter/glob/Markdown 确定性检索； 论点：H1 2026 harness 已从工具翻成平台（13 观察 / 29 模式 / 18 建议 / 90 行 MVP）。

② 两个「缺席」：框架与向量检索

缺席作者发现（自报）实际替代
通用 agent 框架 ~4M LOC 的 Py/TS/Rust 中无 LangChain / LangGraph / AutoGen 等导入；Gemini CLI 也不用 Google 自家框架 手写 async loop、自建 registry / middleware
向量 embedding 检索 无一套用 embedding 做代码检索 ripgrep、tree-sitter、glob、自动发现的 Markdown 上下文（AGENTS.md / GEMINI.md 等）

这与站内 mini-SWE 的「bash + 无状态 subprocess」基线同向： 生产路径优先确定性、可审计、低依赖，而不是通用编排库。 讽刺之处：术语「harness engineering」最早从 LangChain 圈传开，但语料 runtime 里看不到它的库。

③ 扩展标准：SKILL.md / MCP / ACP

标准采纳（作者计数）要点
SKILL.md 9 / 11 技能包领先；含 registry、trust tier、首见 agent 自写 skill
MCP 8 / 11 工具/数据连接标准；与 skills 并存而非互斥

实践建议

  • 先画七格，再加功能。 新 harness 或改造旧脚手架时，对每个子系统写清「最小 / 目标」形态，避免只堆 tools。
  • 检索默认走确定性路径。 ripgrep + AST + 约定 Markdown 上下文文件；向量索引当可选加速层，别当唯一真相源。
  • 扩展面优先 SKILL.md，MCP 作工具总线。 语料显示 skills 采纳领先；两者可叠，别二选一教条。
  • 安全从配置落地，不只从 system prompt。 纵向趋势是策略迁出散文；权限、sandbox、doom-loop 询问应有代码路径。
  • 把「能宿主其它 harness」当成平台能力。 ACP hosting / Omnigent 式 meta 层说明互操作比单打独斗更值钱。
  • 90 行 MVP 可当教学地板。 作者脚手架实现约十条建议；学习路径：Mini-SWE 地板 → 加权限与扩展 → 再谈编排。

思考题

1. 为什么生产 harness 普遍不用 LangChain 一类框架？

作者观察是控制面要钉死到 loop、权限、缓存方言与厂商特性；通用库抽象层往往挡路。框架侧反应是自研 harness，两边在形态上汇合。

2. 「无向量检索」是否等于「无检索」？

否。语料用的是 JIT / 确定性检索：grep、tree-sitter、glob、自动发现的 AGENTS.md 等。缺的是 embedding index 作为默认路径。

3. SKILL.md 领先 MCP 说明什么产品判断？

技能包更接近「可分发的行为与工作流」；MCP 更接近「接外部工具/数据」。生产上两者并存，skills 更易形成 marketplace 与 trust tier。

4. ACP 的「harness hosting」角色新在哪里？

过去 ACP 多被看成会话/编辑器协议；现在 harness 可把其它 harness 当后端互换——互操作升到运行时宿主层。

5. 「从工具到平台」对自建 Agent 团队意味着什么？

要规划 SDK、插件市场、会话导入、治理与可观测，而不只是「能改文件的 CLI」。meta-harness 会出现时，专有差异应可被策略层套利或替换。
