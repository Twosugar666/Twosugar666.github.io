学习笔记｜V-trace：IMPALA 用截断重要性采样稳住 off-policy Actor-Critic

2026-09-25 · 收藏夹：算法 / RL · 学习笔记
经典：Espeholt et al. · IMPALA: Scalable Distributed Deep-RL with Importance Weighted Actor-Learner Architectures · ICML 2018 · arXiv:1802.01561。 交叉： Importance Sampling、 GAE、 Actor-Critic、 PPO、 Granite 4.2（TIS）、 RLOO。

背景与动机

IMPALA 把 Actor 与 Learner 解耦：大量 actor 在各自环境里用行为策略 μ 采样， 中央 learner 用目标策略 π 更新。吞吐上去了，但轨迹相对 learner 一定是 off-policy——μ 与 π 不一致，朴素策略梯度会偏。

纠正手段是 Importance Sampling：逐步乘积 ρ=π/μ。 长轨迹上未截断的乘积方差爆炸。V-trace 的回答是： 截断两套 ratio——ρ̄ 管「修正到目标策略的强度」，c̄ 管「时间信用能回传多远」—— 得到可在大规模 actor–learner 架构里稳定跑的 off-policy value target。

一句话：v_s = V(x_s) + Σ_t γ^{t−s} (∏_{i=s}^{t−1} c_i) δ_t V， 其中 δ_t V = ρ_t (r_t + γ V(x_{t+1}) − V(x_t))，ρ_t=min(ρ̄, π/μ)，c_t=min(c̄, π/μ)； 通常 ρ̄ ≥ c̄；策略梯度用截断 ρ 加权相对 v 的 advantage。

机制拆解

① 为什么 Actor–Learner 必须谈 IS

On-policy AC / PPOIMPALA Actor–Learner
采样策略 与更新策略同为 π（或极近） Actor 用 μ，Learner 更新 π
延迟 同步或近同步 rollout 轨迹入队时 π 可能已前进数步
无修正后果 — 价值与策略梯度对错误分布期望，偏置累积
修正工具 常靠 clip / 短信任域（见 PPO） 轨迹级 IS + V-trace 截断 
# 逐步重要性比
ρ_t = π(a_t | x_t) / μ(a_t | x_t)

# 朴素逐步乘积（长轨迹方差易爆）
ρ_s · ρ_{s+1} · … · ρ_t

② V-trace 目标：截断 ρ 与 c

# 截断后的 ratio（论文常用记号）
ρ_t = min(ρ̄, π(a_t|x_t) / μ(a_t|x_t))
c_t = min(c̄, π(a_t|x_t) / μ(a_t|x_t))
# 实践上通常取 ρ̄ ≥ c̄

# TD 残差（带截断 ρ）
δ_t V = ρ_t * ( r_t + γ * V(x_{t+1}) − V(x_t) )

# V-trace 目标
v_s = V(x_s) + Σ_{t=s}^{s+n-1} γ^{t-s} * (∏_{i=s}^{t-1} c_i) * δ_t V
# 约定：空积 ∏ = 1
符号角色直觉
ρ_t 进 δ_t V 的截断 IS 控制「这一跳」要把更新拉向 π 多狠
c_i 积在时间折扣链上的截断系数 控制更远的 δ 能回传到 s 的幅度（信用分配长度）
ρ̄ ≥ c̄ 常见超参关系 允许单步修正稍强，但回传链更保守，抑方差
v_s off-policy value target Critic 回归目标；也可构造 advantage

ρ 与 c 都来自同一 ratio π/μ，但截断阈值可以不同： ρ 决定目标策略修正强度，c 决定时间信用回传。 这与站内 GAE 用 λ 在 TD↔MC 之间拧偏差–方差是同一类旋钮， 只是 GAE 通常假设 on-policy（或近 on-policy），V-trace 显式服务 off-policy 轨迹。

③ 策略梯度侧：截断 ρ 加权 advantage

# 相对 V-trace 目标的 advantage（示意）
A_t ≈ ρ_t * ( r_t + γ * v_{t+1} − V(x_t) )
# 或等价地用 v_t − V(x_t) 等 IMPALA 实现变体

# 策略梯度带截断 IS
∇ ≈ E_μ [ ρ_t * ∇ log π(a_t|x_t) * A_t ]
组件V-trace / IMPALA对照
Critic 回归 v_s Actor-Critic 的 V 头

读 LLM 后训练里的 TIS / 异步 IS 时，把 V-trace 当经典参照： 截断的是 ratio，保护的是方差，付出的是偏置—— ρ̄、c̄（或 token 截断阈值）都是偏置–方差旋钮，不是「越大越 on-policy 正确」。

实践建议

  • 异步 actor–learner 先承认 off-policy。 队列越深、learner 越快，μ 与 π 差距越大，越需要 V-trace 一类修正。
  • 扫 ρ̄、c̄ 时保持 ρ̄ ≥ c̄。 先固定一对常用值，再看价值损失与策略熵是否失控。
  • 监控 IS ratio 分布。 大量 ρ≪1 或频繁顶到 ρ̄，说明行为策略过旧——优先减延迟，而不是只拧截断。
  • 与 GAE 选型：近 on-policy 用 GAE；明显 off-policy 用 V-trace。 不要把 GAE(λ) 直接当 off-policy 银弹。
  • LLM 栈对照 TIS。 token 级截断与轨迹级 V-trace 同属截断 IS；实现时分清粒度与 advantage 定义。
  • 无 Critic 方法另册。 RLOO/GRPO 用组内相对信号省 V；有环境逐步奖励且异步采样时，V-trace AC 仍更贴经典控制任务。

思考题

1. 为什么朴素逐步乘积 ρ 会在长轨迹上炸？

每步 ratio 独立波动时，乘积的方差随长度 Roughly 指数恶化；极端小概率动作若 π≫μ，单项已很大，连乘更不稳定。

2. ρ 与 c 都截断同一 ratio，为何还要两套阈值？

ρ 进入 TD 残差，管「这一跳」对目标策略的修正；c 乘在回传链上，管更远残差能否传到当前状态。分开才能「修正稍强、回传更保守」。

3. V-trace 相对 on-policy GAE 多付出了什么代价？

截断引入偏置，换来方差可控的 off-policy 目标。若数据已近 on-policy，GAE 往往更简单、偏置结构更清晰。

4. TIS 与 V-trace 最容易混淆的一点是什么？

都叫「截断 IS」，但 TIS 多在 LLM token ratio 上截断，V-trace 在轨迹环境步上截断并拆 ρ/c。家族相同，公式与实现层不同。

5. Actor–Learner 延迟变大时，应先调什么？

先减队列延迟 / 提高 actor 同步频率，使 μ 贴近 π；截断阈值是止损，不是无限容忍过期数据的许可证。
