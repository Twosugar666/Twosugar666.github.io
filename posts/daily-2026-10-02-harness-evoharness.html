学习笔记｜EvoHarness-RL：把 Belief / Progress / Experience 训成可学的运行时协调层

2026-10-02 · 收藏夹：Harness / Agent · 学习笔记
论文：Ning, Fu, Wei, Zeng et al. · EvoHarness-RL: Learning Self-Evolving Runtime Harness for Long-Horizon LLM Agents · arXiv:2608.05446。 交叉： EvoHarness 初读（09-11）、 Hard Stop、 Growing Harness、 ModularRSI、 HEART、 GRPO。

背景与动机

长程 agent 外面通常挂着一堆「执行支持」：记世界状态、追子目标、调工具、验结果、跨 episode 复用经验。 难点往往不在「有没有 memory / tool」，而在两件事耦合： (1) 从嘈杂轨迹形成外部状态； (2) 运行时何时读 / 写这些状态。 多数系统把两者留给 prompt、启发式或领域约定——workspace 与用法策略都是人肉工程。

EvoHarness-RL 把问题立成 harness policy learning：离线学 harness 策略，在线部署时构造与更新外部 harness 状态。 站内 09-11 初读已铺过 BPE 与退火叙事； 本文换一个切面——把它当成可学的运行时协调层，并和近期 Hard Stop（越界硬停）、 Growing（从失败窗口长控制代码）、 ModularRSI、HEART 对照：谁管「状态怎么外置与何时访问」，谁管「越界怎么停 / 脚手架怎么长」。

一句话：BPE 三态 + {track, commit, recall, note}；SFT → cost-aware GRPO； ALFWorld + Qwen3-8B：seen 96.9% / unseen 86.6%； annealing 至约 1 次 harness call / episode；Experience skill bank 巩固 / 遗忘。

机制拆解

① BPE：面向策略的三态外置

状态语义典型 meta-action
Belief B_t 环境当前「以为为真」的世界状态 track：查询 / 刷新 belief
Progress P_t 已完成 / 待办子目标与执行进度 commit：提交或更新 progress
Experience E_t 跨 episode 可复用知识（skill bank） recall 检索；note 写入新洞察

异构 memory / planner / log 被压成策略可直接动作的接口，而不是再堆一套不可学的脚手架 DSL。 ALFWorld adapter 把 B/P/E 分别落地为 world-state tracker、committed subgoal plan、跨 episode skill bank； 抽象层不变，换环境主要换 grounding。

② 训练两段：先语义，再「值不值得花一步」

# Stage 1 — Supervised harness fine-tuning
#   目标：教会 BPE 动作语义，从轨迹外置有用的 B/P/E
# Stage 2 — Cost-aware GRPO（Shao et al. 2024 系）
#   harness action 与 env action 共享交互预算
#   学的是：何时读/写/巩固外部状态才划算

R(τ) = R_succ(τ)                 # 任务成功（主门控）
     + λ_eff  R_eff(τ)           # 效率 bonus
     + λ_div(u) R_div(τ)         # 动作多样性
     − λ_spam R_spam(τ)          # 刷 harness / spam
     − λ_inv  R_inv(τ)           # 非法格式

成功项是门控：没做成任务，效率 / 多样性再好看也撑不起策略。 spam / inv 把「疯狂 track/recall」和坏格式从高奖励区赶走——否则 GRPO 会学到用 harness 刷步数或刷多样性。 与站内 GRPO 对照：这里把相对优势用在协调策略上，而不是纯答题 token。

③ 结果与消融（论文自报）

设置口径
EvoHarness-RL · ALFWorld seen 96.9% success（Qwen3-8B；相对 base ReAct +49.0 abs）
EvoHarness-RL · unseen 86.6%（ReAct 50.0%；prompt-time BPE 零样本约 77.6%）
消融直觉 去掉 Belief / Progress / Experience 任一模块，成功率明显掉（Experience 消融约到 48.6% 量级）

prompt-time BPE 已经抬高 stateful 任务；SFT + GRPO 再把「会用」推到「省着用」。 unseen 上 full RL 高于仅 prompt BPE，说明 cost-aware 阶段学到的是可迁移的访问策略，而不只是背训练房布局。

④ Harness annealing 与 harness evolution

动态现象（据论文）含义
Annealing GRPO 中 harness call 从频繁脚手架用法快速下降，稳定在约 1 次 / episode 例行模式内化进策略；外部访问留给期望收益盖过步成本的时刻
Evolution Experience store：积累 → 巩固 → 遗忘；skill bank 从膨胀到紧凑（通用 / 任务 / 纠错 / 搜索优先级） 协调层不只调「何时调用」，还改写可复用底物本身

annealing ≠「最终删掉 harness」。删的是无效频繁调用；保留的是选择性外置。 与 Growing Harness 对照：Growing 从失败窗口长出可复用控制代码； EvoHarness 用 RL 决定何时碰已有 BPE，并用 note/consolidate 演化 skill bank——一个偏「长出结构」，一个偏「学会调度与改写状态」。

⑤ 和 Hard Stop / ModularRSI / HEART 怎么叠

系统主问题与 EvoHarness 关系
Hard Stop 越界后的内核级抢占 正交：EvoHarness 优化合法循环内的状态协调；Hard Stop 假设循环已 rogue
ModularRSI 模块化自我改进回路 可把 BPE 当作 RSI 循环里可学习的 memory/progress 接口
HEART harness 评估 / 组件视角 EvoHarness 提供「协调策略可训」的实例，便于放入 HEART 类评测轴

实践建议

  • 先固定 BPE 接口，再写 adapter。 换环境时改 grounding，不改 meta-action 词汇表，策略才可迁移。
  • SFT 与 GRPO 目标分开。 SFT 只解决「会说 track/commit/recall/note」；何时值得说，交给带 spam/效率项的 RL。
  • 监控 harness calls / episode。 若长期停在高频脚手架用法，多半是奖励里缺成本项，或 SFT 示范过度依赖外置。
  • Experience 要有巩固与遗忘。 只 append 的 skill bank 会胀死 context；论文里的合并 / 稀有条目淘汰是标配，不是可选美化。
  • 安全层另挂。 协调层学的是省步成功；越权、逃逸仍要 ActPlane / DSec / Hard Stop 一类边界。

思考题

1. 为什么 harness action 必须与 env action 共享预算？

若外置读写「免费」，策略会倾向于无限 track/recall；共享步预算后，访问变成有机会成本的决策，GRPO 才能学选择性。

2. annealing 到 ~1 call/episode 是否说明 BPE 只在开头有用？

不一定。次数下降常伴随模式内化；关键时刻（失败恢复、跨房搜索）仍可能召回 Experience。看的是分布，不是「永远只调用一次」的硬规则。

3. R_spam 与 R_div 会不会互相打架？

会。多样性鼓励换动作，spam 惩罚无效重复 harness。权重与 curriculum（先学语义再加压成本）需要一起调，否则策略在「乱换动作」和「死刷同一 tool」间震荡。

4. EvoHarness 与 Growing Harness 能否同栈？

可以：Growing 负责从失败窗口沉淀控制代码；EvoHarness 负责运行时何时读写 BPE / skill bank。前者扩结构，后者学调度。

5. unseen 上 RL 相对 prompt BPE 的增益说明什么？

说明 cost-aware 阶段学到的访问策略可迁移到新房布局，而不是只记忆 seen 轨迹里的物体位置。
