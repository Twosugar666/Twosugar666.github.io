学习笔记｜SimPO：用平均 logprob 当隐式奖励、丢掉 reference model 的偏好优化

2026-09-21 · 收藏夹：算法 / RL · 学习笔记
经典：Meng, Xia, Chen · SimPO: Simple Preference Optimization with a Reference-Free Reward （NeurIPS 2024）· arXiv:2405.14734。 交叉： DPO、 KTO、 KL 散度、 Softmax / Entropy、 PPO。

背景与动机

DPO 把 KL 约束 RL 的最优策略重参数化成隐式奖励 r = β log(π_θ(y|x) / π_ref(y|x))，从而跳过显式 RM + PPO。 代价仍在：训练时要挂一个冻结的 reference model（多占一份前向与显存），且奖励用的是序列总 logprob，容易偏爱更长回复。

SimPO（Simple Preference Optimization） 做两处手术：① 隐式奖励改成长度归一化的平均 logprob r = (β/|y|) log π_θ(y|x)，不再除以 π_ref；② 在 Bradley-Terry 里显式加 margin γ。 结果是 reference-free：少一次参考模型前向，工程更简单，并对齐指标上作者报出明显增益。

一句话：SimPO = 用平均 log-likelihood 当奖励（无 π_ref）+ BT 目标加 margin γ；比 DPO 更贴生成度量，且省参考模型的算力与显存。

机制拆解

① 从 DPO 奖励到 SimPO 奖励

# DPO 隐式奖励（依赖 reference）
r_DPO(x, y) = β * log( π_θ(y|x) / π_ref(y|x) )
            = β * ( log π_θ(y|x) − log π_ref(y|x) )

# SimPO 长度归一化、reference-free 奖励
r_SimPO(x, y) = (β / |y|) * log π_θ(y|x)
# |y| = 回复 token 数；log π_θ(y|x) = 序列总 logprob
# 等价于：β * (平均 token logprob)
对比DPOSimPO
奖励形式β log(π_θ/π_ref)(β/|y|) log π_θ
Reference model需要（冻结前向）不需要
长度总和 logprob，易偏长平均 logprob，抑制注水
与生成训练度量含 π_ref 比更直接对齐「高平均似然」生成质量

与 KL 的关系：DPO 的 π_ref 项来自 KL 约束最优解；SimPO 丢掉显式 ref 后，用长度归一 + margin 承担「别无限抬高似然 / 拉开胜负」的正则角色，而不是再挂一个参考分布做 KL。

② Bradley-Terry + margin

# 带 margin 的 BT 偏好概率
p(y_w ≻ y_l | x) = σ( r(x, y_w) − r(x, y_l) − γ )

# γ > 0：要求胜出回复的奖励比落败高出至少 γ，才算「够赢」

margin 把「略胜」和「明显胜」分开：γ=0 时只要 r_w > r_l 就推；γ>0 时梯度更强调拉开差距。作者消融称 γ=0 次优。

③ SimPO loss

# 把 r_SimPO 代入带 margin 的 BT，最大似然：
L_SimPO = − E_{(x,y_w,y_l)} [
  log σ(
      (β / |y_w|) * log π_θ(y_w|x)
    − (β / |y_l|) * log π_θ(y_l|x)
    − γ
  )
]

# 典型超参（作者口径）
# β ∈ [2.0, 2.5]
# γ ∈ [0.5, 1.5]
符号作用
β缩放平均 logprob；典型 2.0–2.5，比 DPO 常用 β 量级更大（因奖励定义不同，勿直接搬）
γ胜负 margin；0.5–1.5；γ=0 作者报次优
|y|长度归一；去掉后易长而重复（作者消融）
π_ref不出现——少一次前向

实现注意：log π_θ(y|x) 对 response token 求和时做 padding mask；|y| 用有效 token 数。与 Softmax / Entropy 对照：这里优化的是序列平均 logprob 差，不是显式熵 bonus；但「别用总 logprob 鼓励注水」与长度归一同向。

④ 与 DPO / KTO / PPO-RLHF

KTO 解决「没有成对偏好、只有好/坏」；SimPO 仍要 (y_w, y_l)，但把 DPO 的 ref 与长度问题收掉。 需要在线探索或可验证奖励时，仍回到 PPO / GRPO 栈，而不是用 SimPO 硬替。

实践建议

  • β / γ 按 SimPO 量表扫，勿照搬 DPO 的 β。 奖励已是平均 logprob，数值尺度不同；先从 β∈[2.0,2.5]、γ∈[0.5,1.5] 网格起。
  • 长度归一默认开。 关掉等于用总 logprob 当奖励，作者报会长而重复——与对齐榜上的 verbose bias 同族。
  • 省下的 ref 前向可换 batch。 同卡可加大 micro-batch 或序列长，但先回归偏好过拟合与能力榜。
  • 仍要高质量偏好对。 Reference-free 不降低对标签噪声的敏感；y_w/y_l 过近时 margin γ 会让梯度更「挑食」，需监控有效 pair 比例。
  • 与 DPO 对照实验写清度量。 比 LC / Arena-Hard 时固定解码温度与长度惩罚；否则长度归一的收益会被评测协议吃掉。
  • 有规则奖励时别硬换 SimPO。 数学/代码可验证场景优先 RLVR；SimPO 主场仍是偏好对齐轴。

思考题

1. 为什么 (β/|y|) log π 比 β log(π/π_ref) 更「贴近生成」？

解码时模型按自身 π_θ 采样，并不除以 π_ref。平均 logprob 直接描述「这条回复在当前模型下有多像自己会说的话」；DPO 的比还编码了相对参考的偏离，训练信号与纯生成度量不完全同构。

2. 去掉长度归一会发生什么？

奖励变成与序列总 logprob 成正比，优化器倾向更长回复以累积 logprob。作者消融：w/o LN 伤害大，出现长而重复。

3. margin γ 的作用与 γ=0 为何次优？

γ 要求 r_w − r_l ≥ γ 才算充分满足偏好，迫使胜负在奖励空间拉开。γ=0 时微弱优势即可，区分度不足；作者报 γ=0 次优。

4. SimPO 省掉 reference model，还如何防止策略崩坏？

不再靠显式 KL(π||π_ref)。改为：长度归一限制「靠注水抬总 logprob」，margin 限制「只略胜也猛更新」，外加 β 缩放。仍需用 SFT 初始化与偏好数据质量托底；极端分布外仍可能崩，需能力榜回归。

5. 什么时候选 SimPO，什么时候留在 DPO / KTO？

有成对偏好、想省 ref 显存/时间、且受长度偏置困扰 → SimPO。需要与 SFT 参考强锚定、沿用现成 DPO 配方 → DPO。只有二元好/坏、无配对 → KTO。可验证任务 → PPO/GRPO 更合适。
