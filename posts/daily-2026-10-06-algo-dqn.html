学习笔记｜DQN 与 Double DQN：Experience Replay、Target Network 与 max 算子的过估计

2026-10-06 · 收藏夹：算法 / RL · 学习笔记
经典论文：Mnih et al. · Playing Atari with Deep Reinforcement Learning · arXiv:1312.5602； Mnih et al. · Human-level control through deep reinforcement learning（Nature 2015）； van Hasselt, Guez, Silver · Deep Reinforcement Learning with Double Q-learning · arXiv:1509.06461（AAAI 2016）。 交叉： TD3、 SAC、 TD(λ)、 Importance Sampling。

背景与动机

上一篇 TD3 讲「双 Critic 取 min 压过估计」，SAC 也沿用了 twin Q。这条血脉的源头在离散动作的 value-based RL：Q-learning → DQN → Double DQN。 把它补上，后训练里很多「target 网络」「replay buffer」「过估计偏差」的说法就都有了出处。

表格型 Q-learning 收敛性很好，但一换成神经网络近似就容易发散。Sutton & Barto 把这种危险组合叫 deadly triad：函数逼近 + bootstrapping + off-policy。DQN 没有从理论上消掉它，而是用两个工程手段把它压到可训练的范围内，第一次在 Atari 上用同一套网络和超参从像素学会了几十个游戏。

机制拆解

① 从 Q-learning 到 DQN

# 表格 Q-learning（off-policy TD 控制）
Q(s,a) ← Q(s,a) + α · [ r + γ · max_a' Q(s',a') − Q(s,a) ]

# DQN：Q 用网络 Q_θ 表示，最小化 TD 误差
y       = r + γ · (1 − done) · max_a' Q_θ⁻(s', a')      # θ⁻ 是 target 网络
L(θ)    = E_{(s,a,r,s')~D} [ ℓ( Q_θ(s,a) − y ) ]        # ℓ 常用 Huber
# 行为策略：ε-greedy(Q_θ)，ε 随训练线性退火
组件做什么解决什么
Experience Replay把转移 (s,a,r,s′) 存进大缓冲 D，训练时均匀随机采 minibatch打散时间相关性；一条样本复用多次，提高样本效率；平滑行为分布的突变
Target Network目标 y 用一份冻结参数 θ⁻ 计算，每 C 步从 θ 硬拷贝一次避免「自己追自己」：更新 θ 时目标不跟着同步移动，减少振荡和发散
Error / Reward clippingTD 误差梯度截到 [−1, 1]（等价 Huber）；Atari 奖励截到 {−1, 0, +1}不同游戏奖励尺度差异大，统一超参；防止大误差主导更新
预处理84×84 灰度、4 帧堆叠、frame skip 4部分可观测（速度信息）与算力

Nature 版常被引用的超参（见原文表格）：replay 容量 1M，minibatch 32，γ=0.99，target 更新间隔 C=10,000，RMSProp 学习率 0.00025，ε 在前 1M 帧内从 1 退火到 0.1。注意 replay 让 DQN 天然是 off-policy：缓冲里的动作来自旧策略，但 Q-learning 的目标里是 max 而不是「行为策略的期望」，所以一步 TD 不需要 重要性采样修正；改成 n-step 回报时才需要考虑。

② max 算子为什么会过估计

设真实 Q*(s′,·) 对所有动作相等，网络估计带零均值噪声 ε_a。那么 E[max_a (Q* + ε_a)] ≥ max_a Q* ：对噪声取 max 会系统性偏高（Jensen 不等式 + 选择偏差）。 问题出在同一个估计既用来选动作又用来评估动作——被某个噪声高估的动作恰好被选中，然后它的高估值又被当成目标。过估计本身若是均匀的，不影响贪婪策略；但它往往不均匀，并且会沿 bootstrapping 一步步传播。

③ Double DQN：选择与评估解耦

# DQN 目标：同一个 θ⁻ 既 argmax 又评估
y_DQN    = r + γ · Q_θ⁻( s', argmax_a' Q_θ⁻(s', a') )

# Double DQN：online 网络 θ 选动作，target 网络 θ⁻ 评估
a*       = argmax_a' Q_θ(s', a')
y_Double = r + γ · Q_θ⁻( s', a* )

# 改动只有一行；不需要额外网络（复用现成的 target 网络当第二个估计器）

思想来自 van Hasselt 2010 的表格型 Double Q-learning：维护两套独立估计 Q^A、Q^B，用一套选、另一套评，两者噪声独立时，被选中的动作在另一套里不再系统性偏高。Double DQN 偷了个懒，直接拿 online / target 两份参数当「近似独立」的两个估计器。论文在 Atari 上展示了 DQN 的价值估计远高于真实折扣回报，而 Double DQN 的估计贴近真实值，且多数游戏分数更高（见原文图表）。

④ 一张表串起来：Double 系列的「保守」思想

方法动作空间目标里怎么压过估计偏差方向
DQN离散不压；只靠 target 网络稳住训练偏高
Double DQN离散online 选、target 评接近无偏，仍可能略高
TD3连续两个独立 critic 取 min（Clipped Double Q）偏低（刻意保守）
SAC连续twin Q 取 min + 熵项偏低

TD3 论文明确指出，在 actor-critic 里 online 与 target 网络变化太慢、太相似，Double DQN 式解耦效果有限，于是改成两个独立 critic 再取 min，用低估换稳定。看懂这一条，就能理解为什么连续控制里「取 min」成了默认动作。

⑤ 之后的 DQN 家族（只列方向）

  • Prioritized Experience Replay（Schaul et al.）：按 |TD 误差| 采样，并用重要性权重修正采样偏差。
  • Dueling DQN（Wang et al.）：Q 拆成 V(s) + A(s,a) 两个头，A 减去均值保证可辨识。
  • Rainbow（Hessel et al.）：Double、PER、Dueling、n-step、Distributional（C51）、Noisy Nets 六件套合一。

实践建议

  • 默认就用 Double DQN 目标。 改动一行、零额外开销，几乎没有理由用原版 max 目标。
  • Huber 损失 + 梯度裁剪是标配。 「error clipping」本意是截梯度，不是截损失值；直接把 TD 误差 clamp 到 [−1,1] 再平方，会让大误差的梯度变成 0，方向反了。
  • 监控「预测 Q 均值 vs 实际折扣回报」。 这是 Double DQN 论文的核心诊断图：两条曲线越拉越开，说明过估计在累积。
  • target 更新方式二选一： 每 C 步硬拷贝（DQN 原版），或每步 Polyak 软更新 θ⁻ ← τθ + (1−τ)θ⁻（DDPG / TD3 / SAC 常用）。两者是同一个稳定化思想的不同节奏。
  • 迁移到 LLM 后训练时的对应关系： PPO / GRPO 里的 reference / old policy、value 头的 target、off-policy replay 的 staleness 处理，都能在 DQN 这两个组件里找到原型；但 LLM 动作空间是整个词表序列，Q 网络式 argmax 不可行，所以主流走策略梯度（见 PPO、GRPO）。

思考题

1. 如果只用 Experience Replay 不用 Target Network（或反过来），各会出现什么问题？

只有 replay：样本去相关了，但目标随每次更新同步移动，仍容易振荡或发散。只有 target 网络：目标稳定了，但连续采样的强相关样本让梯度方差大、网络容易对最近的经验过拟合并遗忘旧状态。两者解决的是不同来源的不稳定。

2. 为什么 DQN 的一步 TD 目标不需要重要性采样修正，而 n-step 版本需要考虑？

一步目标 r + γ max Q(s′,·) 只依赖 (s,a,r,s′) 这一个转移，与行为策略在 s′ 之后的选择无关，评估的是贪婪策略。n-step 回报包含行为策略在中间状态选的动作，和目标策略不一致，严格来说要用 IS 或截断修正（如 Retrace、V-trace）；实践里 Rainbow 直接用未修正的 n-step，靠 n 较小来控制偏差。

3. Double DQN 用 online 和 target 两份参数当两个估计器，这两个估计器真的独立吗？

不独立，target 只是 online 的延迟副本，噪声高度相关，所以只能部分消除过估计。这正是 TD3 在 actor-critic 中改用两个独立训练 critic 并取 min 的原因。

4. 过估计如果对所有动作都是均匀的，会不会影响策略？

不会影响贪婪动作的选择，因为 argmax 对整体平移不变。问题在于实际过估计不均匀：访问少、噪声大的动作更容易被高估，策略就会被吸引过去，而且偏差会通过 bootstrapping 传播到前序状态。

5. 为什么 Atari DQN 要做奖励裁剪？它有什么代价？

不同游戏奖励尺度差几个数量级，裁剪到 {−1,0,+1} 后可以用同一学习率和网络。代价是丢失奖励大小信息，智能体分不清「吃一个小豆」和「吃一个大奖」，在某些游戏里会学到次优策略；后续工作用 value rescaling（如 R2D2 的 h 函数）或 PopArt 替代。
