学习笔记｜推测解码（Speculative Decoding）：「先猜后验」为什么能快 3 倍还严格无损

2026-09-07 · 收藏夹：Infra · 领域轮更（infra）
主要依据：Leviathan et al. arXiv:2211.17192、 Chen et al. arXiv:2302.01318（两篇 2022/2023 原始论文）、 EAGLE 系列（arXiv:2401.15077）、Medusa（arXiv:2401.10774）； 加速比汇总数字参考 Morph 的整理

背景与动机

KV cache 笔记留下了一个结论：decode 阶段是 memory-bandwidth-bound—— 每步都要把全部权重 + KV cache 从 HBM 读一遍，却只产出 一个 token。算术强度极低，GPU 的算力在 decode 时大面积闲置。

推测解码（speculative decoding）就是对「一次前向只出一个 token」这个浪费的直接攻击： 既然读一遍权重的成本已经付了，能不能用这一遍前向同时「验证」多个 token？ 答案是 draft-then-verify——小模型先猜 γ 个 token，大模型一次并行前向全部核验，接受前缀、拒绝即回退。 近期它重新变热：GLM-5.2 把 MTP 层的接受长度提升 20%（GLM-5.3 笔记提过）， 开源社区用 DFlash2 类推测解码把 Qwen3.8-27B 在单卡上推到 250+ tok/s，vLLM/SGLang 都把推测解码做成了一行配置。 本篇把机制、无损性证明的直觉、加速比公式和草稿模型的四条路线讲透。

核心概念

1. 机制：先猜后验，一轮最多产 γ+1 个 token

每轮循环：
  ① 草稿：小模型（或 n-gram / 草稿头）自回归猜 γ 个 token：x̃_1..x̃_γ   # 便宜
  ② 验证：目标大模型对 γ 个草稿做一次并行前向，拿到每个位置的 p_target(·)  # 与生成 1 个 token 同价
  ③ 裁决：逐个位置接受/拒绝（见下），拒绝发生在位置 i → 接受 x̃_1..x̃_{i-1}，
     并在位置 i 从「修正分布」采样一个 bonus token，本轮结束
  一轮产出：1 ～ γ+1 个 token，分布与大模型逐个生成严格一致

关键点在②：decode 的成本是「读权重 + 读 KV」，验证 γ 个 token 与生成 1 个 token 读的量几乎相同—— 只要还没进入 compute-bound 区间，验证就是近乎免费的。这就是为什么加速来自「带宽闲置」而非「算力节省」。

2. 无损性：修正拒绝采样保持目标分布

对位置 i 的草稿 token x̃（来自草稿分布 q），接受规则： 以概率 min(1, p_target(x̃)/q(x̃)) 接受；若拒绝，从修正分布 normalize(max(0, p_target − q)) 重采样一个 token（bonus token）。 可以证明：这样产出的序列分布与目标模型逐个自回归生成的分布完全相同——推测解码是严格无损的加速，不是近似。 贪心解码（temperature=0）下规则退化为「草稿 == 大模型 argmax 就接受」，实现最简单且接受率最高；温度越高，两分布差异越大，接受率越低。

技术要点

1. 加速比公式：接受率 α 与成本比 c 的账

设草稿长 γ、单 token 草稿耗时 T_d、验证耗时 T_v、目标模型逐 token 耗时 T_ar、接受率 r：
  平均接受长度  L_a = (1 − r^(γ+1)) / (1 − r)
  加速比        speedup = (L_a × T_ar) / (γ·T_d + T_v) ≈ L_a / (γ·c + 1)，其中 c = T_d / T_ar

算例（Morph 整理口径）：r = 0.8、γ = 5、草稿近乎免费（c≈0）→ L_a ≈ 3.69，加速约 3.7×
来源设置报告加速比
Leviathan et al.（2022/23）T5-XXL + 小草稿2～3×（输出完全一致）
Chen et al.（2023）Chinchilla 70B2～2.5×
EAGLELLaMA2-Chat 70B2.7～3.5×
EAGLE-2动态草稿树3.05～4.26×
EAGLE-3training-time test 等多改进最高约 6.5×（官方口径）

两个工程推论：① 接受率 r 是杠杆最大的变量——r 从 0.7 到 0.8，γ=5 时 L_a 从 2.9 涨到 3.7； ② 草稿成本 c 必须远小于 1，否则 γ·c 项直接吃掉收益——「草稿要够蠢够快」是硬约束。

2. 草稿从哪来：四条路线

路线代表优点代价/痛点
独立小模型原始论文；DistillSpec（蒸馏对齐）即插即用，不动目标模型分布对齐难；多存一份模型；接受率上限低
检索 / n-gramPLD、Lookahead、REST；Morph 生产实例（k=64 n-gram）零训练、零额外参数；代码/编辑场景重复度高时奇准只适用于高重复分布（代码、文档编辑）；开放生成弱
目标模型挂草稿头Medusa（多个头各预测一个未来位置）不要独立模型；一次前向出整棵候选头要额外训练；Vicuna-7B 上约 11% 显存开销；各头独立预测、位置间无依赖
特征级自回归草稿EAGLE 系列（目标模型倒数第二层 hidden state + 单层 Transformer 草稿器）接受率最高的一档（草稿与目标分布对齐最紧）训练-推理不一致：训练用真值特征/真值 token，推理用自己的特征/自己的草稿（exposure bias），位置越深接受率衰减越快
训练时内嵌 MTPDeepSeek-V3 的 MTP 模块；GLM-5.2 改进 MTP 层使接受长度 +20%草稿与目标天然同分布（同一模型同一训练）；推理零外挂只能在预训练/后训练阶段加入，存量模型用不了

另一个正交维度是验证结构：链式草稿一次只验一条路径，树形草稿（tree attention）一次并行验证整棵候选树， 相同草稿预算下期望接受长度更高——EAGLE-2 的 4× 级别加速主要靠动态树。

3. 什么时候推测解码不赚

  • 大 batch / 长上下文下，验证不再免费：batch 已经很大时，一次前向的 FLOPs 本来就被打满（进入 compute-bound 区间），多验 γ 个 token 是真金白银的算力——加速比显著缩水，在线服务高并发时可能不值得开；
  • 高温度采样：两分布差异大 → 接受率降；greedy/低温场景最赚；
  • 草稿与目标分布漂移：领域外输入（比如给通用草稿喂医疗文本）接受率塌方；EAGLE 系的 exposure bias 在超长草稿时同样衰减。

实践建议

  • 先在离线/低并发场景开：vLLM 的 --speculative-config、SGLang 的 --speculative-algorithm 都是一行开关；离线批量（评测、数据合成、agent 轨迹生成）几乎稳赚，在线高并发要先测。
  • 监控指标选「平均接受长度」而非加速比：加速比受负载混淆，接受长度 τ 直接反映草稿质量；r 掉了先查输入分布是否漂移，再调 γ。
  • γ 从小往大调：γ 越大期望接受越长，但 γ·c 项线性吃收益；从 3～5 起步，按实测 L_a 曲线找拐点。树形验证下这个旋钮换成树宽/树深。
  • 代码/编辑类负载优先考虑 n-gram 路线：零训练成本、对现有系统侵入最小（prompt lookup）；这正是 Morph 等 coding 产品生产环境的选择。
  • 训练新模型时把 MTP 写进架构清单：GLM-5.2/DeepSeek-V4 的经验是训练期内嵌 MTP 头收益稳定且推理零成本；与 KV cache 笔记的「每 token KV 字节数」一样，「是否自带草稿头」已是模型选型的一阶指标。
  • RL 训练管线的 rollout 侧：推测解码加速 rollout 直接缓解 Mercor 配方里的「系统天花板」（KV 容量 ÷ 轨迹长）；注意投机采样与训练引擎 logprob 的一致性检查（参考该文的 train-inference mismatch 检查）。

思考题

  1. 为什么「验证 γ 个草稿 token」与「生成 1 个 token」成本几乎相同？这个近似在什么条件下失效？
    参考答案 decode 单步的成本由 HBM 读取量主导：全部权重 + 该请求的 KV cache。验证 γ 个 token 只需把 γ 个位置的 K/V 追加进 cache、做一次并行前向——权重和已有 KV 仍只读一遍，增加的只是 γ 个位置的注意力/FFN 计算，而这部分在 memory-bound 区间本来就被带宽闲置掩盖。失效条件：当 batch 足够大或序列足够长，算术强度越过屋顶线拐点进入 compute-bound 区间，γ 个位置的 FLOPs 变成真实成本；此时验证不再免费，加速比向 1 回归。这也是推测解码在高并发在线服务上收益骤降、在离线小 batch 上接近理论值的原因。
  2. 推测解码号称「严格无损」。写出位置 i 的接受/拒绝规则，并解释为什么输出分布与目标模型逐 token 生成完全一致。
    参考答案 对来自草稿分布 q 的 token x̃：以概率 min(1, p(x̃)/q(x̃)) 接受（p 为目标分布）；拒绝则从修正分布 p′ = normalize(max(0, p − q)) 采样。直觉证明：联合看待「提议 + 裁决」后，任意 token x 被产出的总概率为 q(x)·min(1, p(x)/q(x)) + [拒绝概率]·p′(x)。当 q(x) ≤ p(x)：第一项 = q(x)，修正项补足 p(x) − q(x)，合计 p(x)；当 q(x) > p(x)：第一项 = p(x)，修正项为 0，合计 p(x)。两种情形都精确等于目标分布——这是经典拒绝采样「包络-修边」结构在自回归上的逐位置版本，且第一个拒绝位置后本轮终止，保证不重写已接受前缀。所以无损性不依赖草稿质量：草稿差只是慢，不会错。
  3. 加速比公式 speedup ≈ L_a / (γ·c + 1) 中，L_a = (1−r^(γ+1))/(1−r)。在 r=0.6、γ=4、c=0.05 下估算加速比；并说明 r 与 c 哪个对结果更敏感。
    参考答案 L_a = (1 − 0.6⁵)/(1 − 0.6) = (1 − 0.0778)/0.4 ≈ 2.31；分母 = 4×0.05 + 1 = 1.2；speedup ≈ 1.92×。敏感性：r 进入 L_a 的分子是几何级数，r 的小幅提升（0.6→0.7 时 L_a 从 2.31 涨到约 2.86）带来超线性收益，且不收 γ·c 的税；c 在分母与 γ 相乘，只有 γ·c 与 1 可比拟时才显著（c=0.05、γ=4 才 0.2）。所以在 c 很小时优化接受率 r 是最优先的（换更对齐的草稿、缩短 γ、低温解码）；当草稿变重（c→0.3+），γ 和 c 的联合优化才变成主要矛盾。
  4. EAGLE 用目标模型的 hidden state 做特征级草稿，相比 Medusa 的「多头各自预测」解决了什么？又引入了哪个新的训练难题？
    参考答案 Medusa 的每个头独立预测未来第 k 个位置，位置之间没有条件依赖（第 3 个头不知道第 2 个头猜了什么），且只用最终 hidden state——信息瓶颈明显。EAGLE 把草稿器做成一个自回归小模型：输入是目标模型倒数第二层特征 + 已猜的草稿 token 序列，逐位置有依赖地生成草稿，特征信息更全、位置间一致，接受率因此显著更高。引入的新难题是训练-推理不一致（exposure bias 的变体）：训练时草稿器看到的是真值特征 + 真值前缀 token，推理时看到的却是自己上一步生成的特征和自己的草稿 token——特征与 token 双重漂移，位置越深衰减越狠（pos-acc 曲线断崖）。HASS（用草稿步骤特征训练）等工作就是在补这个缝，但单草稿器跨所有位置的泛化仍是瓶颈，催生了「位置专精草稿」一类后续工作。
  5. 训练时内嵌 MTP 头（DeepSeek-V3 / GLM-5.2 路线）与推理时外挂草稿模型，各自的核心优势是什么？为什么说 MTP 路线与 RL 后训练存在耦合红利？
    参考答案 外挂路线的优势是存量可用：任何已发布模型都能配草稿，且草稿可独立迭代（蒸馏、领域适配），不动目标模型的权重与部署。MTP 路线的优势是天然对齐：草稿头与主模型共享主干、在同一训练分布上联合优化，草稿分布与目标分布的错位最小，接受率上限高，且推理时无任何外部组件。耦合红利在于：RL 后训练会显著改变模型的输出分布（想想 GRPO 前后同一 prompt 的回答差异）——外挂草稿若在 SFT 时代训练，RL 后接受率会漂移衰减，需要随策略版本重训；而 MTP 头随主干一起被后训练更新（GLM-5.2 改进 MTP 层使接受长度 +20% 就是后训练期的成果），草稿始终跟随当前策略。这也是 verl-SpeCo 这类「RL 训练与推理共用草稿」工作出现的动机：在 rollout 循环里草稿与策略同源演化，加速收益不被分布漂移侵蚀。
