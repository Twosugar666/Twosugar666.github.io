特别篇｜2026 新模型全景：十五个新旗舰的架构与训练方法拆解

2026-08-27 · 收藏夹：Infra / RL · 特别篇
调研范围：2026 年 1 月–8 月发布的主要语言模型 · 信息来源见文末「参考链接」，文中数字除特别说明外均为厂商自报； 闭源模型（OpenAI / Anthropic / Google）基本不披露架构，相关段落会明确标注「未披露」而非转述传闻

背景与动机

2026 年上半年是大模型发布密度史无前例的半年：6 月一度出现 Claude Mythos 5（6.9）、GPT-5.6（6.11 预览）、 Gemini 3.2（6.13）、Qwen3.7 与 DeepSeek V4.1（6.17）五家旗舰挤在两周内发布的「会车窗口」。 更值得注意的是，这一代的竞争焦点已经从「刷榜分数」迁移到了架构效率与训练方法本身： 混合线性注意力、流形约束残差、FP4 量化感知训练、agentic RL、按推理预算分档——这些才是算法工程师该读的部分。

本文按「时间线 → 架构趋势 → 训练方法趋势 → 逐家拆解」组织。与上一篇 Granite 4.2 单点深挖不同，这篇是横向扫描，目标是回答一个问题：2026 年训一个 frontier 模型，技术栈到底长什么样？

架构趋势：2026 年的五个共识

① MoE 成为旗舰默认形态，竞争点是「稀疏度管理」

这一代新模型里，dense 架构几乎只剩 IBM Granite 4.2 这种明确面向部署效率的特例。旗舰全部转向 MoE， 且稀疏度一个比一个激进：DeepSeek V4-Pro 每 token 只激活 49B / 1.6T（3%），Kimi K3 为 104B / 2.8T（3.7%），Mistral Small 4 更是 6B / 119B（5%）。 于是真正的技术分水岭落在路由与负载均衡上：

  • DeepSeek V4 延续 auxiliary-loss-free 路线：用动态偏置（按 batch 负载加减 bias）替代辅助均衡损失，不与主损失抢梯度；V4 还把亲和度函数从 sigmoid 换成 √Softplus，并在前几层直接用 hash routing（按 token ID 确定性路由）——浅层的通用模式根本不需要学习路由。
  • Kimi K3 在 896 选 16 的极端稀疏度下提出 Quantile Balancing：直接由 router 分数的分位数推导专家分配，消掉了启发式更新规则和敏感的均衡超参。
  • 激活专家数普遍下调：DeepSeek 从 V3 的 8 个降到 V4 的 6 个，Qwen3.7 从 3.6 的 Top-8 降到 Top-6——单个专家更专精，每 token 需要的专家更少。

② 注意力机制大分化：线性/稀疏注意力为 1M 上下文回归

2026 年旗舰上下文集体迈过 1M token（Kimi K3、DeepSeek V4、Claude Opus 5、GPT-5.6 均为 1M 级），靠的不是硬堆全注意力，而是各家不同的「亚二次方」方案：

方案代表要点
混合线性注意力Kimi K3（KDA）93 层中 69 层用 Kimi Delta Attention（线性注意力变体），仅 24 层保留 Gated MLA 全注意力；官方称百万 token 解码快 6.3×。代价是 prefix caching 失效，Moonshot 给 vLLM 贡献了专用实现

③ 「深度方向」成为新的创新轴：mHC 与 AttnRes

过去三年架构创新集中在「宽度」（MoE 专家）和「序列」（注意力），2026 年两家不约而同动了残差流这个最保守的部件：

  • DeepSeek V4 的 mHC（Manifold-constrained Hyper-Connections）：把 Hyper-Connections 的多流残差约束在流形上，解决 HC 放大梯度不稳的问题——官方口径是 2.4 倍参数下训练吞吐反升。
  • Kimi K3 的 AttnRes（Attention Residuals）：跨深度选择性检索历史层表示，而不是均匀累加；官方称约 25% 训练效率提升、额外开销不到 2%。K3 还配了 Per-Head Muon（按注意力头独立跑 Muon 优化器）和 SiTU 激活函数。

④ 量化感知训练（QAT）下沉到 SFT 阶段

FP8 训练已是 2025 年的旧闻；2026 年的标志是 FP4 进入主训练流：Kimi K3 从 SFT 起就做量化感知训练， 专家权重 MXFP4、激活 MXFP8（非专家组件保持高精度）；DeepSeek V4 的路由专家权重直接以 FP4 存储； Granite 4.2 发布即提供 NVFP4 / MXFP4 校准版。低精度不再是部署时的「事后压缩」，而是训练配方的一部分。

⑤ 闭源模型进入「架构黑箱」时代

OpenAI 对 GPT-5.6 的披露是这一代闭源策略的极端样本：无参数量、无 dense/MoE 说明、无注意力方案、无训练数据规模、无算力数字， 唯一具体的技术披露在安全侧（见下节）。Anthropic 与 Google 同样只发布 system card / model card。 对工程师的实操含义：闭源模型的一切性质（显存、长上下文衰减、知识截止）只能对 API 实测，不能从 config 推断—— 「架构信息」本身已经变成开源阵营的差异化竞争力。

训练方法趋势：后训练的四个转向

① RL 的主战场从「可验证奖励」转向「真实环境 agentic RL」

RLVR（数学判分 / 单测判分）在 2026 年已是基础设施，新前沿是把模型扔进真实环境： IBM Granite 4.2 在 OpenHands 真实仓库、真实终端（64 轮交互）、真实搜索里做分阶段 RL（详见上篇）； Grok 4.6 官方明确表示提升来自「更长的补充训练 + 重新生成的微调数据 + agentic 环境中的 RL」； GLM-5.3 的 Terminal-Bench 从 4.6 跳到 28.3 被官方归因于同源基座上的后训练 Scaling。 共同模式：基座不变，能力增量全部来自后训练——「同基座刷后训练」成为 6–8 周快节奏发布的技术基础。

② 推理预算分档成为标配产品能力

Claude Opus 5 提供 low → max 五档 effort（且在 xhigh/max 档禁止关闭 thinking）；Grok 4.6 新增 xhigh 档； GLM-5.3 始终开思考、分 low/high/max 三档；GPT-5.6 Sol 有 max effort 与可调子智能体的 ultra 模式； Granite 4.2 在权重内做三档切换。训练侧的含义值得注意：档位不是推理时截断出来的， 而是后训练里显式训进去的（Granite 甚至专门用一轮带长度惩罚的 RLHF 来压冗余思维链）。 「按 query 复杂度分配推理预算」已经从技巧变成模型能力。

③ 数据路线分裂：蒸馏派 vs 反蒸馏派

  • 蒸馏派：Google 用 k-sparse 分布蒸馏（只保留教师 top-k token 概率）训练 Flash 小模型；xAI 的 Grok 4.5/4.6 用 Cursor 的真实开发者工作流数据做训练协作——「真实环境轨迹数据」本身成为可交易的资产。
  • 反蒸馏派：字节 Seed 公开表态「一款模型可以通过蒸馏进入前沿，但一家实验室没法通过蒸馏成为前沿实验室」；图像生成侧的 Z-Image 也明确拒绝用专有模型输出做训练（理由是学生上限被教师锁死）。
  • 合成数据依旧主流：Granite 4.2 预训练里约 1T token 是 CodeAlchemy 管线生成的合成代码；DeepSeek 系继续用 GRPO 自博弈生成推理数据。

④ 训练算力与安全的「双工业化」

  • 国产算力跑通旗舰全流程：DeepSeek V4（1.6T）据报道全程在昇腾 950PR 上训练；GLM-5.1（754B）实现旗舰级「零 NVIDIA」；美团 LongCat-2.0 用 5 万余张国产芯片一个月完成预训练（均为媒体/WAIC 报道口径，未经厂商技术报告逐一证实）。
  • 安全训练量化披露：OpenAI 披露为 GPT-5.6 投入 70 万+ A100 等效 GPU 小时做自动化红队（优化搜索 + RL + 测试时搜索找通用越狱）；METR 的部署前评估特别指出 OpenAI 刻意不对思维链施压训练，保留 CoT 作为可监控表面。Anthropic 则给 Mythos 5 单设了 Opus 之上的「Capybara」能力分级并限制访问。
  • 反面教材：OpenAI 4 月的事故复盘《Where the Goblins Came From》值得每个做 RLHF 的人读——GPT-5.5 训练中一个失准的奖励模型系统性地偏好提及「哥布林」的回复（相关提及率相对 GPT-5.2 基线暴涨 3,881%），应急修复竟是系统提示词里重复四遍「禁止谈论哥布林」。奖励模型的微小错位会被 RL 放大成行为灾难，这是 2026 年最生动的一课。

7 月 16 日发布、7 月 27 日开放权重（修改版 MIT）。这是目前披露最完整的超大开源模型，技术报告给出全套配置：

OpenAI GPT-5.6：黑箱化与安全工业化

6 月 27 日向约 20 家受信伙伴限量预览（应美国政府要求暂缓大范围开放），7 月 9 日起全面铺开。 首次以三档家族发布：Sol（$5/$30）、Terra（$2.50/$15）、Luna（$1/$6），统一 1.05M 上下文、128K 最大输出。 架构与训练配方完全未披露；值得记录的三条训练侧信息：① 70 万+ A100 等效小时的自动化红队； ② METR 确认其「不针对思维链训练」的策略；③ 5.5 的哥布林事故后，5.6 被广泛认为是首条重建奖励审计管线的模型（此点为分析推测）。 8 月 13 日又预览了 Ultrafast 模式（同权重最高 14× 速度）。

Anthropic：Fable / Mythos / Opus / Sonnet 四层梯队

Anthropic 2026 年的产品线出现了能力分级制度：Fable 5 是最高能力模型（受 EO 14409 出口管制， 6 月曾离线约三周）；Mythos 5 是网安特化 gated 模型——官方红队报告明确说它的漏洞挖掘能力 「从通用代码与推理训练中涌现」，做法是 Opus 4.8 基座 + 网安后训练，这是「通用能力溢出 → 专用 gated 发布」的第一个案例； Opus 5（7.24）定位「Fable 5 半价档」，1M 上下文、五档 effort、默认开思考，$5/$25 与 4.8 同价。 架构全部未披露；训练侧可参考的是其对齐叙事：Opus 5 号称在自动化行为审计中欺骗行为最低、宪法遵循度最高（自报）。

Google Gemini 3.x：稀疏 MoE + Deep Think + 蒸馏工厂

Gemini 3 系延续 1.5 以来的稀疏 MoE 路线，主打原生多模态与 Deep Think 推理模式；3.1 Pro（2.19）、3.2（6.13）依次迭代。 训练侧两个已知点：全程 TPU；Flash 小模型用 k-sparse 分布蒸馏（教师只传 top-k token 概率，省存储省吞吐）。 其余未披露。Gemini 的代表性不在架构新颖，而在「多模态 token 与文本统一预训练」这条只有 Google 坚持了四年的路线。

阿里 Qwen3.5 → 3.8：全尺寸矩阵与「全域思考」

  • Qwen3.5（2.16）：397B-A17B（激活仅 4.3%），0.8B–397B 全尺寸覆盖，混合推理模式（思考/非思考无缝切换），201 种语言；
  • Qwen3.6（3–4 月）：dense + 稀疏 MoE 双线，混合线性注意力，原生 256K + YaRN 至 1M；
  • Qwen3.7（5.20 云峰会）：Max-Preview 约 1.2T MoE 激活 45B，Top-6 路由（较 3.6 推理成本降 28%，自报）；核心创新是全域思考（All-field Thinking）——文本+图像+代码统一推理链；SWE-bench Verified 自报 72.3%；
  • Qwen3.8-Max：第三方报道总参数跳至 2.4T，细节未证实。

xAI Grok 4.5 / 4.6：用「数据 + 后训练时长」代替架构创新

Grok 4.5（7.8）基于 V9 基座：1.5T MoE，训练数据包含与 Cursor 合作的真实开发者工作流；500K 上下文，$2/$6。 Grok 4.6（8.12）不换基座，官方归因于更长的补充训练、重新生成的微调数据与 agentic 环境 RL，新增 xhigh 推理档。 背后是 Colossus 2（约 55 万张 GB200/GB300，千兆瓦级）同时训练 7 个模型——xAI 的路线是纯粹的「算力 + 数据」 scaling 信徒， 架构细节零披露。Grok 4.20 的 4-agent 多智能体模式（协调/研究/逻辑/唱反调四个角色并行互验）是推理时架构的有趣分支。

实践建议

  • 做后训练选型，先读开源技术报告再谈闭源 API：2026 年可读性最高的三份配方是 DeepSeek V4（auxiliary-loss-free 均衡 + mHC + Muon）、Kimi K3（Quantile Balancing + Per-Head Muon + QAT）、Granite 4.2（分阶段 agentic RL + 异步 GRPO）。闭源三家能给你的只有行为，开源三家能给你机制。
  • 「同基座刷后训练」是中小团队可复用的节奏：Grok 4.6、GLM-5.3 都证明基座不动、只加长后训练也能换来 benchmark 两位数涨幅。如果你有一个够用的基座，下一个季度的算力预算投给 agentic RL 环境与数据再生，性价比大概率高于重训基座——但前提是你的基座已越过「rollout 成功率非零」的门槛（参见上篇对 3B 不做环境 RL 的分析）。
  • 评估长上下文模型时区分「窗口大小」与「缓存经济性」：KDA/CSA 这类亚二次方注意力的代价是 prefix caching 语义改变（vLLM 为 K3 单独解耦了状态块与前缀粒度）。接入前在你的真实 prompt 分布上测缓存命中率，别看宣传窗口。
  • 奖励模型要有「哥布林审计」：GPT-5.5 事故的通用教训——上线前对 RM 输出做分布审计（哪些表面特征被系统性偏爱），比上线后用系统提示词打补丁便宜得多。GRPO 系方法同样不免疫：组内 baseline 消不掉「组间共享的偏置」。
  • 推理预算档位纳入路由层设计：五档 effort（Opus 5）、三档思考（GLM-5.3 / Granite 4.2）、xhigh（Grok 4.6）意味着「小模型分流」组件可以被「同模型降档」替代。垂类 Agent 的路由表建议从「选模型」改写为「选模型 × 选档位」的二维表。
  • 对自报数字保持分层信任：本文大部分分数为厂商自报；DeepSeek/Kimi 有权重可自测，闭源模型只能等第三方复测。Llama 5 的「5M 上下文 / Recursive Self-Improvement」等说法目前仅见于单一来源，引用前务必回到 Meta 原始材料。

思考题

  1. DeepSeek V4 在前几层用 hash routing（按 token ID 确定性路由）替代学习路由。为什么这个替换在浅层是安全的，在深层却不行？
    参考答案 浅层学到的多是与语义弱相关的通用模式（词法、句法、局部搭配），这类知识按 token 身份组织即可——同一个 token 在任何上下文里需要的「初级加工」高度稳定，确定性路由不会损失表达力，还省掉了浅层路由器的训练信号竞争。深层承载的是上下文相关的语义组合，同一个 token 在不同语境需要路由到不同专家（如「苹果」在食谱 vs 财报中），确定性路由无法表达这种条件依赖。这与「浅层特征通用、深层特征 task-specific」的可解释性观察一致；工程上还顺带获得一个好处：浅层路由决策无状态、可静态分析，利于专家并行的静态编排。
  2. Kimi K3 用 69 层线性注意力（KDA）+ 24 层全注意力（Gated MLA）的混合配比。为什么不是全 KDA？周期性保留全注意力层在解决什么问题？
    参考答案 线性注意力把历史压缩成固定维度的循环状态，天然有损：精确检索「很久以前某个具体 token」的能力（associative recall）会随距离衰减，而全注意力的 KV 是无损的。全 KDA 模型在 1M 上下文的「大海捞针」类任务上会出现系统性掉点。周期性插入全注意力层等于在深度方向上设置若干「精确检索检查点」，让循环状态里已经模糊的信息有机会从原始 KV 重新读出。这和 DeepSeek CSA「先压缩再稀疏选 top-k」是同一件事的两种实现：都承认纯压缩/线性方案保不住精确检索，区别在于 K3 在深度方向补救，DeepSeek 在序列方向补救。
  3. Grok 4.6 与 GLM-5.3 都是「不换基座、只加强后训练」的发布。这种做法的能力天花板由什么决定？什么信号提示你该重训基座了？
    参考答案 天花板由基座的「可引导能力」决定：RL 只能放大基座中已有非零概率的行为（rollout 全败则 GRPO advantage 全零），SFT 蒸馏同理（学生上限被教师锁死，且受基座表示容量约束）。具体的预警信号：① 环境 RL 的首轮成功率低到组内无差异，加数据只能学到格式学不到策略；② 后训练增益逐版递减（GLM-5.2→5.3 的边际若显著小于 5.1→5.2，说明基座潜力快吃光了）；③ 错误模式从「不会解题」退化为「知识不存在」（后训练补不了预训练没见过的事实）。出现③基本就是重训基座的信号。字节 Seed 2.0 训练稳定性事故、三个月打补丁也提示另一个方向：基座质量本身就是后训练投资回报率的乘数。
  4. 为什么闭源实验室（OpenAI/Anthropic/Google）在 2026 年集体停止披露架构，而开源阵营（DeepSeek/Moonshot/智谱）反而披露得越来越细？这对双方各是什么策略？
    参考答案 闭源侧：当能力差异主要来自训练配方而非架构论文时，配方就是核心商业秘密；不披露还能规避「被对手针对性蒸馏/复制」与监管审视，沉默本身是防御。披露的义务被转移到 system card（安全面）——因为企业客户与政府的采购门槛在安全合规，不在架构新颖性。开源侧：权重本来就要放出来，架构藏不住；把训练配方讲透反而能换来三样东西——社区 kernel/框架适配（Moonshot 给 vLLM 贡献 KDA 实现，本质是发动社区帮自己补推理栈）、学术界引用与人才吸引力、以及「透明度」作为对闭源阵营的差异化营销。同一个动作（不披露 vs 披露），对卖 API 的是护城河，对卖权重+生态的是获客漏斗。
  5. Mistral Small 4 用一个 reasoning_effort 参数把推理、视觉、编码三个原独立产品线合并成单模型。这种「统一可配置模型」对推理基础设施提出了什么新要求？
    参考答案 ① 调度器必须把 effort 档位当一等公民：不同档位的 token 吞吐差可达数倍，容量规划、限流和计价都要按档分桶，否则高档请求会把低档的延迟拖垮；② KV cache 与 batching 策略要兼容「同模型多行为模式」——思考档的长输出让 decode 阶段占比剧增，continuous batching 的混合配比不再是稳态；③ 可观测性要按档位切片：同一模型在低档的幻觉率与高档可能完全不同，统一监控会掩盖回归；④ 对客户端，「模型版本钉死」要扩展为「模型 × 默认档位」钉死，因为服务端改默认档位等价于一次静默的模型升级。
