学习笔记｜GSPO：序列级重要性采样如何稳住 MoE 上的 RL

2026-08-31 · 收藏夹：算法 / RL · 学习笔记
主来源： Qwen · GSPO: Towards Scalable Reinforcement Learning for Language Models、 arXiv:2507.18071（Zheng et al.）； 对照 PPO、 GRPO、 10 篇导读、 Miles · R3。 公式用 pre 书写；实验现象以官方博客为准，不引用二手曲线数值。

背景与动机

PPO 把 trust region 写成 clipped surrogate； GRPO 删掉 critic，用同题一组相对 reward 当 advantage，但 importance ratio 仍停在 token 级。 Qwen 团队观察到：长训里 GRPO 会出现严重不稳甚至不可逆 collapse，挡住「加算力就继续涨」的 RL scaling。 他们把根因指向一个单位错配——token-level 的 importance ratio 去乘 sequence-level 的 reward / advantage——高方差噪声被写进每一步更新。

Group Sequence Policy Optimization（GSPO） 的回答很硬：重要性比率按序列似然定义，clip / 优化也整段做；组内相对 advantage 保留。 官方报告三点收益：更高训练效率且能随算力持续涨点；训练过程显著更稳，并从根上缓解大型 MoE 的 RL 稳定难题；对精度误差更宽容，利于简化基建。 这些被用作最新 Qwen3（Instruct / Coder / Thinking）大规模 RL 的算法基石。

一句话：GSPO = 组内相对 advantage（GRPO 的 A） + 序列级 length-normalized importance ratio（把 PPO/GRPO 的 token 级 r 升一级） + 对整条 response 做 clip。

机制拆解

① 单位错配：为什么 token 级 ratio × 序列级 reward 会噪

Outcome reward 通常一条 response 一个标量；GRPO 的 Â_i 也是按整段算的。 但 GRPO / PPO-Clip 在 LLM 里的常见实现是：每个生成 token 一个 r_t = π_θ(y_t|…)/π_old(y_t|…)，再进 min(r_t Â, clip(r_t) Â)。 同一条 Â 被复制到成百上千个 token 上，而每个 r_t 又在自己的数值尺度上抖——优化信号在「整段好坏」与「局部概率比」之间错位，长训里表现为不稳定甚至 collapse（官方观察）。 

# GRPO 常见形态（示意）：序列级 A，token 级 r
for t in response:
  r_t = exp(logπ_θ(y_t|x,y_<t) - logπ_old(y_t|x,y_<t))
  loss += min(r_t * A_i, clip(r_t, 1-ε, 1+ε) * A_i)
# A_i 来自同题一组 reward 的相对值——与 r_t 的「单位」不一致

② 目标：序列级 s_i(θ) 与整段 clip

设 x 为 query，π_θold 采样一组响应 {y_i}，Â_i 为组内相对 advantage，π_θ 为待优化策略。GSPO 目标（官方形式）：

J_GSPO(θ) = E_{x~D, {y_i}~π_old} [
  (1/G) * sum_i  min(  s_i(θ) * A_hat_i ,
                       clip(s_i(θ), 1-ε, 1+ε) * A_hat_i )  ]
]

# 序列级 importance ratio（length-normalized）
s_i(θ) = ( π_θ(y_i|x) / π_old(y_i|x) ) ^ (1/|y_i|)
       = exp(  mean_t  log( π_θ(y_{i,t}|x,y_{i,<t})
                           / π_old(y_{i,t}|x,y_{i,<t}) )  )

# 即：先对 token log-ratio 取平均，再 exp —— 降方差，并统一 s 的数值范围

与 PPO 相同的是 clipped surrogate 外形；与 GRPO 相同的是组内 Â。 不同的是：clip 的对象是整条 response 的一个 s_i，不再是逐 token 的 r_t。 长度归一化（1/|y|）避免长回答的联合比乘性地炸数值，也让不同长度的 s 落在可比尺度上。

③ 对 GRPO：clip 掉更多 token，却更高效（官方观察）

官方对比冷启动自 Qwen3-30B-A3B-Base 的模型，在训练 reward 与 AIME'24 / LiveCodeBench / CodeForces 等曲线上，GSPO 相对 GRPO 训练效率更高，并能通过加训算力、更新 query 集、拉长生成持续涨点。 一个反直觉现象：GSPO 被 clip 掉的 token 比例比 GRPO 高约两个数量级，却仍更高效。 解读：GRPO 的 token 级目标大量「未触界」更新其实是噪声；GSPO 用更稀、但与序列奖励同构的信号，宁可 clip 得多，也不用局部 ratio 噪声去推参数。

GRPO（典型）GSPO
Advantage组内相对组内相对（同）

④ MoE：摆脱 Routing Replay 依赖

官方指出：GRPO 训 MoE 时，expert 激活的波动会阻止正常收敛；此前需要 Routing Replay——缓存 π_old 激活的 expert，在 π_θ 算 importance ratio 时回放。 该策略对收敛关键，但引入额外内存与通信，并可能限制 MoE 真实容量。

GSPO 的关键洞察：优化只看序列似然 π_θ(y|x)，对单个 token 似然 π_θ(y_t|…) 不敏感，因此不再依赖 Routing Replay。 与 Miles 的 R3 对照：

Miles R3GSPO
层面基建：回放 SGLang 路由算法：改 IS 粒度
仍用 token-level IS 时常必要—
改用序列级 IS 时可不再依赖设计目标之一

两篇不要读成互斥：平台可以同时提供 R3；算法选型到 GSPO 后，应明确是否关闭 Replay，以免双重开销。

⑤ 基建友好：推理引擎 logprob 与训推分离

序列似然比逐 token 似然更能容忍精度差。官方因此强调：GSPO 使直接用推理引擎返回的 likelihood 做优化成为可能，而不必强制训练引擎重算——这对 partial rollout、多轮 RL、训推分离框架尤其有利。 结合同日 TITO：序列级目标降低了对「每个 token 数值绝对一致」的苛刻度，但不自动允许 harness 乱改 token 串；TITO 仍决定「似然是对哪一条 y 算的」。

工程落地：Unsloth / ms-swift 等框架提供 importance_sampling_level=sequence（或同名配置）以切换到序列级 IS——接 GSPO 思想时优先确认该开关与 clip 作用在 s_i 而非 r_t。

实践建议

  • 先对齐「A 的粒度」与「r 的粒度」。 Outcome-only + 组内 Â → 优先序列级 s_i。逐步 PRM / 稠密过程奖励 → token 级 PPO/GRPO 仍可能更同构。混用是噪声源，不是「更精细」。
  • MoE 上把 Routing Replay 当成 GRPO 的补丁，不是永久架构。 若主损失已是 GSPO，做一次关 Replay 的对照；省下的内存/通信应记进实验收益，而不是默认双开。
  • ε 的数量级会随粒度变。 Token 级常用 ~0.2；序列级 length-normalized 的 s 更接近 1，官方博客强调的是形式而非让读者照搬某一 ε。调参时看 clip fraction 与序列 KL，而不是照抄 token 级默认。
  • 训推分离时优先验证「推理 logprob → 序列 s_i」路径。 能稳住再考虑训练引擎重算。重算解决的是数值合同；解决不了错误 y（那是 TITO 的活）。
  • 框架开关。 在 Unsloth / ms-swift 将 importance_sampling_level 设为 sequence，并确认 advantage 仍来自组内相对、clip 包裹的是序列比。
  • 与站内其它文的阅读顺序。 PPO 弄清 clip → GRPO 弄清组内 A → 本文升 r 的粒度 → Miles 看 R3 基建对照 → 10 篇导读 看 GSPO 在系列中的位置。

思考题

  1. 为什么说 GRPO 的「token 级 r × 序列级 A」是单位错配？若奖励改成逐步 PRM，这个批评还成立吗？
    参考答案 Outcome / 组内 Â 描述的是整段 y 相对同题其它样本好多少，却被用来缩放每个 token 的局部概率比，梯度把「整段信用」按局部 r_t 的噪声纹理分配。逐步 PRM 提供 token/span 级奖励时，token 级 r 与逐步 A 更同构，错配批评减弱；此时 GSPO 不是自动更优，而是要重新论证。算法选择应由奖励的时间粒度决定。
  2. s_i = exp(mean_t log ratio_t) 相对「先乘再开 |y| 次方」在实现上要注意什么？为何要长度归一化？
    参考答案 数学上 (Π ratio_t)^(1/|y|) = exp(mean log ratio_t)，应用 log-sum 避免 underflow。长度归一化把不同 |y| 的联合比拉回相近尺度，降低长回答方差、统一 clip 数值范围。实现上应对 mask 后的生成 token 做 mean，把 prompt / tool 旁路排除在外。
  3. 官方观察「GSPO clip 掉的 token 比例高两个数量级仍更高效」。这如何反驳「clip 越少学得越多」的直觉？
    参考答案 Clip 比例衡量的是「有多少位置的更新被封顶」，不是「有效学习信号的多少」。Token 级目标大量未触界更新可能是高方差噪声；序列级目标每次更新都对准整段 A，触界更频繁但方向更干净。效率来自信号质量，不是来自未 clip token 的计数。
  4. 为何 GSPO 能削弱对 Routing Replay 的需求，而 Miles 仍要为 token-level 栈提供 R3？一个训 MoE 的团队如何二选一或组合？
    参考答案 Routing Replay / R3 修复的是 token 级 IS 对路由 flip 的敏感；GSPO 不依赖逐 token 似然对齐，故可关 Replay。若团队损失仍是 GRPO token 级，应开 R3/Replay；若已切 GSPO，应关 Replay 做对照以省资源。组合仅在「主损失序列级、辅损失 token 级」时有意义，并需分别论证。
  5. 「直接用推理引擎 logprob 优化」怎样简化 partial rollout / 多轮 / 训推分离？它能否替代 TITO？
    参考答案 免去训练引擎对同一 y 再前向，降低显存与调度耦合，partial / 多轮里尤其值钱。它替代的是「重算合同」，不是「y 是哪一条」的合同：若 harness re-tokenize 改了 ID，推理 logprob 再准也是对错误串取数。GSPO 提高对精度差的容忍，TITO 保证串的身份——两者叠用，而不是互相取消。
