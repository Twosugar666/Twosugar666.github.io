学习笔记｜张量并行（Megatron-LM）：先列切再行切，一个 MLP 前向只要一次 all-reduce——f / g 共轭算子、按头切 attention、词表并行 + 融合交叉熵、复制 LayerNorm 与分 RNG；8.3B 在 512 张 V100 上 15.1 PFLOPs，以及「TP 不出节点」背后的 8bsh(t−1)/t 通信账

2026-10-28 · 收藏夹：算法 / Infra · 学习笔记
经典来源：Mohammad Shoeybi、Mostofa Patwary、Raul Puri、Patrick LeGresley、Jared Casper、Bryan Catanzaro（NVIDIA）· Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism（arXiv:1909.08053，2019；本文按 v4）； 通信与配置经验：Deepak Narayanan、Mohammad Shoeybi、Jared Casper 等（NVIDIA / Stanford / Microsoft Research）· Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM（arXiv:2104.04473，SC 2021）。 思想先驱：Mesh-TensorFlow（Shazeer et al., 2018）。论文数字按原文（V100 / DGX-2H 时代）；「box 小实验」一节为本文在 box 上用 numpy 实跑。 交叉： ZeRO、 激活重计算、 混合精度训练、 MQA / GQA / MLA、 MoE 路由。

背景与动机

这几天的系统算法课是一条线：混合精度把每个数变小，ZeRO 把参数 / 梯度 / 优化器状态切到 Nd 份，激活重计算用 FLOPs 换激活显存。但它们都有一个共同前提：每张卡在算一层时，仍然完整地执行这一层的矩阵乘（ZeRO-3 也是先把这层参数 all-gather 回来再算）。当单层的权重、激活或单卡算力本身成为瓶颈时，就必须把一个矩阵乘拆到多张卡上——这就是张量并行（tensor model parallelism，TP，Megatron 论文里叫 intra-layer model parallelism）。

Megatron-LM 的贡献不是发明「切矩阵」，Mesh-TensorFlow 已经有一套通用的分布式张量语言和编译器；它的价值在于发现 Transformer 层的结构允许一种极简切法：只在 PyTorch 里插入几个通信原语，每层前向两次 all-reduce、反向两次，不需要新编译器。2019 年用它训出 8.3B 的 GPT-2 式模型和 3.9B 的 BERT，今天 Megatron-Core、vLLM、SGLang 的 TP 实现仍是这套切法。昨天提到的 sequence parallel 也是在它之上补的一刀。

机制拆解

① MLP：为什么先列切 A、再行切 B

# MLP: Y = GeLU(X A),  Z = Dropout(Y B)      X: [bs, h]  A: [h, 4h]  B: [4h, h]

# 方案 1（不用）：A 按行切、X 按列切
X = [X1, X2],  A = [A1; A2]  ⇒  Y = GeLU(X1 A1 + X2 A2)
#   GeLU 非线性：GeLU(X1A1 + X2A2) ≠ GeLU(X1A1) + GeLU(X2A2) → GeLU 之前就要同步一次

# 方案 2（Megatron）：A 按列切
A = [A1, A2]  ⇒  [Y1, Y2] = [GeLU(X A1), GeLU(X A2)]     # 每卡独立做 GeLU，无需通信
B = [B1; B2]（按行切）⇒  Z = Y1 B1 + Y2 B2               # 每卡得到部分和
Z = all_reduce(Z_i)  → Dropout → 残差                     # 整个 MLP 前向只在这里通信一次

关键在于把列并行（column-parallel）接行并行（row-parallel）：第一个 GEMM 的输出按列分在各卡上，正好是第二个 GEMM 行切所需的输入，中间的非线性逐元素进行，不需要任何通信。两个 GEMM「融合」成一组，中间少了一个同步点。

② f 与 g：一对共轭的通信算子

class f(torch.autograd.Function):      # 放在 TP 区域入口
    def forward(ctx, x):  return x                     # 前向：恒等（X 在每卡都是完整副本）
    def backward(ctx, grad):  all_reduce(grad); return grad   # 反向：各卡对 X 的梯度是部分和

# g 放在 TP 区域出口，与 f 相反：前向 all_reduce，反向恒等
# 一个 Transformer 层 = attention 区域 (f … g) + MLP 区域 (f … g)
#   ⇒ 前向 2 次 all-reduce（两个 g），反向 2 次 all-reduce（两个 f）

为什么反向时 f 要 all-reduce：X 被复制到所有卡上，各卡只用自己那份 Ai 算了 ∂L/∂X 的一部分（∂L/∂X = Σi ∂L/∂Yi · AiT），求和才是完整梯度。g 前向把部分和加起来，反向时输出梯度对每个部分和都是同一个值，直接恒等传回即可。这对「前向恒等 ⇄ 反向求和」的对偶，和 ZeRO 里「all-gather 的反向是 reduce-scatter」是同一种 autograd 对偶关系。

③ Self-attention：按头切

子模块切法通信
Q / K / V 投影列并行：每卡拿 a/t 个头对应的列入口 f（前向无）
每个头的 softmax(QKT)V本地完成，头与头之间天然独立无
输出投影行并行：直接吃本卡头的输出出口 g：all-reduce

多头注意力本身就是「a 个独立的小注意力」，按头分卡是零额外成本的切法。约束也随之而来：头数 a 必须能被 t 整除。到了 GQA / MQA 时代，KV 头只有几个，当 t 大于 KV 头数时，常见实现只能让多张卡各存一份相同的 KV 头（复制），KV cache 的切分收益在这里打折——这是选择 TP 度时容易被忽略的一点。

④ 词表并行 + 融合交叉熵：把 b×s×v 的通信降到 b×s

# 输入嵌入 E: [h, v] 沿词表维切   E = [E1, E2]
#   每卡只查得到自己词表段内的 token（其余置 0）→ g（all-reduce）拼出完整嵌入

# 输出层（与输入嵌入共享权重）：[Y1, Y2] = [X E1, X E2]       # 每卡持有一段 logits
# 朴素：all_gather 得到完整 logits → 通信 b × s × v 个元素（v≈5 万，巨大）
# Megatron：把并行 GEMM 的输出直接与 cross-entropy 融合，只交换标量 → 通信降到 b × s 量级
# 常见实现：all_reduce(max) → all_reduce(Σexp) → all_reduce(目标 logit) 三次 b×s 的标量通信

配套的工程细节：GPT-2 原词表 50,257，为了让每卡的 logit GEMM 是 128 的倍数且支持到 8 路 TP，论文把词表 pad 到能被 128×8=1024 整除的 51,200。

⑤ 不切的部分：复制计算，分开 RNG

  • LayerNorm、dropout、残差：每卡持有 LayerNorm 参数的完整副本，拿到 g 之后的完整输出各自算一遍，而不是让一张卡算完再广播。所有值要么本地、要么复制，各 TP rank 只优化自己那份参数，不需要再同步参数。这部分重复的激活正是 激活重计算一文里 TP 公式 sbh(10 + 24/t + …) 中那个「10」；sequence parallel 后来沿序列维把它也切开。
  • 随机数：TP 区域外（残差前）的 dropout 必须在所有 TP rank 上一致——用同一个种子初始化；TP 区域内（attention 内部）的 dropout 作用在不同的头上，必须不同——为它维护一个按 TP rank 单独设种子的 RNG。两套 RNG 状态是 Megatron 的 tensor_parallel.random 的来源，也是激活重计算时必须一起保存 / 恢复的状态。

⑥ 与数据并行组合 + 论文实测

硬件：最多 32 台 DGX-2H（512 张 V100 32GB），服务器内 NVSwitch 300 GB/s，服务器间 8 块 InfiniBand 共 100 GB/s。TP 组放在同一台服务器内（例如 GPU 1–8），不同服务器上相同位置的 GPU 组成数据并行组做梯度 all-reduce。弱扩展实验固定每头 hidden 96，以单卡 1.2B（39 TFLOPS，单卡峰值的 30%）为基线：

摘要里的口径是「512 卡持续 15.1 PFLOPs、76% 扩展效率」，正文与 Fig. 5 给的是 74%，两个数都出自原文。附录还有两组值得记住的数：

  • 头数影响（8.3B、8 路 TP）：16 头（每头 192）82%、24 头（128）80%、32 头（96）77%——头越多，每卡的 GEMM 越小、softmax 元素越多，效率越低。
  • 强扩展（1.2B、batch 固定 8）：2/4/8 卡加速 1.64 / 2.34 / 2.98×。即效率 82% / 58% / 37%（本文换算）：模型不够大时，每卡计算量下降、通信和访存开销占主导，TP 收益迅速递减。

训练配方（GPT-2）：混合精度 + 动态 loss scaling，权重 N(0, 0.02) 初始化、残差前的层再乘 1/√(2N)（N 为层数），Adam + weight decay 0.01，全局梯度裁剪 1.0，dropout 0.1，每层做激活 checkpoint；序列 1024、batch 512、300k 步，lr 1.5e-4 warmup 3k 步后单周期余弦衰减到 1e-5。结果：8.3B 模型 WikiText103 困惑度 10.81（此前 SOTA 15.79），LAMBADA 准确率 66.51%（此前 63.24%）；512 卡上一个 epoch（68,507 步）约 2.10 天。BERT 侧的发现是：模型变大时必须调整 LayerNorm 与残差的位置，3.9B BERT 在 RACE 测试集上 90.9%。

⑦ 通信账：为什么 TP 不出节点

Narayanan et al.（PTD-P）给出了定量比较：pipeline 并行每个 micro-batch 在相邻两个 stage 之间只传一次 bsh 个元素（点对点）；TP 每层前向、反向各两次 all-reduce bsh 大小的张量，按 ring all-reduce 计，每层每卡每 micro-batch 的通信量是 8bsh(t−1)/t，且每层都要通信。 

# 本文按该公式算 GPT-3 175B 形状（b=1, s=2048, h=12288, BF16）
t =  2: TP 每层每 micro-batch ≈ 192 MiB      对比 PP 点对点 bsh ≈ 48 MiB（每个 stage 边界一次）
t =  4: ≈ 288 MiB
t =  8: ≈ 336 MiB
t = 16: ≈ 360 MiB      # (t−1)/t → 1，t 再大每卡通信量也不降，而每卡计算量按 1/t 缩小

所以论文的 Takeaway #1 是：用 g 卡服务器时，TP 度一般用到 g 为止，再往上用 pipeline 并行跨服务器扩展；Takeaway #2：TP×PP 的总模型并行度只要能让参数与中间状态放进显存即可，再往外用数据并行。PTD-P 的组合在 3072 张 A100 上以 502 PFLOP/s（每卡达到理论峰值的 52%）跑 1T 参数模型的训练迭代。

方案 1 的误差在 1 的量级，说明「先在非线性前切开」不是数值误差问题，而是数学上就错——必须在 GeLU 之前同步。方案 2 只差浮点求和顺序带来的 1e-15，对应真实训练中 TP 改变 all-reduce 求和顺序导致的「同配置不同 TP 度 loss 不逐位一致」；这类差异在 RL 里会叠加到训推 mismatch 上（参见 Rounding-Location Alignment）。

实践建议

  • TP 度 ≤ 单节点 GPU 数：8 卡 NVLink 节点上 TP ≤ 8；跨节点用 PP 或 FSDP / ZeRO-3。PCIe-only 的机器上 TP=2 也可能不划算。
  • 小模型别硬上 TP：强扩展数据说明 1.2B 规模 8 路 TP 效率只有 37%。显存放得下时，DP + ZeRO 往往更快；TP 的价值在「单层放不下或单卡算不完」。
  • 选 TP 度先查整除性：注意力头数、KV 头数（GQA）、FFN 维度、词表（pad 到 128·t 的倍数）都要能被 t 整除；KV 头数 < t 时会出现 KV 复制。
  • TP 一开就配 sequence parallel：通信量不变（all-reduce = reduce-scatter + all-gather），却能把 LayerNorm / dropout 的重复激活也切成 1/t，见 激活重计算一文的公式表。
  • RL 训推两端的 TP 度可以不同，但要会做权重重分片：rollout 引擎（vLLM / SGLang）常用较小 TP 提高并发，训练端用较大 TP；权重同步时需要按列 / 行切分规则重新分片（QKV 的列切顺序、gate/up 合并方式各框架不同），这是 weight sync 出错的高发区。
  • Debug 先关 TP：怀疑数值问题时，用 TP=1 跑同一 batch 对齐 loss；仅有 1e-6 级差异属于求和顺序，若差距大则检查 RNG（TP 区域内外的 dropout 种子）和 f/g 是否漏插。

思考题

1. 为什么 Megatron 的 MLP 用「列并行接行并行」，而不是两个都列并行？两个都列并行会多出什么通信？

两个都列并行时，第一个 GEMM 的输出 Y 按列分在各卡上，但第二个列并行 GEMM 需要每卡拿到完整的 Y 作为输入，所以中间要做一次 all-gather（Y 的大小是 bs×4h，比 bsh 还大 4 倍）；输出 Z 又是按列分布的，下一个 LayerNorm 需要完整的行，还得再 all-gather 一次。列接行的组合让中间结果「天然就是下一个 GEMM 需要的分片」，整个 MLP 只在末尾对 bs×h 的部分和做一次 all-reduce。

2. 写出 f 的反向为什么必须 all-reduce，并说明如果漏掉这个 all-reduce 会发生什么。

Yi = X Ai，所以 ∂L/∂X = Σi (∂L/∂Yi) AiT，每张卡只能算出自己那一项。漏掉 all-reduce 后，各卡继续往前传的是不完整且彼此不同的梯度：前面所有层（包括 LayerNorm 和嵌入）的梯度都错了，而且因为每张卡上「复制」的参数收到不同梯度，原本应该一致的副本会逐步发散——loss 可能不会马上爆炸，但会明显比 TP=1 差，是一类很隐蔽的 bug。

3. 按 8bsh(t−1)/t 估算：GPT-3 形状、t=8、每个 stage 12 层、每 step 32 个 micro-batch，单卡每步 TP 通信多少？与 NVLink（约数百 GB/s）、跨节点 IB（每卡约 25–50 GB/s）对比说明「TP 不出节点」。

每层每 micro-batch 约 336 MiB（BF16），12 层 × 32 个 micro-batch ≈ 129,000 MiB ≈ 126 GiB / 卡 / step。按 300 GB/s 量级的节点内带宽，约 0.4–0.5 秒，且大部分可以与计算重叠；若放到每卡 25–50 GB/s 的跨节点链路上，就是 3–5 秒，几乎无法被计算掩盖。相比之下 PP 每个 stage 边界每 micro-batch 只传约 48 MiB。这就是 PTD-P 把 TP 限制在节点内、跨节点用 PP 的原因（数字为本文按公式粗算，不含协议开销）。

4. 为什么 TP 区域外的 dropout 要用相同种子，区域内的要用不同种子？如果反过来会怎样？

区域外（g 之后、残差之前）的张量在所有 TP rank 上是同一个完整副本，各卡各自算 dropout；如果 mask 不同，各卡的「复制」激活就不再一致，后续层在不同卡上看到不同输入，等价于模型状态分裂。区域内（attention 内部）各卡处理的是不同的头，如果用相同种子，不同头会得到完全相同的 dropout 模式，失去随机性的独立性（相当于把 mask 在头之间相关化）。反过来设置：区域外不一致会导致副本发散，区域内相同会让正则效果变差。重计算时还必须恢复这两套 RNG 状态。

5. （开放题）在 2 台 8×H100 节点上做 32B dense 模型（GQA，8 个 KV 头）的 RL 训练，训练端你会怎么组合 TP / PP / ZeRO-3 / SP？rollout 端 vLLM 的 TP 又怎么定？

思路：训练端模型状态按 ZeRO 的 16Ψ 估算约 512 GB，16 卡均分每卡 32 GB，用 FSDP / ZeRO-3 跨 16 卡即可放下，再配 selective 重计算；若长回复（如 32K）使激活过大，在节点内加 TP=4 或 8 + SP 切激活，节点间保持 ZeRO-3 / DP，避免 TP 跨节点；PP 在 2 节点规模下收益有限，通常不需要。KV 头数 8，TP≤8 不会出现 KV 复制。rollout 端：32B BF16 权重约 64 GB，TP=2 即可放下权重并留出 KV cache 空间，多开实例提高吞吐；如需更长上下文或更低延迟再用 TP=4。训推 TP 度不同意味着权重同步要做重分片，务必用逐字节或 logprob 校验确认同步正确。
