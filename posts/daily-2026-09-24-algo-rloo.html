学习笔记｜RLOO：用 Leave-One-Out 基线把 REINFORCE 做成无 Critic 的在线对齐

2026-09-24 · 收藏夹：算法 / RL · 学习笔记
论文：Ahmadian / Cremer / Gallé / Fadaee / Kreutzer / Pietquin / Üstün / Hooker（Cohere / Cohere For AI）· Back to Basics: Revisiting REINFORCE Style Optimization for Learning from Human Feedback in LLMs · arXiv:2402.14740（ACL 2024）。 交叉： REINFORCE、 PPO、 GRPO、 GAE、 Actor-Critic、 DPO、 GRPO 实践笔记。

背景与动机

RLHF 第三阶段几乎默认挂 PPO：策略、参考、Critic、奖励最多四份模型同驻， 再叠加 clip / GAE / 归一化等旋钮。作者主张：Deep-RL 里催生 PPO 的「大方差、狂偏策略更新」在 预训 + SFT 暖启动的 LLM 对齐里并不典型——概率质量已挤在少数 token 上，环境更稳。

另一条常见建模习惯是把每个 token 当动作、前缀当状态；但偏好奖励几乎只打在完整生成上， 中间 token 只有 KL 项。更干净的视角是 bandit：整段 completion 是一次动作。 回到 REINFORCE，再用多条在线样本构造 Leave-One-Out 基线， 就是 RLOO——无 Critic、无 PPO clip 也能在作者设定里赢过 PPO / DPO / RAFT。

一句话：序列级 REINFORCE + 同 prompt 的 k 条样本互相当基线（排除自身）； 无 Critic、暖启动下不必依赖 PPO clip；教学上务必与 GRPO「组均值含自身」对照。

机制拆解

① 从 PPO 目标回到序列级 REINFORCE

# RLHF 常用 KL-shaped 奖励
R(x,y) = r_φ(x,y) − β · log( π_θ(y|x) / π_ref(y|x) )

# 序列级 REINFORCE（整段 y 当一个动作）
∇J ≈ E[ (R(x,y) − b) · ∇ log π_θ(y|x) ]

# 朴素基线：训练过程奖励滑动均值 b_MA
建模动作奖励落点代表
Token MDP 每个 token 末 token 拿 r，其余多半只有 KL PPO + GAE
Bandit / 序列 整段 generation 完整 y 一次拿 R REINFORCE / RLOO / RAFT

作者拆 PPO：在 RLHF 实验里提高 GAE 的 λ（更少偏置、更多方差）更好；λ=1 退回 Vanilla PG 时奖励曲线最强； clip 触发率常 <5%，关掉 clip 甚至略好——说明更新接近 on-policy，PPO 的「防大步」动机变弱。

② RLOO：Leave-One-Out 基线

# 对同一 prompt x 采 k 条 i.i.d. 样本 y_(1)..y_(k) ~ π_θ(·|x)

# 第 i 条的基线 = 其余 k−1 条奖励均值（排除自身）
b_i = (1/(k−1)) · Σ_{j≠i} R(y_(j), x)

# 多样本 MC 策略梯度
(1/k) · Σ_i  ( R(y_(i), x) − b_i ) · ∇ log π_θ(y_(i)|x)
性质含义
无参数 Critic基线由同批在线样本即时构成，少加载一份价值网络
无偏（相对均值基线家族）Leave-one-out 是经典方差削减技巧（Kool et al., 2019）
用满 k 条样本相对 RAFT「只训 top-1」信息更全
额外采样成本每个 prompt 要生成 k 条；换来更稳的优势估计

③ 关键对照：RLOO vs GRPO

RLOOGRPO
基线怎么算 Leave-one-out：均值排除当前样本 组均值：含组内所有样本（含自身）
优势形态 R_i − mean_{j≠i} R_j 常再标准化：(R_i − mean_all) / std_all
自包含效应 自身奖励不进自己的基线 → 优势不被「自己拉平」 自身进入均值 → 高分样本优势被略微压缩
谱系 Cohere 2024；REINFORCE 多样本 DeepSeekMath → R1；站内 GRPO 
# 教学例子：k=2，奖励 {1.0, 0.0}
# RLOO: 样本1 优势 = 1.0 − 0.0 = 1.0；样本2 = 0.0 − 1.0 = −1.0
# GRPO: 组均值 0.5 → 优势 +0.5 / −0.5（若再 /std 则尺度变化）

# k=4 时差异更细：RLOO 的 b_i 对每个 i 都不同；GRPO 共用一个组统计量

两者都属「用同 prompt 组内相对信号省 Critic」家族；实现与论文配方不同， 不要把 GRPO 的 group mean 直接叫成 RLOO。细节与工程笔记见 GRPO 实践笔记。

实践建议

  • 暖启动 + 在线奖励时先试序列级 PG。 已有强 SFT / RM 时，优先验证「无 Critic 的 RLOO/REINFORCE」是否够用，再决定是否上 PPO。
  • k 从 2～4 扫。 论文主结果在 k=2/4；更大 k 换方差但烧采样——对照站内 GRPO 组大小习惯。
  • 实现时显式 leave-one-out。 用 (sum − R_i)/(k−1)，不要偷懒写成含自身的 mean（那就更接近 GRPO 家族）。
  • 奖励用 KL-shaped R，不只裸 r。 β 过大时 RAFT 排序更脆；RLOO 仍建议监控 KL 与奖励双曲线。
  • 与离线偏好法分工。 无在线采样预算 → DPO/IPO；有 RM 且能 rollout → RLOO/GRPO；只要 top-1 监督 → RAFT（但信息利用率更低）。
  • 失败模式： RM 过优化、k=1 退化成无 LOO、把 token-level PPO 日志直接塞进序列级公式——三者都会让「看似 RLOO」训歪。

思考题

1. 为什么 LLM RLHF 里「整段当一个动作」说得通？

真值奖励几乎只标注完整回复；中间 token 没有独立偏好信号。环境转移对已生成前缀也是确定性拼接，可压成 prompt→completion 的 bandit。

2. Leave-one-out 相对「组均值含自身」差在哪一步代数？

LOO 的 b_i 不含 R_i；组均值把 R_i 算进基线，使高分样本优势变小、低分样本负优势的幅度也变小。k 较小时数值差更明显。

3. 作者为何说 PPO clip 在该设定里常多余？

实验中 clip 触发率很低，关掉 clip 不伤甚至略好，说明迭代间策略比变化温和；PPO 防「大偏策略步」的前提在暖启动 RLHF 中较弱。

4. RLOO 相对 RAFT 的样本效率优势从哪来？

同样 k 条在线样本，RAFT 只对 top-1 做 CE；RLOO 对每条都算加权策略梯度，差样本提供负向信号，好样本提供正向信号。

5. 何时仍该上 PPO / Actor-Critic 而不是 RLOO？

需要逐步稠密奖励、长程信用分配、或与现有 PPO 基础设施强绑定（含 value head、GAE 工具链）时。纯序列末奖励 + 强 SFT 初始化，RLOO/GRPO 往往更省。
