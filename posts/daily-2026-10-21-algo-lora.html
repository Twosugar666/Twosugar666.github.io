学习笔记｜LoRA：低秩适配为什么够用——ΔW = BA 的参数化、B=0 初始化与 α/r 缩放、可合并的零推理开销、r=1 就够的 intrinsic rank 证据，再到 QLoRA / rsLoRA / DoRA 与「学得少也忘得少」

2026-10-21 · 收藏夹：算法 / Infra · 学习笔记
经典来源：Edward J. Hu、Yelong Shen、Phillip Wallis、Zeyuan Allen-Zhu、Yuanzhi Li、Shean Wang、Lu Wang、Weizhu Chen（Microsoft）· LoRA: Low-Rank Adaptation of Large Language Models（arXiv:2106.09685，ICLR 2022）； Tim Dettmers、Artidoro Pagnoni、Ari Holtzman、Luke Zettlemoyer · QLoRA（arXiv:2305.14314）； Damjan Kalajdzievski · rsLoRA（arXiv:2312.03732）； Shih-Yang Liu 等（NVIDIA / HKUST）· DoRA（arXiv:2402.09353）； Dan Biderman 等（Columbia / Databricks）· LoRA Learns Less and Forgets Less（arXiv:2405.09673）。 公式与实验数字按原文；「box 小实验」一节为本文在 box 上用 numpy 实跑。 交叉： Adam、 Muon、 MQA → GQA → MLA、 知识蒸馏、 今日一线：Arctic-SWE。

背景与动机

全参数微调 GPT-3 175B 意味着每个下游任务都要存一份 175B 的副本，训练时还要为每个参数存 Adam 的两份状态（本站 Adam 一文讲过 m / v 的显存账）。2021 年前的参数高效方案各有硬伤：Adapter 在层间插小 MLP，增加串行深度，小 batch 在线推理时延迟明显上升；prefix / prompt tuning 占用序列长度，而且难优化、对可训练参数量非单调。

LoRA 的出发点来自 Aghajanyan et al. 2020 的观察：预训练模型的「intrinsic dimension」很低，随机投影到小子空间里也能学。LoRA 把假设落到权重更新上：适配时的 ΔW 本身就是低秩的。于是不去改 W，而是学一个低秩的 ΔW，且训练完可以把它加回 W，推理零额外开销。今天几乎所有开源微调、很多 RL 后训练实验（包括多 adapter 的 population 训练）都建在这个结构上。

机制拆解

① 参数化：冻结 W0，只学 B 和 A

# W0 ∈ R^{d×k} 冻结；B ∈ R^{d×r}，A ∈ R^{r×k}，r ≪ min(d, k)
h = W0·x + (α / r) · B·A·x

# 初始化：A ~ 高斯随机，B = 0  ⇒  训练开始时 ΔW = BA = 0，模型与预训练完全相同
# α：与 r 无关的常数。论文把 α 设成第一次尝试的 r，然后不再调
#    （用 Adam 时，在初始化适当缩放的前提下，调 α ≈ 调学习率）

# 推理前合并：W = W0 + (α/r)·B·A，之后和普通 dense 层一模一样
# 切任务：W − (α/r)·B·A + (α/r)·B'·A'

几个设计点值得逐一想清楚：

  • 为什么 B=0 而不是 A=0？两者都能让 ΔW=0，但梯度不同：∂L/∂B = (∂L/∂h)·(Ax)T，A 随机时这项非零，B 第一步就能动；若 A=0、B 随机，则 ∂L/∂B=0，只有 A 先动。两种都能训，但 B=0 是原文默认，也是之后 rsLoRA 等分析的出发点。不能两个都为 0——那样两者梯度都是 0，永远不动。
  • α/r 的意义：r 变大时 BA 的输出量级会变，除以 r 是希望换 r 时不必重新调学习率（原文引 Yang & Hu 2021）。这个选择后来被 rsLoRA 证明在大 r 时过度抑制，见 ⑥。
  • 泛化全参微调：对所有权重矩阵用 LoRA 且令 r 等于原矩阵的秩，就近似恢复全参微调的表达力；而 Adapter 增参数会收敛到一个 MLP、prefix 方法收敛到不能吃长输入的模型。

作者进一步比较 r=8 与 r=64 学到的 A 的右奇异向量子空间（基于 Grassmann 距离的归一化相似度）：top 方向高度重合，r=64 多出来的方向大多是噪声。原文脚注也提醒了反例：如果下游任务与预训练分布差得很远（例如换一种语言），小 r 不会够，r = dmodel 的全量更新当然更好。这一点三年后被 Biderman et al. 用更大规模的实验证实，见 ⑦。

④ ΔW 和 W 是什么关系：放大「已学到但没被强调」的方向

在 GPT-3 第 48 层，把 Wq 投影到 ΔWq（r=4）的 top-r 奇异方向上：‖UTWqVT‖F = 0.32，而 ‖ΔWq‖F = 6.91、‖Wq‖F = 61.95。三点结论：ΔW 与 W 的相关性强于随机矩阵；但 ΔW 放大的不是 W 的 top 奇异方向；放大倍数很大，约 6.91 / 0.32 ≈ 21.5。r=64 时这个因子只有约 2，说明多出的秩大多没被「用力」放大。直觉：预训练已经学到了任务需要的特征，只是没给它们足够权重，LoRA 做的是重新加权。

⑥ rsLoRA：α/r 在大 r 时把学习「压死」了

Kalajdzievski（arXiv:2312.03732）的论点：缩放因子 γr = α/r 让 r 越大的 adapter 学得越慢、效果越差，这也是实践中 LoRA 长期只用很小 r 的原因之一；他证明 adapter 应除以 √r（rank-stabilized LoRA），这样增大 r 能稳定地「用训练算力换效果」，推理成本不变。

box 小实验（本文实跑，numpy）：d = k = 1024，n = 512 个样本，B 从 0 出发，模拟 Adam 第一步（≈ sign 更新，lr = 1e-3），看输出增量 Δh 的 RMS 随 r 的变化：

rγ = α/r：rms(Δh)γ = α/√r：rms(Δh)

原因：Adam 让每个参数的步长约为 lr、与 γ 无关；Δh = γ·ΔB·Ax 对 r 个方向求和，近似随机符号叠加，量级 ∝ γ√r。于是 α/r 下 Δh ∝ 1/√r（r 每乘 4，增量约减半，与表中一致），α/√r 下大致恒定。这是一个只看第一步的玩具，不是 rsLoRA 的完整证明，但足以说明「换 r 必须重调 lr」在 α/r 下是常态。

同一实验里的另外两个数：

  • d = k = 4096 的方阵，LoRA 参数量 2dr：r=1 / 8 / 64 分别是 8,192 / 65,536 / 524,288，占原矩阵 0.049% / 0.39% / 3.1%。
  • 合并等价性：FP64 下 W0x + γBAx 与 (W0+γBA)x 的最大误差 5.2e-15；但若把合并后的权重存回 FP16，最大误差约 2.4e-3（激活均值约 0.80）。合并进低精度权重是有损的——这在 QLoRA 的 4-bit 基座上更明显，部署时通常要先反量化再合并、或不合并直接挂 adapter。

⑦ 之后的三条主线

工作改了什么论文自报要点
QLoRA（Dettmers et al. 2023）冻结的基座量化到 4-bit，梯度穿过量化基座流进 LoRA单张 48GB GPU 微调 65B，保持 16-bit 微调的任务表现；三件套：NF4（对正态分布权重信息论最优的 4-bit 类型）、double quantization（把量化常数再量化）、paged optimizers（应对显存尖峰）；Guanaco 在 Vicuna benchmark 上达到 ChatGPT 的 99.3%，单 GPU 24 小时
rsLoRA（2023）γr = α/√r大 r 不再学得慢，r 成为可以用训练算力换效果的旋钮
DoRA（Liu et al. 2024）把预训练权重分解成 magnitude 与 direction，用 LoRA 只更新 direction，magnitude 单独学动机来自对全参微调 vs LoRA 的权重分解分析；在 LLaMA、LLaVA、VL-BART 的多类任务上稳定超过 LoRA，可合并、无额外推理开销
LoRA Learns Less and Forgets Less（Biderman et al. 2024）在代码与数学上系统对比 LoRA 与全参（指令微调约 100K 对、持续预训练 20B token）标准低秩设置下 LoRA 明显不如全参；但更好地保住目标域之外的能力，抗遗忘强于 weight decay / dropout，生成更多样；全参学到的扰动秩是常见 LoRA 配置的 10–100 倍

最后一行和原文 ③ 的「r=1 就够」并不矛盾：GPT-3 上的 WikiSQL / MNLI 离预训练分布近，Biderman et al. 的代码 / 数学持续预训练要注入大量新知识，正好落在原文脚注说的「小 r 不够」的区域。

实践建议

  • 先决定任务离预训练分布多远。格式 / 风格 / 指令对齐类任务，小 r 足够；要注入大量新知识（新语言、新领域持续预训练），要么用大 r + rsLoRA，要么直接全参。
  • 铺广优于堆深。同预算下所有线性层（含 MLP）都挂 LoRA、用较小 r，通常比只挂 q/v 用大 r 更好。
  • 换 r 就重调 lr，或改用 α/√r 缩放；不要只改 r 然后比较结果。
  • LoRA 的 lr 通常比全参大一个量级左右（经验值，依模型与 α 而定，务必 sweep）；B=0 初始化意味着前几步 ΔW 很小，warmup 不宜过长。
  • 部署时想清楚合并与否。单任务高 QPS：合并进 BF16 权重；多租户多 adapter：不合并，用多 adapter serving；4-bit 基座上合并前先反量化。
  • RL / 后训练里用 LoRA 的一个隐性好处是「忘得少」——在意通用能力保持（以及 KL 约束本身较弱）时，LoRA 是一种结构性正则；但要接受它学得少。
  • 和蒸馏配合：知识蒸馏得到的小模型再按任务挂 LoRA，是在多任务部署下性价比很高的组合。

思考题

1. 如果把 A 和 B 都初始化为小随机数（而不是 B=0），会有什么问题？

训练第一步之前模型就已经偏离预训练权重：ΔW = γBA 是一个随机低秩扰动，会立刻改变输出分布，等于在一开始就注入噪声并损失部分预训练能力；在 α 较大或层数多时，这个扰动在残差流里累积，可能让初始 loss 明显升高。B=0 保证起点就是预训练模型，微调完全从零增量开始，这对「小数据、少步数」的微调尤其重要。另一方面不能两者都为 0，否则两边梯度都为 0。

2. 为什么说「用 Adam 时调 α 约等于调学习率」？用 SGD 还成立吗？

Adam 对每个参数做尺度归一化，步长约为 lr，与梯度的整体缩放无关。γ = α/r 对输出 Δh 的影响有两处：梯度 ∂L/∂B 里乘了一次 γ（被 Adam 归一化掉），前向 Δh = γΔB·Ax 又乘一次 γ（保留）。净效果是 Δh ∝ γ·lr，所以 α 和 lr 在一阶上可以互换（初始化缩放合适时）。SGD 不做归一化，两处 γ 都保留，Δh ∝ γ²·lr，此时 α 与 lr 不再等价，且大 r 下 α/r 的抑制更严重。

3. 预算固定时，「Wq,Wv 各 r=4」优于「只 Wq r=8」。从 intrinsic rank 的角度解释。

如果每个矩阵的有效更新秩都很低（r=1~4 就覆盖主要方向），那么对单个矩阵从 r=4 加到 r=8 的边际收益接近零（多出来的是噪声方向，③ 的子空间分析也这样显示）；而把这部分预算拿去适配另一个原本完全没动的矩阵，能覆盖一个全新的、有用的更新方向。也就是说，收益来自「覆盖更多矩阵的 top 方向」，而不是「把一个矩阵的长尾方向学出来」。

4. LoRA 在 RL 后训练中被广泛使用（如多 adapter population、低成本 rollout 引擎热切换）。从 Arctic-SWE 讨论的训推一致性角度看，LoRA 带来哪些新风险？

（1）合并与否导致数值路径不同：训练端是 W0x + γBAx 分开算，推理引擎如果把 adapter 合并进 BF16 权重，舍入不同，importance ratio ω 偏离 1，mismatch KL 上升；（2）推理引擎的多 adapter kernel（分块 / 不同精度）与训练框架实现不同，同样制造 ω 噪声；（3）权重推送变便宜（只推 A、B）会鼓励更频繁的刷新，若缓存不重算，陈旧缓存问题更频繁。缓解：训练与推理用同一种「不合并」的计算路径，监控 mismatch KL，对超大 ratio 的 token 做 mask。

5. （开放题）「LoRA 学得少也忘得少」与 KL 正则（KL 散度）都在限制模型偏离。两者限制的「距离」有什么本质区别？

KL 正则限制的是输出分布的距离，在被采样到的状态上起作用，对没覆盖的输入几乎没有约束；LoRA 限制的是参数更新的结构（秩 ≤ r、只在选定矩阵上），对所有输入同时生效——它无法表达高秩的改变，所以未覆盖输入上的行为也很难被大幅改写，这可能是它「忘得少」的来源。代价是即便目标需要高秩更新，LoRA 也学不到。两者可以组合：RL 里用 LoRA 做结构约束、用 KL 做分布约束；值得讨论的是在 Agent RL 中去掉 reference KL（如 Arctic-SWE）后，LoRA 能否部分替代它的稳定作用。
