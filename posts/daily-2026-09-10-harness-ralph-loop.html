学习笔记｜Ralph Loop：用 hook 拦截退出、清窗重注目标的长程 harness 续跑

2026-09-10 · 收藏夹：Harness / Agent · 学习笔记
素材：Vivek Trivedy · The Anatomy of an Agent Harness（LangChain Blog）· langchain.com/blog/…。 对照站内 Context Compaction、 Harness 运行时、 OpenHands V1、 mini-SWE-agent、 TITO。

背景与动机

LangChain 文把公式写死：Agent = Model + Harness。Harness = 一切非模型的东西——system prompt、tools/skills/MCP、filesystem / sandbox / browser、编排（subagent、handoff、routing）、以及确定性 hooks/middleware（compaction、continuation、lint）。 模型贡献智力；harness 把智力变成可工作的系统。站内 Harness 运行时 同一立场：运行时接管工具、上下文与环境。

长程自主执行仍卡在两类病：① early stopping——模型过早声称完成并退出；② 跨多窗口不连贯——工作跨过多个 context window 后，同会话硬塞历史会腐烂，清窗又丢进度。 Compaction（见 站内笔记）解决的是「同会话快爆窗时如何压缩续跑」；Ralph Loop 解决的是另一条轴：拦截退出 → 干净窗口 → 重注入原目标，进度靠外存（文件系统 / git）而不是靠塞满的对话历史。

一句话：Ralph Loop = hook 拦住「我做完了/要退出」→ 在干净 context里重注原目标 prompt → 强迫相对 completion goal 继续；上一轮产物落盘，新一轮读盘不读旧上下文。

机制拆解

① Harness 组件清单（从模型能力缺口反推）

模型做不到 / 不该独自做的Harness 补丁
跨交互持久状态Filesystem、AGENTS.md 式记忆注入、git 账本
执行代码 / 装依赖Bash + sandbox + 预装工具链
实时知识Web search / MCP
上下文腐烂Compaction、tool-output offload、Skills 渐进披露
长程早停与跨窗断裂Ralph Loop + plan 文件 + self-verification hooks

与 mini-SWE-agent（bash-only、线性 messages）和 OpenHands V1（Workspace 工厂）对照：前两者给执行面与状态容器；Ralph 是续跑控制面——不换工具集，改「何时允许停、停了如何再开」。

② Ralph Loop 逐步

# Ralph Loop（harness 模式，示意）
goal_prompt = 原始用户目标（固定文本）
while not done and within_budget:
  ctx = 空 / 干净 context window          # 不继承上一轮对话 token
  inject(goal_prompt + 如何读盘/plan 的提醒)
  run_agent_until_model_tries_to_exit()
  if hook_intercepts_exit_claim:
    # 不把「声称完成」当成真完成
    persist_artifacts_to_filesystem_and_git()
    continue   # 下一轮清窗，读盘续做
  else:
    # 仅当外部完成判定（测试绿 / 验收脚本）通过才放行
    break

# 关键不变量
#   对话历史不是跨轮真理；文件系统 / git 才是
#   每一轮相对的是 completion goal，不是「接着昨天的聊天语气」
  • Hook 拦截退出：模型输出「完成」或触发 stop 工具时，harness 可拒绝放行，改为开启新一轮。
  • 清窗重注：新窗口只带 goal + 必要的读盘/计划指令，避免把腐烂长历史原样续上。
  • 外存状态：代码、报告、plan 文件、测试日志落在 workspace；下一轮用 bash/读文件恢复态势。

③ 与 Compaction 对比

维Context CompactionRalph Loop
会话身份 同一会话内压缩续跑 常开启新的干净窗口迭代
历史处理 摘要 / 裁剪 / checkpoint 同窗历史 丢弃对话上下文，依赖外存
触发 接近上下文上限、腐烂风险 模型声称完成 / 请求退出，或主动续跑策略
风险 摘要丢细节、TITO 边界（见 TITO 文） 无限续跑烧钱；丢盘则进度真丢
可组合 单轮内仍可 compaction Ralph 外层迭代 + 内层 compaction

一句话分工：compaction = 同会话减肥；Ralph = 清窗 + 外存账本的迭代续跑。长程系统往往两层都要。

④ 配套：plan、自验证、git 账本

  • Plan 文件：harness 提示模型把目标拆步写入 workspace 中的 plan；每轮清窗后先读 plan，减少「忘记还剩什么」。
  • Self-verification hooks：退出前跑固定测试 / lint；失败则把错误回灌模型，不允许声称完成。这与 OpenHands / mini-SWE 的「观察—修复」环同构，只是钩在 harness 确定性层。
  • Filesystem + git：跨会话与多 agent 的共享账本；新 agent / 新窗口靠 git log / 工作树快速对齐「已做到哪」。

对 RL 训练侧（TITO）：Ralph 改变的是部署时轨迹长度与停止分布。若训推 harness 不一致（训练无 Ralph、线上有 Ralph），早停与上下文分布会偏移——训推合同要显式声明。

⑤ 实践边界：无限 Ralph 会烧钱

# 必须同时具备的闸门（工程清单）
budget.max_iterations / max_tokens / max_wallclock
completion_predicate = 测试绿 ∧ 验收脚本 ∧ （可选）人工门
stagnation_detect = 连续 k 轮 diff 为空 / 测试失败集不变 / plan 无进展
on_stagnation → 降级：换策略提示 / 请求人类 / 硬停并保留现场

Ralph 把「模型想停」从控制权里拿走；若不加预算与停滞检测，系统会在失败环里清窗重试到账单爆炸。Harness 的职责不只是「让它继续」，更是「知道何时不许继续」。

实践建议

  • 先定义完成谓词，再开 Ralph。 没有可机判的 done，拦截退出就变成无限循环。
  • 磁盘是真理，聊天是草稿。 关键产物与 plan 必须落盘；清窗前做一次「可恢复检查点」（至少 git commit 或工件清单）。
  • 与 compaction 分层启用。 单轮内防爆窗用 compaction；跨轮防早停用 Ralph。不要用无限塞历史代替外存。
  • 钩子要确定性。 退出拦截、测回灌、预算计数放 harness hooks，不交给模型「自觉」。
  • 对齐训推。 若线上 Ralph 显著拉长轨迹，评估与 RL 数据采集应用同一停止政策，或显式 domain randomization。
  • 观察停滞信号。 重复失败测试、空 diff、plan 步骤来回改——应触发熔断，而非再开一轮同温采样。
  • 成本看板。 按「每完成目标的 token / 迭代次数」报警；Ralph 是能力旋钮也是成本旋钮。

思考题

  1. 为什么「Agent = Model + Harness」比「Agent = 带工具的模型」更干净？
    参考答案 后者仍把脚手架当成模型附属；前者强制把 prompt、工具、沙箱、编排、hooks 全部划到系统设计面。能力缺陷可以落在模型或 harness 两侧分别治理，也方便做「同模型换 harness」消融。
  2. Ralph 清窗后为何还能续做，而不是从头瞎做？
    参考答案 因为进度被外置到文件系统与 git：代码、plan、测试结果仍在。新窗口重注目标后，模型通过读盘重建态势，不依赖上一窗的对话 token。没有外存，清窗就真是失忆。
  3. Compaction 与 Ralph 能否互相替代？
    参考答案 不能。Compaction 保留同会话身份并压缩历史；Ralph 常丢弃对话历史、用迭代 + 外存对抗早停与跨窗断裂。替代会导致：只用 compaction 仍可能早停；只用 Ralph 单轮仍可能爆窗。宜分层组合。
  4. Self-verification hook 失败回灌，解决的是 early stopping 的哪一层？
    参考答案 解决「声称完成但客观未完成」。模型主观 stop 被测试/验收否决后，错误信号回灌，迫使继续修。若无客观谓词，拦截退出只能靠启发式，易误杀或漏放。
  5. 无限 Ralph 的主要风险与最小闸门集是什么？
    参考答案 风险：token/费用爆炸、失败环空转、磁盘堆积无价值 diff。最小闸门：迭代/token/墙钟预算、可机判完成谓词、停滞检测（空 diff / 失败集不变）与熔断降级。缺任一闸门都不应默认开启自动续跑。
