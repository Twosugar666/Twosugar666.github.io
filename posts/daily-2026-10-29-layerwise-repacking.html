一线追踪｜Layerwise Repacking：混合注意力变长训练里，全注意力层要 SP16/32、稀疏层 SP8 就够——把「换布局」塞进全注意力层本来就有的两次 Ulysses all-to-all，被拆开的宽组里稀疏层不再跨节点；22 个宽组 step 端到端 −7.61%、MFU 56.47%→61.30%

2026-10-29 · 收藏夹：Infra · 一线追踪
来源：Jiahao Zhang、Junwei Feng、Dongliang Huang、Xiaoling Zhou、Yiqiao Liao、Chengru Song（KlingAI Research / 快手 Kling Infra Team，北京；通讯作者 Chengru Song；一作为实习期间工作）· Layerwise Repacking: Variable-Length Hybrid-Attention Training without an Extra Redistribution Pass（arXiv:2610.35989，cs.LG，v1 页眉日期 2026-10-26，出现在 arXiv 10-28 的 /new 批次）。 实现基于 TorchTitan。数字均为论文自报：一个 1F3S 混合注意力模型、一个 64 卡（8 节点 × 8 卡）集群、前 200 步中触发宽组的 22 步；「box 小验证」一节为本文用 numpy 实跑 / 对论文表格实算。 交叉： 今日算法：序列并行（Ulysses / Ring）、 张量并行、 激活重计算、 远端 KV tier + PCP、 2026 新模型架构全景。

背景与动机

2026 年的新基座几乎都是混合注意力：少量全注意力（full attention）层负责全局信息流，大量便宜层（滑窗、稀疏、线性注意力、Mamba）负责其余。Gemma 2 是局部 / 全局交替，MiniMax-01 是 7 层线性 + 1 层 softmax，Kimi Linear 是 3 层线性 + 1 层全注意力；本文研究的是 1F3S：每个全注意力层后跟 3 个稀疏注意力层（S 层里注意力只看有界数量的 key，成本由投影和 MoE 主导，近似随长度线性）。架构背景可回看 新模型全景。

这类模型做变长训练（一个 step 里样本长度差很多；论文 22 个宽组 step 中最长 / 最短样本之比为 9.8–175×，中位 23×）时，序列并行（SP）的「宽度」需求在层与层之间是冲突的：

  • 全注意力层成本随长度平方增长，最长的那几个样本必须摊到 SP16 / SP32 的宽组上，否则单个样本在 8 卡上的成本就会远超组内平均负载；
  • 稀疏层的工作近似线性，同一批样本在节点内 SP8 就能负载均衡；
  • 但现有变长调度器（FlexSP、ByteScale、Megatron-Core Dynamic Context Parallelism 等）都是「一个样本 / 一个 packed micro-batch 选一个 SP 组，所有层共用」。于是为全注意力层准备的宽组被原样带进后面 3 个稀疏层，稀疏层的 Ulysses all-to-all 也被迫跨节点。

跨节点有多贵？论文用同一计时器测得：节点内 SP8 的有效 Ulysses 速率 275.6 GiB/s，跨节点 SP16/32 只有 39.5 GiB/s，差 7.0×（这是含等待的有效速率，不是链路规格）。基线下宽组 rank 每步暴露的 all-to-all 时间 7.97 s，占 37.22 s 步长的 21.4%；SP8 rank 只有 1.60 s（4.3%）。宽 rank 每步发 278 GiB，其中约 203 GiB 属于稀疏层——这部分本来不必出节点。

直觉解法是「稀疏层换成 SP8 子组」，但换组意味着换了哪个 rank 持有哪个样本的哪些 token，每次 F↔S 边界都要做一次激活重分布。论文估算，单独做一遍重分布要 0.9–1.9 s / step，会吃掉 30–60% 的收益。Layerwise Repacking 的核心观察是：全注意力层本来就有两次必须的 Ulysses all-to-all，而且它们本来就把每个 token 在整个宽组里搬一遍——只要把 split size 改成可变、再加一个确定性置换，布局转换就能「搭车」完成，不多传一个字节。Ulysses 本身的原理见今天的算法课 序列并行。

机制拆解

① 两种布局：宽 parent 给全注意力，节点内 child 给稀疏主干

概念定义谁在用
parent（布局 F）基线 solver（round 1A）给出的 SP 组：固定的 rank 区间 + 有序样本列表；SP16 跨 2 节点、SP32 跨 4 节点只有全注意力的 core attention（两次 Ulysses 交换之间）
child（布局 S）把每个 SP16/32 parent 的样本重新装进若干个 SP ∈ {1, 2, 4, 8} 的子组，每个子组在一个 8 卡节点内，rank 区间铺满 parent所有稀疏层 + 全注意力层的投影 / MoE；hidden state、残差、mask、位置元数据全程驻留在这里，作者叫它 sparse trunk
正确性契约parent 内所有 shard 不重不漏地划分 parent 的真实 token；逆置换能还原原始 packing 顺序；padding 只在 child 内部保证 attention / MoE kernel 看到的都是普通 packed 输入

SP8 parent 不拆；SP16 parent 至少要 2 个样本、SP32 至少 4 个样本才能拆成非空的节点内 child（最小样本数 m = R/8）。不够时有一个 repair 步骤从别的 parent 借小样本，再不行就整体不拆；评测的 22 步里 repair 一个样本都没动过。

② 通信融合：两次 Ulysses 交换顺便完成 S→F 与 F→S

# 一个被拆开的 parent（R 个 rank，H 个头，每 rank 头数 H/R），在每个全注意力层：
# rank i 在 S 布局下持有 parent 打包顺序里的一组 token 位置 own[i]（长度随 child 的 SP 不同而不同）

S→F（原 Q/K/V Ulysses 站点）:
    for j in 0..R-1:  send(to=j, X[own[i]][:, 头切片 j])          # 可变 split：|own[i]| 个 token 发给每个 peer
    recv 按源 rank 拼接（rank-major）→ 用置换 perm 排回 parent 升序 → 得到「整条 parent 流 × H/R 个头」
full attention（varlen mask，每个样本只看自己）
F→S（原输出 Ulysses 站点）:
    逆置换 → 把 own[i] 那些 token 发回 rank i → rank i 拼回全部头

# 均匀 shard 时 own[i] 就是第 i 个连续块、perm 是恒等 → 退化成标准 Ulysses
# 每个张量仍只穿过每个必要交换一次；变的只有 split 大小和本地置换

这样做必须同时满足四条（论文 §3.4）：前向 / 反向布局变换严格互逆；每个 rank 独立算出完全相同的置换表（不能为元数据再发一次 collective，所以从共享 plan 确定性构造）；padding 和 packed length 留在 child 内部；反向与重计算图要以一致的 split 元数据逆向走同样的不均匀交换，loss 路径最后用一次不均匀 all-gather 替代原来的均匀 all-gather 还原全局顺序。

结构性账：前向图里跨节点的 Ulysses 调用点，基线是 2(NF + NS)，repack 后是 2NF。1F3S 有 NS = 3NF，所以8NF → 2NF，少 75%（1F1S 是 50%，MiniMax 式 1F7S 是 87.5%）。剩下那 25% 是全注意力宽组本身必需的跨节点流量，repacking 不碰它。

③ parent 成员决定 child 能平衡到什么程度：两分量代价的辅助 solver

child 规划只能在一个 parent 内部挪样本，所以 parent 的稀疏层最优 makespan 有硬下界： 

M*_b ≥ max( Σ_{i∈parent b} s_i / R_b ,  max_{i∈parent b} s_i / 8 )
          └─ 理想平均（受成员影响）─┘  └─ child 上限 SP8：最重的样本最多摊到 8 卡 ─┘

基线 solver 用一个对全注意力 profile 拟合的标量权重分配样本到 parent，这在同构 Transformer 堆叠里没问题；但 1F3S + repacking 下每个样本是两分量成本（平方的 full 部分 + 线性的 sparse 部分），而且两类层在不同的组上跑：full 层在 parent 上平衡，sparse 层由最慢的 child 决定。即使把两部分加成一个总和也平衡不了。辅助 solver（round 1B）保持 parent 的 rank 拓扑不变，只重分配成员：

阶段固定什么输出
Round 1A（基线）DP world、允许的 SP 档parent 拓扑 + 初始成员
Round 1B（改进，可选）1A 的全部拓扑全局 parent 成员：Compute-LPT / Memory-LPT / Anchor-Fill 三条路线生成候选，用聚合关键路径预测器打分取最小（容差内按固定顺序破平）；重样本先各占一个宽 parent；单步求解 ≤ 4 ms
Repairparent 拓扑满足 m = R/8 的可行成员
Round 2（child 规划）每个 parent 的成员节点内 child：复用 1A 的 SP 分配器，候选度 {1, 2, 4, 8}，近似最小化 child 稀疏 makespan；异常时回退均匀 SP8，再不行不拆

⑤ 失败案例与「全窗口」口径

22 步里 20 步是单个 SP16 parent，repacking 全部变快（基线 solver 下 2.6–11.7%）；剩下的 2-SP16 和 SP32 两步反而变慢（最多 +3.3 s）：按长度计，这两步里最重样本摊到 8 卡后的负载是 parent 平均每 rank 负载的 1.47–1.70×，而所有变快的步骤里最高 1.34×——正是上面下界的第二项在起作用。作者提出的 future work 也直指这里：按预测收益门控 repacking、让 child 上限变成可选（SP8 / 跨一个节点的 SP16 / 不拆）、对「执行后的计划」打分而不是对 repair 前的成员打分。

另一个必须读清的口径：7.61% 是每个触发宽组的 step 的收益。200 步里只有 22 步触发；其余 178 步全是 SP8，按对照 step 均值 28.27 s 估算，宽组 step 约占窗口墙钟的 14%（818.9 s / 5851 s）。乘下来全窗口节省约 1.06%（本文按论文数字估算）。收益随长度分布的离散程度变化——长尾越重，宽组越常见，收益越大；且只来自一个模型、一个集群、训练前 200 步。

实践建议

  • 混合注意力模型的并行规划要「按层类型」做：全注意力层与线性 / 稀疏层的计算对长度的依赖不同，用同一个 SP 组是在拿线性层的 all-to-all 给平方层的负载均衡买单。先 profile 一下「宽组 rank 的 all-to-all 占比 vs 节点内 rank」，差距大就值得做。
  • 新增布局转换前，先找已有的必经通信：这篇的核心技巧是「不加新 collective，只改已有 collective 的 split 和本地置换」。同类机会还有 MoE 的 dispatch / combine（已经是 all-to-all）、TP 的 all-gather / reduce-scatter 边界（见 张量并行）。
  • 置换元数据必须确定性、本地可算：所有 rank 从同一份 plan 推出同一张 rank-major 索引表；任何 tie-break 都要固定（论文的 repair 和 solver 都按 rank / sample 顺序破平），否则就会出现「某个 rank 发的 split 和对端预期不一致」这种难查的挂死。
  • 给变长调度器加两分量代价模型：quadratic full 项 + linear sparse 项分开预测，评估时看关键路径（最慢的 child）而不是总量；求解器做多候选 + 预测器选优，单步几毫秒可承受。
  • 要有「不拆」的退路，并按收益门控：当最重样本的 8 卡负载超过 parent 平均每 rank 负载约 1.3–1.5× 时（论文 22 步上的经验阈值，需在自家负载上重新标定），repacking 可能变慢。
  • 汇报收益要给全窗口口径：只在 14% 的 step 上触发的优化，整窗口大约是 1%。对 RL 训练这种长度分布更长尾的场景（参见 FlashNext-RL 的 131K 长程 rollout），触发比例可能更高，值得单独测。

思考题

1. 为什么不直接把稀疏层改成独立的 SP8 组、在 F↔S 边界单独做一次重分布？论文的成本估算是怎么得出的？

因为全注意力宽组要求 token 在整个 SP16/32 组上分布，而 SP8 child 要求每个样本的 token 留在一个节点内，两者的 token 归属不同；单独重分布等于在每个全注意力层进出各多一次跨节点激活传输，而且前向、重计算、反向三遍都要做。论文用实测转换 payload（74.6 / 70.5 GiB 每宽 rank 每步）除以跨节点有效速率 39.5 GiB/s：搬 Q/K/V/O 四个 attention 张量约 1.89 / 1.78 s，搬两个 hidden state 约 0.94 / 0.89 s，相当于 repacking 本身省下的 3.20 / 2.99 s all-to-all 的 30–60%。融合方案让这部分变为零。

2. 说明 S→F 交换中「可变 split + 置换」为什么在均匀 shard 时退化为标准 Ulysses。

标准 Ulysses 中 rank i 持有第 i 个连续 token 块，向 rank j 发送这块 token 的第 j 个头切片；接收端按源 rank 拼接，得到的就是按 token 升序排列的完整序列，置换为恒等。Repacking 中 own[i] 是 child 布局下 rank i 的 token 位置集合（不连续、长度随 child 的 SP 变化），发给每个 peer 的 token 数为 |own[i]|，接收端按源 rank 拼接后得到的是 rank-major 顺序，需要 argsort(concat own) 这一置换才能排回 parent 升序。own[i] 退化为第 i 个等长连续块时，两者完全相同。

3. 解释下界 M* ≥ max(Σs/R, max s/8) 两项各自对应什么瓶颈，以及为什么 round 1B 只能改善第一项。

第一项是理想平均：parent 内所有稀疏工作均摊到 R 个 rank，它取决于 parent 内有哪些样本，round 1B 重新分配成员可以降低偏重 parent 的这一项。第二项来自 child 上限 SP8：单个样本最多摊到 8 张卡，最重样本的 s/8 不可能再低。移动最重样本只是把这一项换到另一个 parent，而它会出现在收到该样本的那个 parent 里，所以任何成员调整都消除不了。2-SP16 与 SP32 两步变慢，正是第二项（最重样本 8 卡负载是平均负载的 1.47–1.70×）主导。

4. 为什么作者选纯 Ulysses 而不是 USP（Ulysses + Ring）？在什么条件下 Ring 维度会重新变得有价值？

Ring 的价值在于把 KV 块的 P2P 传输与块内 attention 计算重叠，前提是块计算量足够大（Ring Attention 的条件是块大小 c ≥ F/B）。在 1F3S 的稀疏层里，attention 计算太少，无法盖住通信，后面的 MoE 又在重叠窗口之外，所以 Ring 维度预期收益很小；同时 Ulysses 的 all-to-all 是必经交换，恰好可以搭载 repacking。对剩下的全注意力宽组交换（83–86% 的剩余 all-to-all 时间），序列足够长时在宽组内引入 Ring 维度做重叠是有价值的，论文把这一组合列为与 repacking 正交的未来工作。注意 Ulysses 并行度受头数限制（GQA 下受 KV 头数限制），宽组超过头数时也必须引入 Ring。

5. （开放题）把 Layerwise Repacking 用到 Agentic RL 的长程 rollout 训练里，你预期收益会更大还是更小？需要先测哪些量？

可能更大：Agent RL 的轨迹长度通常更长尾（一部分轨迹 100K+ token、大量轨迹很短），宽组触发比例会高于论文的 11%（22/200），全窗口收益随之上升。但有三个风险：(a) 极长单轨迹占比高时，下界第二项（最重样本的 SP8 成本）更常主导，repacking 变慢的 step 也会更多，必须做收益门控；(b) RL 每步的长度分布随策略变化，代价预测器需要在线重标定；(c) 训练端与推理端的数值一致性（参见 舍入位置）对 RL 更敏感，非确定性归约带来的 |Δloss| 漂移要单独监控。需要先测：宽组触发比例、宽组 rank 的 all-to-all 占比、各 step 最重样本 8 卡负载与 parent 平均负载之比的分布。
