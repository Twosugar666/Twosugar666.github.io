第 0 篇 · 损失函数：IS / PPO / CISPO

核心问题：RL 里模型自己生成一段话、事后才拿 reward，loss 到底在优化什么？

一句话答案：后来被证明有用的 token，下次更容易生成；拖后腿的 token，下次少生成。拆开就是三个变量：

  • advantage：这一步是好是坏；
  • sampling_logprobs：采样时（old policy）多喜欢这个 token；
  • target_logprobs：训练时（current policy）多喜欢这个 token。
Loss核心动作人话比喻最易误解的点
ISratio × advantage，ratio = exp(target_lp − sampling_lp)按功劳发奖金loss 为负是正常的——代码在最小化负目标
PPOmin(ratio·A, clip(ratio)·A)奖金有预算上限min 不是随便取小，是做保守更新
CISPOdetach(clip(ratio)) × logprob × A给学习力度挂固定砝码detach 后 ratio 不走梯度，真正被优化的是 logprob

PPO clip 的是 objective；CISPO clip 的是 ratio 并把它 detach 成固定权重——这是两者最本质的区别。

第 1 篇 · GRPO

出处：DeepSeekMath（arXiv:2402.03300）。动机一句话：PPO 好用但太重——actor-critic 要额外训练一个与 policy 同量级的 value model，且数学题只有最终答案可打分，value model 很难给每个 token 估准 baseline。

核心替换：

PPO:  用 value model 估 baseline
GRPO: 用同一 prompt 下一组回答的平均 reward 当 baseline
      A_i = (r_i − mean(r)) / std(r)   （demo 简化为 r_i − mean(r)）

实现要点（GSM8K，boxed 答案 0/1 reward）：

  • 每个 step 先从当前 LoRA 权重导出 sampler —— 它就是 old policy，logprobs 必须来自采样当时，不能更新后重算；
  • 同一题采 group_size 条回答；整组 reward 全同 → advantage 全 0 → 跳过（记 frac_degenerate 指标，模型太弱全错/太强全对都没信号）；
  • Datum 对齐是易错点：model_input = prompt + completion[:-1]，prompt 区间的 target/logprob/advantage 全部填 0——GRPO 不是训练模型背 prompt；
  • 同一套 rollout 可切换三个 loss：内置 importance_sampling/ppo，CISPO 走 forward_backward_custom（远端算可求导 logprob，本地用 torch 写任意 loss）；
  • 关键指标：reward、frac_degenerate、cispo/clip_fraction（高说明 lr 太大或策略偏离太远）。

与论文的差异：rule-based 0/1 reward（未用 reward model）、advantage 未除 std、未加 reference KL。成本：调试共 55 元，10 步小跑约 5 元。

第 2 篇 · OPD（On-Policy Distillation）

脉络：GKD（arXiv:2306.13649，Student 在自己生成的序列上接受反馈）+ MiniLLM（arXiv:2306.08543，reverse KL）。

与 GRPO 的分野：

GRPO: advantage 来自同组回答的相对 reward
OPD:  advantage 来自 Teacher 与 Student 的逐 token logprob 差
      reverse_kl_t = logp_student − logp_teacher
      A_t = −β · reverse_kl_t   （Teacher 更认可的 token 被鼓励）

关键约束：Teacher 用 compute_logprobs 对同一条 Student 轨迹做 teacher forcing，绝不重新生成答案——两条 completion 不同就无法逐 token 对齐。group_size 只是多产轨迹，不在组内比较。

真实问题实验（中文医疗增强）：Medical SFT 把 MedQA-zh 从 72.17% → 79.00%，但 C-Eval 通用能力 81.67% → 69.33%（灾难性遗忘）。于是设计两套方案：

方案结构结果（MedQA-zh / C-Eval）
SAR-OPD（分阶段锚点恢复）① SFT 出 Medical Teacher → ② fresh Student 做 Medical OPD（lr 4e-5, 300 步）→ ③ 换原始 Base 当 Teacher 做 C-Eval OPD 恢复通用能力（lr 5e-6）84.33% / 84.67%，双超 Base
IDT-OPD（交替双教师）同一 Student 按 step 1:1 交替接受 Medical/Base Teacher，共享 LoRA、optimizer state、全局 stepstep 100 偏医疗（79.17/81.67），step 200 偏通用（76.50/86.00）；训到 600 步反而回落——没有单调变好的终点，早停和选 checkpoint 比跑满更重要

意外发现：SAR 第三阶段没用任何医疗数据，MedQA 却不降反升（80.00 → 84.33）——恢复通用分布和保持领域能力未必是零和。工程细节：sampler_weights（推理/冻结 Teacher）与 training_state（恢复续训）两类路径不能混用。成本：全套实验约 500 元，复现约 200 元内，只跑 DeepMath 入门版约 50 元。

第 3 篇 · Search-R1

出处：arXiv:2503.09516。核心变化：搜索从回答前的固定步骤（RAG），变成推理轨迹中可反复选择的动作。训练对象是 LoRA 权重，搜索引擎是固定环境。

最大的复现决策：原版要 160GB Wikipedia 语料 + E5 索引 + 180GB 内存的本地 retriever；作者换成可切换的在线搜索（DeepSeek Evidence 模式 / Wikipedia / 知乎），算法闭环不变——只要保留 search(query) → observations 接口。

实现要点：

  • 轨迹分叉：首轮同题 8 条轨迹共享 prompt（num_samples=8）；第一次搜索后各轨迹 query/observation 不同，必须拆成 num_samples=1 并发推进。轨迹内严格串行，轨迹间并发；
  • outcome-only reward：对 1.0 / 错 0.0 / 格式非法 −0.1。不奖励搜索次数等中间行为——中间 reward 容易诱导 reward hacking；
  • observation mask：搜索结果留在上下文但 advantage/logprob 置 0，不进 loss；
  • group 完整性：先在完整 8 条轨迹上算组内 advantage，再拆 micro-batch（按 n_k/N 缩放 advantage 保证等价全局均值），顺序不能反。

结果（固定 70 题评测）：知乎后端 Step 50 Macro EM 28.57% → 45.71%，Format 58.57% → 94.29%；DeepSeek 后端 20 步 +5.71pp。重要教训：训练后期知乎 API key 额度耗尽 → correctness reward 下降是环境污染而非模型退化（format reward 不受影响仍稳定上升）。Agentic RL 里环境质量本身就是实验变量。成本：¥13.30（一杯奶茶）。

第 4 篇 · OPSD（On-Policy Self-Distillation）

出处：Self-Distilled Reasoner（arXiv:2601.18734）。一句话：不找更大的 Teacher，让同一个模型一边闭卷答题、一边拿着参考答案给自己判卷。

机制：Student 和 Teacher 是同一个初始模型，区别只在 prompt——Teacher 的 prompt 里多了参考解答（privileged information）。Teacher 对 Student 的真实 rollout 做一次 forward 算 logprob（不生成新 token），advantage 同 OPD 的 sampled-token reverse KL。

解决的两个问题：① SFT 的 off-policy 错位（训练看专家轨迹，推理面对自己的错误状态）；② GRPO 的稀疏信号（上千 token 只有一个 0/1，且全对全错组 advantage 归零）——OPSD 每个 completion token 都有监督，即使最终答案错，中间 token 仍能产生信号。

方法轨迹来源信号粒度Teacher
SFT固定专家轨迹token CE无
GRPO当前策略sequence rewardVerifier
OPD当前 Studenttoken logprob 差独立模型
OPSD当前 Studenttoken logprob 差同一模型 + 参考答案 prompt

配置与结果：LoRA rank 64，OpenThoughts 29,434 条，100 步，IS loss，严格 on-policy（每步刷新 sampler）。AIME25：Average@12 51.67% → 52.78%，Pass@12 80.00% → 86.67%（中间有波动，Step 75 甚至低于 Base）。注意：loss / reverse KL 下降只说明 Student 靠近 Teacher，不等于能力提升，必须看独立 benchmark。成本：训练 ¥41.81 + 5 次评测 ¥83.61 ≈ 一顿疯狂星期四；100 步约 2 小时。

第 5 篇 · ReTool

出处：字节 Seed（arXiv:2504.11536）。一句话：让模型在 long CoT 里自己决定什么时候写 Python——没人教它什么时候用计算器，这个习惯从结果奖励里涌现。

两个关键设定：① code-interlaced rollout——生成到代码就暂停，沙箱执行后把 stdout/stderr 拼回上下文，返回 token 不进 loss；② outcome-only reward——只看最终 \boxed{}（math_verify 数学等价），对 +1 错 −1。

复现决策与踩坑：

  • 用 Qwen 原生 <tool_call> 协议代替特殊 token/代码围栏，不动 tokenizer；
  • 跳过 cold-start SFT：smoke test 显示 base 工具调用率已 87.5%，直接 RL；
  • 本地 subprocess 沙箱（30s 超时 + RLIMIT_CPU + 自动补 print + 对返回文本消毒——模型打印 <|im_end|> 之类特殊 token 会破坏 observation 结构）；
  • token-in token-out 续写：用真实采样 token 拼接，不做 text↔token 重编码——官方实测重编码不可逆会导致约 100 步后性能崩塌、grad_norm NaN；
  • PPO clip 0.8/1.28（即 DAPO 的 clip-higher）。

结果：200 步 AIME25 Average@12 23.61% → 47.50%（+23.89pp），Format 25.83% → 76.11%（受 8k 预算截断所限，论文用 16k）。模型学会的顺序：先调出合法 tool call（0.6→0.95）→ 再写能跑的代码（沙箱 error 腰斩）→ 最后写对解题有用的代码（correct 0.2→0.6）。成本：20 步验证 ¥31.66（两杯瑞幸），200 步正式训练 ¥224.44。

第 6 篇 · DAPO

出处：arXiv:2503.14476（Decoupled Clip and Dynamic sAmpling Policy Optimization）。不是推翻 GRPO，而是面向 long CoT 的四项改进 recipe：

改动内容解决什么
Clip-HigherPPO clip 从对称 [0.8, 1.2] 改为 [0.8, 1.28]entropy collapse——给低概率但有价值的正向 token 更大提升空间
Dynamic Sampling剔除组内全对/全错的 prompt 并补采，直到 batch 全是 accuracy∈(0,1) 的有效 group无效 group 不提供梯度，在线难度筛选
Token-level Loss所有 completion token 等权求均值（token mean），而非先按样本求均值（sample mean）长推理轨迹不被 sequence 级平均稀释
Soft Overlong Punishment长度接近上限时线性惩罚（如 max 4096 / cache 1024：3072 起罚，4096 处 −1）硬截断导致的 reward 突跳噪声

本篇最有价值的工程分析——Dynamic Sampling 的隐性代价：

  • 被丢弃的 group 不是零成本：已经完整经历了 prefill → 采样 → reward 判定，只是没进 loss；
  • refill barrier：batch 只差最后 1 个有效 group 时，只能单组补采、串行等待。B=4、候选倍率 M=2 时最坏 1+(M−1)×B = 5 个等待 wave，每 wave 还可能撞上 8k token 长尾；
  • 这与异步 RL 存在结构性冲突：异步想让数据流动起来，严格 Dynamic Sampling 却要求凑齐整批才能更新；
  • 必看指标：effective_fill_ratio（质量）、oversample_ratio（筛选代价）、train/rollout token 比（利用率）、step_seconds（真实 wall-clock 产出）。

作者实测 35 步耗时 4.17 小时后手动停止，并把默认配置缩小（max_tokens 8192→4096 等）。本篇不做效果对比，重点是"把算法从黑盒里拿出来看清代价"。

第 7 篇 · GSPO

出处：Qwen 团队（arXiv:2507.18071，Group Sequence Policy Optimization）。改动极其集中：group rollout、reward、组内 advantage 全部沿用 GRPO，只把重要性比率和裁剪从 token 级提升到 sequence 级。

GRPO: 一条回答 T 个 token → T 个 ratio → T 次 clipping
GSPO: 一条回答 1 个 ratio → 1 次 clipping
      s_i = exp( mean_t[ logp_current(y_t) − logp_old(y_t) ] )   ← 长度归一化
      J = (1/G) Σ min( s_i·A_i , clip(s_i)·A_i )
      论文 clip 范围：ε_low = 3e-4, ε_high = 4e-4（看着小，因为约束的是整句 ratio）

动机：reward 本来就是按完整回答给的，sequence-level ratio 让 reward、重要性采样、优化目标处于同一粒度，减少长序列逐 token ratio 的高方差噪声。实现走 forward_backward_custom（本地算 sequence ratio）。

结果（100 步，¥155.80）：Step 20 Pass@12 相比 Base 66.67% → 73.33%（+6.66pp，即标题"提高 6 个点"）；但更扎实的观察是行为变化——Format 47.5% → 99.44%，平均回答长度缩短约 48%，而 Average@12 在 Step 20 后逐步下降。两次 Base 评测 Pass@12 本身就差 10pp（30 题小样本波动）。结论：GSPO 明显改变了输出行为，准确率是否稳定提升还需 matched GRPO 对照和多种子验证。

第 8 篇 · ALFWorld

环境：ALFWorld（ICLR 2021）的 text-only 模式——TextWorld/PDDL 维护真实状态的文字厨房。原论文用 DAgger；本文是自己加的 GRPO-style group rollout + PPO，属于"基于 ALFWorld 的 Agentic RL recipe"。

与前作的本质不同：每次工具调用真正改变环境状态（没开冰箱就放不进苹果），一条轨迹最多 50 次交互、评测平均 21～23 步、上下文上限 12K tokens，模型始终看到从任务开始的完整历史（强状态依赖，丢历史会重复搜索/拿错物体）。

关键设计：

  • 唯一工具 alfworld_step(action)，实例名（如 apple 1）必须原样复制；终止信号由环境给出（won/done），不让模型自己宣布完成；
  • GRPO 分组单位 = 同一游戏同一初始状态的 8 个独立环境轨迹；
  • reward = 1[won] − 0.1 × 非法动作数（episode 级，无 step reward）；advantage 只减组内均值（不除 std）；
  • observation token advantage/logprob 置 0，只训练 assistant token；PPO clip 0.8/1.2，lr 1e-6。

结果（80 步，274 个固定游戏）：总成功率 52.92% → 56.93%（+4.01pp），valid_unseen +5.97pp（提升主要来自没见过的房间，说明策略真的迁移了），平均非法动作 5.41 → 4.81。任务间提升不均匀（heat 类 +26.1pp，pick-two 类 −11.8pp）。

成本警示（¥1613.71）：账单构成 prefilling 843.51M ≫ train 62.24M ≫ sample 14.28M——长轨迹 Agentic RL 里，每轮都要带着不断增长的历史重算 prefix，反复读上下文的 prefill 才是大头，训练 token 只是零头。这是做 Agent-RL 预算时最容易低估的部分。

第 9 篇 · Vision GRPO

任务：GeoQA 中文几何问答（图 + 题 + 四选项），把整条 GRPO 链路推进到多模态。

多模态特有的实现点：

  • prompt 沿 <|image_pad|> 拆成 Text + Image + Text 三个 chunk；图片先合成白底转 RGB，用 image processor 算视觉 patch 数写入 ImageChunk.expected_tokens；
  • 采样后强制校验 response.input_tokens == len(prompt)——本地视觉 token 估计与远端不一致立即报错，否则后续 target/logprob/advantage 的坐标系全错；
  • 图片和 prompt 区间的 target/logprob/advantage 同样全部填 0，策略梯度只作用于 completion。

结果（100 步，固定 100 题）：Accuracy 71.0% → 87.0%，Format 75.0% → 91.0%。最有意思的拆解：+16pp 几乎全来自格式——格式正确的样本里，条件准确率只从 94.7% 提到 95.6%。也就是说 GRPO 主要教会了模型"稳定地把答案写进 \boxed{}"，答题能力本身只微涨。剩余 9 条失败样本全是顶到 1024 token 上限被截断的长推理。成本：20 步试跑仅 ¥5.06（标题"5 块钱"）。

贯穿全系列的六条方法论

  • 信号三分法：reward（GRPO 系）/ Teacher logprob 差（OPD 系）/ 同模型 privileged context（OPSD）——选算法先看你能拿到什么信号；
  • outcome-only 优先：中间过程 reward（搜索次数、调代码次数）容易 reward hacking，能只奖励最终结果就只奖励最终结果；
  • mask 纪律：prompt、tool observation 留在上下文但 advantage 置 0；old logprob 必须来自采样当时的 policy；
  • degenerate group 是健康度指标：全对全错组无信号，比例高说明题太易/太难或环境出问题；
  • 环境即变量：搜索 API 限流、沙箱超时都会污染 reward——先看 search/error_rate 再下"模型退化"的结论；
  • loss 下降 ≠ 能力提升：一切结论以固定题库、固定温度的独立评测为准，且小样本（30～100 题）要警惕波动。
