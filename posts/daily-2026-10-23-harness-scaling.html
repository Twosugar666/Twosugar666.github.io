学习笔记｜Harness Scaling：把「怎么执行」当成 Agentic RL 的新扩展轴——5 组件 × 3 变体的 243 格 harness 空间，strength-2 正交表只挑 18 个训练，同一任务配邻近 harness；Qwen3-4B GRPO 平均 29.81→39.04，迁移到 Claude Code 胜过直接在 OpenClaw 上训

2026-10-23 · 收藏夹：Harness / Agent / RL · 学习笔记
来源：Fei Bai*、Huatong Song*、Chuan Hao、Ran Tao、Jian Yang、Bryan Dai、Wayne Xin Zhao†、Ji-Rong Wen（中国人民大学高瓴人工智能学院 / IQuest Research / 北京航空航天大学）· Harness Scaling for Generalizable Agentic Reinforcement Learning（arXiv:2610.29458，2026-10-21 提交）。 数字均为论文自报：Pass@1 为 3 次独立评测均值，In-Space 再对 18 个 held-out 配置取平均；rubric 类评测与行为分析用 GPT-5.4 作 judge。「box 小验证」一节为本文在 box 上用 Python 对论文附录给出的配置表实算。 交叉： Agent Lightning v1.0、 Coding Agent Harness 组件消融、 ClawLoop、 When the Harness Decides Success、 今日一线：FlashNext-RL。

背景与动机

本站 harness 系列反复看到同一个现象：同一个模型换个 harness，分数能差一大截——组件消融里规划 / 动作空间 / 上下文管理各自能拉开差距，再观测那篇里上下文策略能决定成败。于是「直接在 harness 里做 RL」成了主流（Agent Lightning、OpenClaw-RL 等）。但这些方法几乎都只在一个固定 harness 里训：策略学会的可能是这个 harness 的工具命名、提示措辞、观测格式，而不是「在任意执行环境里把事做成」。

这篇的主张是：task scaling 扩展「解什么」，environment scaling 扩展「在哪儿解」，还缺一条 harness scaling——同一任务、同一环境，换「怎么执行」。难点不在想法，而在组织：harness 变体组合爆炸，全训既贵又冗余；随便抽一些又没有覆盖保证。作者借用了实验设计里的正交表（orthogonal array）来回答「挑哪些」，再用 Hamming 距离回答「同一任务配哪些」。

机制拆解

① 把 harness 因子化：5 个组件 × 3 个实现

harness 被拆成 system prompt（S）、tool interface（T）、observation（O）、context management（C）、workflow（W）五个组件，每个组件从 base 出发由 Opus-4.7 生成变体，约束是「只改目标组件，任务语义、环境行为和其他组件功能不变」。完整空间 H = S×T×O×C×W = 35 = 243 个配置，构成 Hamming 图 H(5,3)：相邻配置恰好差一个组件。

组件Base（0）Variant I（1）Variant II（2）
S 系统提示直接给出角色与执行规则同样要求嵌入一个模拟产品语境，附平台与 UI 描述用叙事 / 角色扮演方式重述要求
T 工具接口原始工具名与 schema（如 execute_bash、file_editor），无干扰项语义相关的别名 + 若干无功能干扰工具不透明标识符 + 干扰工具，基本去掉工具名里的词汇线索
O 观测原始工具输出附加模拟基础设施元数据（pod 名、namespace、调度信息）附加 XML 风格结构化元数据（工具名、exit code、PID、耗时、执行节点）
C 上下文管理完整历史保留LLM 周期性 compaction 总结早期历史，保留最近 5 轮更激进：只留最近 3 轮，总结外置到辅助文件

base 工具族有五类：文件读写编辑、Bash、代码解释器、搜索、网页抓取。注意 T 的变体 II 很「狠」：工具名不再泄露功能，策略必须读 schema 与反馈来推断用途——这正是固定 harness 训练最容易过拟合的地方。

② 挑 18 个：strength-2 正交表

# 把 harness 空间看作因子设计：组件 = 因子，实现 = 水平
# 目标：保住低阶结构
#   一阶（component balance）：每个组件的每个实现出现次数相同
#   二阶（pairwise balance）：任意两组件 i≠j 的任意实现对 (ℓ, ℓ') 出现次数相同
#         N_ij(ℓ, ℓ') = λ
# M 个组件、每个 L 个实现：
#   N = λ · L²                  （任意两组件的 L² 种组合划分了全部选中配置）
#   N ≥ 1 + M(L − 1)            （Rao bound）
# 本文 M=5, L=3：N = 9λ 且 N ≥ 11 → 最小 N = 18（λ = 2）
#   每个实现出现 λL = 6 次，每个跨组件实现对恰好出现 2 次

18 / 243 ≈ 7.4%。一阶与二阶投影完全平衡，但大量三阶以上的完整组合训练时没见过——这正好留出「组合泛化」的评测空间：从 H \ Htr 里固定选 18 个 held-out 配置（每个实现在其中也恰好出现 6 次，配置间两两 Hamming 距离 2–5），所有 benchmark / 模型 / 算法共用。

③ 同一任务配谁：locality-aware 分配

for task x:
    h_x ~ Uniform(H_tr)                       # anchor：全局覆盖
    neighbors = argsort_{h ∈ H_tr \ {h_x}} d_H(h_x, h)[:K-1]   # 最近的 K-1 个：局部变化
    H_x = {h_x} ∪ neighbors
# K 个 (x, h) 实例在 K 个连续训练 step 中使用
# 优化目标不变：标准 clipped objective，token 级 mean
L(θ) = (1/N_B) Σ_{(x,h,τ)∈B} Σ_t M_t · min(ρ_t A_t, clip(ρ_t, 1−ε, 1+ε) A_t)
# ρ_t 的条件里带着 h：π_θ(τ_t | x, h, τ_<t) / π_old(τ_t | x, h, τ_<t)

设计意图是「全局 + 局部」：随机 anchor 让不同任务铺满整个 Htr；最近邻让同一任务在结构上相近但不同的配置下各跑一次，相当于对 harness 做受控扰动，逼策略把「任务解法」和「harness 表面特征」分开。Harness Scaling 只改变 rollout 用哪些 (task, harness) 实例，RL 算法本身（PPO / GRPO）不动。

一个容易被忽略的训练细节（附录 C.1）：C 组件的 compaction 会把一条 rollout 切成多个训练段。所有段共享 rollout 级奖励，GRPO 的组归一化仍只在 8 条原始 rollout 的奖励上算，段继承父 rollout 的组身份和 advantage、不额外进入均值方差；loss 用全 batch 有效 token 的 mean，所以切成几段都不会给某条 rollout 额外的样本级权重。这和 compaction 文里讨论的「压缩后怎么训」是同一问题的一个干净解法。

  • 训练集规模：1 → 3（一阶覆盖，每个实现至少出现一次）已有 +11.43 / +4.84（ClawGym）与 +3.44 / +7.86（PinchBench）；18 个结构化配置再 +4.02 / +1.57 与 +7.20 / +2.66；全 243 个配置（包括评测配置本身）在同预算下反而更差——穷举覆盖不保证更好，预算被摊薄了。
  • K=1 已大幅领先 Single：说明「不同任务用不同 harness」本身就有价值；K=2 比 Repeat-2 稳定更好（ClawGym +3.02 / +1.77，PinchBench +5.90 / +2.83），排除了「只是同一任务多见一次」的解释；K=4 无进一步收益。
  • 基线敏感性：换三个结构上最分散的固定 harness 作 Single 基线（三个 benchmark 平均 In-Space 31.06–35.79、Claude Code 28.57–36.11），Harness Scaling（40.86 / 37.22）仍全部领先，说明优势不是 base 配置选得差造成的。

⑦ 行为层面：学到了什么

用 GPT-5.4 对 200 条轨迹 × 18 个 held-out harness 按 5 分制打六个维度：instruction following、interface handling、observation reading、state tracking、workflow compliance、error recovery。增益最大的是 state tracking、workflow compliance、error recovery，observation reading 增益最小。两个差 4 个组件的 held-out 配置（A = S0T2O1C1W2，B = S2T1O1C2W0）上的逐任务配对奖励，Harness Scaling 整体向右上移动，且更贴近对角线——换 harness 时逐任务表现更一致。

实践建议

  • 做 harness RL 时，至少做一阶覆盖：哪怕只有 3 个变体（每个组件的每个实现出现一次），收益已经很大（ClawGym In-Space +11.43）。成本只是多写几套 prompt / 工具别名 / 观测包装。
  • 变体要「功能等价、表面不同」：论文的约束是只改目标组件、不改任务语义。工具别名 + 干扰工具、观测里加无关元数据，是最便宜也最有效的「去捷径」扰动。
  • 用正交表而不是随机抽或穷举：组件数 M、实现数 L 给定后，先用 N = λL² 与 Rao bound 算最小规模；Random-18 与 Full-243 都更差。
  • 同一任务配一个近邻 harness（K=2），连续两步使用；不要贪多（K=4 回落）。
  • 评测要分 In-Space 与真实黑盒两档，并把「base harness 上掉多少」作为代价一起报告——这比单一 harness 的 leaderboard 分数更接近部署现实。
  • context management 作为变体时，注意训练段的权重语义：段继承 rollout 级奖励与 advantage、组归一化只在原始 rollout 上做、loss 按 token mean。

思考题

1. 为什么 Full-243（训练集甚至包含评测配置）在同预算下反而不如结构化的 18 个？

固定 300 步、每步 16 个任务的预算下，243 个配置意味着大多数配置只被少数几个任务碰到，每个 (任务, harness) 组合的信号很稀；而且同一任务几乎不会在相近配置下被比较，局部对比（K 个近邻）的效应被稀释。18 个配置在一阶、二阶上精确平衡，每个配置有足够曝光，近邻分配又提供了受控扰动。本质上是「覆盖」与「每格样本量」的 trade-off：正交表在低阶交互上做到了最省的完全覆盖。

2. Repeat-2（同一 anchor 用两次）为什么是必要的对照？它的结果说明了什么？

K=2 把每个任务连续用两步，相比 K=1 多了一次同任务曝光；如果收益只是来自「同一任务多学一次」，Repeat-2 应和 K=2 一样好。结果是 Repeat-2 相对 K=1 有涨有跌（PinchBench In-Space 54.23→50.34 反而掉），而 K=2 在两个 benchmark 的两种评测上都优于 Repeat-2，说明「同一任务换 harness」本身贡献了额外收益，类似对 harness 做数据增强、让策略学到对表面特征的不变性。

3. box 实算显示：在论文的 18 行正交表里，每个 anchor 的最近邻都差 2 个组件。这对「locality-aware 分配」的解读和复现意味着什么？

（1）解读：K=2 时同一任务看到的两个 harness 总是同时改动两个组件，扰动强度比「只差一个组件」更大，且无法区分是哪个组件带来的不变性；论文里「邻近」的含义是「在 Htr 内最近」，不是 Hamming 图上的相邻。（2）复现：同为 strength-2、λ=2 的等价正交表（行置换、列内水平重标号之外的不同构造）可能有不同的行间距离分布，K=2 的实际扰动强度会随之变化，应报告实际分配到的距离分布。（3）可做的消融：在 Htr 外额外允许 d=1 的配置作为同任务伙伴（牺牲严格平衡），检验「更小的局部扰动」是否更好——这能把「局部性」与「正交平衡」两个因素拆开。

4. 行为分析里 observation reading 增益最小，而 state tracking / error recovery 增益最大。结合 O 与 C 两个组件的设计，你怎么解释？

O 的变体只是在原始输出外面加元数据（pod 名、PID、耗时等），任务相关内容不变，强一点的基座模型本来就能忽略噪声，所以上升空间有限。C 的变体会删掉或外置历史（只留 3–5 轮），W 的变体要求定期核查进度，这些直接迫使策略维护内部任务状态、在信息缺失时恢复——正好对应 state tracking 与 workflow compliance；T 的不透明工具名让早期调用更容易失败，训练出 error recovery。也可以联系 再观测文：当上下文策略让信息不可再观测时，记笔记 / 状态跟踪能力最值钱。

5. （开放题）如果把 Harness Scaling 与 ClawLoop 或 Harness 自动进化（如 EvoHarness-RL）结合，会出现什么新问题？

自动进化会持续产生新的 harness 变体，空间不再是固定的 S×T×O×C×W 笛卡尔积，正交表无法预先构造；可以把进化产生的变体按组件归类后周期性重建正交表，或用 covering array（只保证每对至少出现一次）降低重建成本。另一个问题是因果混淆：harness 在变、策略也在变，分数提升难以归因（参见 HDA 的归因思路）。还要警惕「harness 变体由强模型生成」带来的分布偏置——Opus-4.7 写的变体是否覆盖了真实生产 harness 的差异维度（例如权限模型、并行工具调用、子 Agent），论文的 5 组件并未包含。
