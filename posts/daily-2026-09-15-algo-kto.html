学习笔记｜KTO：用二元好/坏信号做前景理论对齐（无需偏好对）

2026-09-15 · 收藏夹：算法 / RL · 学习笔记
经典：Ethayarajh 等 · KTO: Model Alignment as Prospect Theoretic Optimization · arXiv:2402.01306 · ICML 2024。 交叉： DPO、 PPO、 REINFORCE、 Actor-Critic。

背景与动机

对齐数据最贵的形态之一是偏好对：同一 prompt 上标 y_w ≻ y_l。 DPO 把 Bradley-Terry + KL 约束 RL 重参数化成偏好对上的 −log σ(…) 目标，省掉显式 RM + PPO 环，但仍然吃成对数据。

现实里更常见、也更便宜的是二元标签：这条 (x, y) 合意 / 不合意——点赞、点踩、安全审核通过/拒绝、人工抽检好/坏。不必为每个 x 生成并比较两条回复。 KTO（Kahneman-Tversky Optimization） 把对齐写成前景理论里的效用最大化：不最大化偏好似然，而最大化生成相对参考点的价值；损失族被作者归为 HALOs（human-aware losses）——并指出 DPO 一类目标里已隐式编码了类似前景理论的偏置。

一句话：KTO 用 Kahneman-Tversky 价值函数，对带二元 desirable / undesirable 标签的 (x,y) 做不对称 sigmoid 损失；只需好/坏，不需偏好对；β 控偏离参考策略的尺度，desirable_weight / undesirable_weight 校正类别失衡与损失厌恶不对称。

机制拆解

① HALOs 与「为何不必成对」

DPO 族KTO
数据(x, y_w, y_l) 偏好对(x, y, label∈{好,坏})
目标语义偏好 log-likelihood（BT）生成效用（前景理论价值）
参考点隐式进 π_θ/π_ref 比显式 KL 参考点 + 不对称价值
成本成对标注 / 配对构造二元反馈；更易规模化

作者将人类感知偏差（损失厌恶、参考依赖等）写进损失设计，并观察：许多成功的人类感知损失（HALOs）与前景理论结构同族；DPO 等偏好法在重参数化后也浮现类似偏置——KTO 则直接从效用侧下手。

② Kahneman-Tversky 价值：相对参考点

# 前景理论直觉（示意）：
# 人评价的是相对参考点的「得/失」，且损失侧更陡（损失厌恶）

# LLM 对齐里常用的「隐式奖励」片段（与 DPO 同族写法）：
r_θ(x,y) = β · log( π_θ(y|x) / π_ref(y|x) )

# KTO：不把两条 y 做差进 BT，而是对单条 y 的 r_θ
# 相对一个参考基准（与 KL / 期望相关）做不对称价值
# 合意样本：鼓励 r 高于参考 → 提高效用
# 不合意样本：惩罚 r 高于参考（或等价地压低坏回复的相对奖励）

与 PPO / REINFORCE / Actor-Critic 的对比：后者在奖励（或优势）上做策略梯度；KTO 是离线对齐目标，不滚动环境，也不估计 V。它更接近 DPO 的「闭式偏好/反馈损失」家族，只是反馈从成对变成二元。

③ 损失形态：不对称 sigmoid + 类别权重

# 示意（实现细节以原论文 / 官方代码为准）
# z = r_θ(x,y) − 参考基准（与 π_ref、KL 估计相关）

# 合意 (desirable)：
L+ ∝ 1 − σ( β · z )          # 推高相对参考的价值

# 不合意 (undesirable)：
L− ∝ σ( β · z )              # 压低坏回复的相对价值
# （等价写法常体现损失厌恶：坏侧权重/斜率与好侧不对称）

L_KTO = λ_d · E_{好}[L+] + λ_u · E_{坏}[L−]

# β：偏离 π_ref 的温度 / 强度
# λ_d = desirable_weight，λ_u = undesirable_weight
# → 校正好/坏比例失衡，并编码损失厌恶不对称
旋钮作用
β越大越贴参考策略（保守）；越小越敢按二元反馈挪分布
desirable_weight上调时更强调「学好样本」；数据里好样本稀缺时可加大
undesirable_weight上调时更强调「远离坏样本」；安全/拒答场景常更敏感
π_ref冻结参考；与 DPO 一样，更新 ref 会毁掉比的语义

④ 和 DPO / PPO 放一张图里

PPO-RLHFDPOKTO
在线采样要经典设定不要不要
显式 RM要不要不要
数据偏好→RM；再 RL偏好对二元好/坏
核心对象E[r]−β KLBT 偏好似然KT 效用 / HALO
典型场景有奖励模型的在线对齐有成对偏好有点赞点踩 / 审核标签

论文口径：在约 1B–30B 尺度上，KTO 匹配或超过偏好类方法（作者自报）。读实验时分清：二元数据量往往更大——比较的是「同预算标注」还是「同条数样本」，结论会不同。

实践建议

  • 有成对就 DPO，有二元就 KTO：不要为了用 DPO 硬把点赞点踩拼成伪对；噪声配对会直接毒 BT 似然。
  • 先看类别比例再设 λ_d / λ_u：好/坏严重失衡时，默认等权会让梯度被多数类吞掉；权重是一等超参，不是装饰。
  • β 与 DPO 同逻辑扫：过小易过拟合反馈、伤语言质量；过大则几乎不动。对齐轴与能力轴分开回归。
  • 坏样本质量很关键：随机噪声「坏」不如真实有害/跑题/拒答失败； undesireable 侧决定你在推开什么。
  • 与 RLVR 栈分工：数学/代码/agent 可验证成功优先规则奖励 + GRPO；主观对齐、安全、风格优先偏好/二元 HALO。可串联，勿混成一个 loss 解释一切。
  • π_ref 冻结：从 SFT 拷贝后冻结；中途换 ref 等于改参考点，前景理论里的「得/失」会漂移。

思考题

1. 为什么说 DPO 隐式带有前景理论味，而 KTO 是显式？

DPO 从 KL 约束最优策略反解隐式奖励再代入 BT，人类偏好数据本身含参考依赖与损失厌恶，损失曲面会体现类似偏置。KTO 直接把 KT 价值函数写进目标，并对单条生成相对参考点打分，不经成对 BT。

2. 只有好样本、几乎没有坏样本时，KTO 还能用吗？

理论上可把权重倾斜到 desirable，但缺少「推开」方向时，模型可能只会提高好样本似然、对有害模式约束弱。实践上应补至少一定量的真实 undesireable，或与安全分类器 / 规则过滤联用。

3. KTO 的 β 与 PPO 的 KL 系数是同一个旋钮吗？

角色类似——都约束相对 π_ref 的偏离——但嵌入的目标不同：PPO 在在线 RL 目标里显式减 KL；KTO 在离线效用损失里通过 log-ratio 尺度体现。调参直觉可迁移，实现与曲线不可照搬。

4. 把两条 unary 标签拼成伪偏好对喂 DPO，错在哪？

BT 假设同一 x 上两条回复可比较。跨 prompt 或随机配对会破坏「同一上下文下的相对偏好」，梯度指向无定义的比较。KTO 的设计初衷之一就是避免这种伪造。

5. 何时仍应优先 PPO / Actor-Critic，而不是 KTO？

需要在线探索、环境交互、或奖励随状态密集变化时（agent 工具成功、多步终局），策略梯度 / AC 更直接。KTO 擅长消化离线二元人类反馈，不是环境 RL 的替代品。
