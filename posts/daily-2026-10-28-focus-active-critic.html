一线追踪｜FOCUS：长程 Agent RL 把 critic 当「主动学习」来训——在 compaction 切出的段边界分叉续跑，按「再采一条能把价值误差降多少」分配 rollout 预算；Qwen3.5-9B 上 BrowseComp-Plus 55.4 vs GRPO 48.2，GRPO 后期工具调用塌缩而 FOCUS 不塌

2026-10-28 · 收藏夹：Agent / RL · 一线追踪
来源：Zhengping Jiang、William Jurayj、Liaoyaqi Wang、Chunsheng Zuo、Anqi Liu、Benjamin Van Durme（Johns Hopkins University）· FOCUS: Active Critic Learning for Long-Horizon Language Model Agents（arXiv:2610.35801，cs.LG，v1 2026-10-26，出现在 arXiv 10-27 的 /new 批次）。 代码 zipJiang/FOCUS。FOCUS = Focused Optimization on Critical Underperforming Segments。 文中数字均为论文自报；「box 小验证」一节为本文在 box 上用 numpy 实跑。 交叉： TD(λ)、 GAE、 Actor-Critic、 GRPO、 Compact-Bench、 Context Compaction。

背景与动机

长程 agent（几十到上百次 tool call 的 deep search、读法规、代码定位）做 RLVR 时，稀疏的终局奖励要被摊到整条轨迹的每个 token 上。GRPO 用组内相对奖励省掉 critic，但信用是轨迹级的——一条成功轨迹里多余的、甚至有害的步骤也会被同样强化。另一条路是给中间状态估价值，来源只有两种：

  • 学习的 critic（Actor-Critic / PPO 路线）：跨轨迹复用信息，但 LLM 规模的 value head 在长程任务上经常估不准；
  • Monte Carlo 续跑（VinePPO、TreeRL、TreePO 一类）：从中间状态分叉再采若干条，均值当价值，准但贵——每个估计都要额外生成。

FOCUS 的提问是：既然预算有限，哪些中间状态最值得再采一条？它把「用续跑证据修 critic」建模成 critic 的主动学习（active learning）：只在「再多一条结果能最大程度降低价值估计误差」的状态上分叉，修正后的价值一边给 actor 做分段 TD 优势，一边当 critic 的训练目标。长程场景里，分叉点直接取 context compaction 的边界——这和昨天 Compact-Bench 讨论的是同一个 harness 机制，只是这里把它当成了 RL 的「天然 step 切分」。

机制拆解

① 把 episode 当一棵树：节点 = 可恢复状态，边 = 一段续跑

对每个 prompt x，所有 rollout 组织成树 Tx。非终止节点是「能用同样上下文和环境状态恢复执行」的点（论文假设至少部分中间状态可 fork，重复采样便宜），边是从该点到下一个节点之间 policy 生成的内容加环境转移。工具型 agent 里，一个节点就是一次 compaction 之后的状态：agent 带着压缩后的历史继续跑。

② 价值修正：critic 预测与续跑证据按「伪观测」加权

# 一层回传（与 TreeRPO 相同的 backup，而不是对所有后代结局直接取平均）
Ḡ(c) = (1/n(c)) · Σ_{c'∈ch(c)} ( R_{c→c'} + γ^{d} · Ṽ(c') )      # 终止节点 Ṽ=0

# 与 critic 预测混合，κ = critic 的「伪观测数」
Ṽ(c) = ( κ·V_φ(c) + n(c)·Ḡ(c) ) / ( κ + n(c) )                   # n=0 时 Ṽ=V_φ

# critic 回归固定目标
L_critic = E[ Σ_{c: n(c)>0} ( V_φ(c) − Ḡ(c) )² ]

# actor：段级 TD 残差当优势，广播到该段 policy 生成的 token（含 compaction token），观测 mask 掉
Â_i = δ_i = R_i + γ^{d_i}·Ṽ(c_i) − Ṽ(c_{i−1})
L_actor = −E[ Σ_i Σ_{t∈y_{e_i}} min(ρ_t Â_i, clip(ρ_t, 1−ε, 1+ε) Â_i) ]   # 标准 PPO clip

为什么不用「后代叶子结局的平均」？因为分配器是有选择地扩展节点的，某个节点下面的叶子不再是从该节点 on-policy 抽出的样本；一层一层回传各子节点自己的修正价值，可以把这种选择偏差挡在每一层内部。所有实验都取 γ=1、λ=0、κ=1——也就是说优势就是相邻两个 compaction 边界之间的单步 TD 残差（附录给出一般 TD(λ) 扩展），critic 只算 1 个伪观测，续跑一条之后两者等权。

③ 选点：Beta 后验 + 期望 MSE 下降

选点用的不是上面的递归 Ṽ，而是「直接观测到的续跑结局」：N(c) 是该节点被观测到的续跑结局数，Ḡobs 是它们的均值。对二值结局，以 critic 预测 v=Vφ(c) 为中心放一个强度 κ 的 Beta 先验： 

μ_obs = (κ·v + N·Ḡ_obs) / (κ + N)
ê²    = (v − μ_obs)² + μ_obs(1 − μ_obs) / (κ + N + 1)     # critic 的期望平方误差
σ̂²    = μ_obs(1 − μ_obs)                                  # 下一条结局的方差

MSE(N) = (κ²e² + N·σ²) / (κ + N)²                          # 混合估计的误差
g(c)   = −dMSE/dN = (2κ²·ê² + (N − κ)·σ̂²) / (κ + N)³       # 再采一条的边际收益

while B > 0 and 候选集 F = {非终止、可恢复、g>0} 非空:
    c* = argmax_F g(c);  ξ = Continue(c*, π_θ)   # 一路跑到终止，沿途按 compaction 切出新节点
    B -= ξ 新增的 task 转移数（执行失败也扣 1）
    更新 c* 及新节点的 N、Ḡ_obs；刷新 g
最后自底向上做一次 ② 的回传

直觉：critic 与已观测结局偏离越大（ê² 大）越值得采；已经采了很多（N 大）收益按 (κ+N)−3 衰减。工程上分配可以异步：在途续跑数 m 计入 Neff=N+m，每个节点最多 C=2 条并发续跑，全局受 worker 数 W 限制。

⑥ 最有信息量的现象：GRPO 后期工具调用塌缩

三个基准上，GRPO 训练后期每 episode 的平均 tool call 数都在塌缩，VinePPO 与 FOCUS 保持在初始水平附近。附录的轨迹显示 GRPO 越来越倾向于compaction 一结束就直接 submit，哪怕法规或仓库还没读完；DeonticBench 上 GRPO 的 held-out 曲线在中途见顶后回落。作者的解释是：轨迹级组内信用让「过早提交」这种短路行为很容易被强化（有一部分短轨迹恰好答对，就整体被加分），而 VinePPO 的后缀分叉和 FOCUS 的段级修正价值能把「这一段到底有没有推进」单独打分。这与 GACA、AHEAD 等步级信用工作的动机一致，但给了一个更直接的病理指标：盯 tool call 数。

⑦ 消融与诊断

  • 选点规则：以 n=16 条 MCTS 续跑均值为「真值」，在常数初始化和随机初始化两种劣质 critic 下，按 g(c) 选点比随机选点更快压低 critic MSE；直接按「critic 与观测的残差」排序效果很差。
  • critic 是否在学：LocBench 各 checkpoint 上，critic 值与 MCTS 目标的 Spearman 相关稳步上升。
  • 去掉修正续跑（BrowseComp-Plus）：只从题目根部采独立轨迹、价值全靠 critic，训练明显变慢，前期尤甚。
  • 换 compaction 算子（DeonticBench）：in-context 重写 vs in-memory workspace 表现接近。
  • 结构化压缩 prompt（LocBench）：强制 State / Evidence / Open questions / Next steps 四段、不合格式就拒收，曲线更平稳但峰值低于自由格式。

两点读法：(1) 「κ=1、N=0 时 g 恰为 0」（一般 κ 下 N=0 时 g=κσ̂²(κ−1)/((κ+1)κ³)，κ>1 才为正）意味着 FOCUS 不会在从未观测过结局的节点上「盲采」——候选点都来自已完成轨迹上的节点（它们一开始就各有 1 条后缀结局）。(2) 在这个没有树结构、没有共享前缀的扁平玩具里，按 g 选点并不比 round-robin 好，和随机差不多；按残差选点则明显最差（与论文「raw residual performs poorly」一致）。g 的单样本 Beta 后验很噪，它的优势要依赖论文那种设定：节点是同一棵树上的段边界，一次续跑同时给路径上多个节点带来观测，且对比对象是随机选点。复现时值得把 round-robin / 均匀分叉也作为基线。

实践建议

  • 先把 harness 做成可 fork：FOCUS 的前提是中间状态能「同上下文 + 同环境状态」恢复。工具环境要支持 snapshot / restore（参见 Sandbox Snapshots），否则分叉续跑在真实 sandbox 里做不出来或代价极高。
  • step 粒度用 compaction 边界：token 太细、整条轨迹太粗；compaction 段天然对应「一轮工作」，critic 的 horizon 以段计数也短得足以 bootstrap。即便不用 FOCUS，这也是给步级 critic 选 step 的好默认。
  • 监控 tool call 数和「压缩后立即提交」比例：GRPO 类轨迹级信用在长程任务上可能悄悄学会短路，reward 上升不代表行为健康；held-out 曲线中途见顶回落时先查这个。
  • 预算记账按 task 转移数：论文扣的是新增的环境步数，执行失败也扣 1；做 matched-budget 对比时要和 GRPO 的 group size 换算到同一口径。
  • κ 和 critic 规模：论文全程 κ=1、critic 与 actor 同为 9B；critic 很弱时 κ 小一点让证据快速接管，critic 训好后可增大 κ 省续跑。
  • 压缩 prompt 是 RL 超参：结构化与自由格式压缩的训练曲线形状不同，换压缩 prompt 等于换环境，要和 Compact-Bench 式的离线评估一起看。

思考题

1. FOCUS 的优势是 γ=1、λ=0 下的单步段级 TD 残差。它与 GAE 中 λ=0 的 TD(0) 优势有什么异同？为什么这里 λ=0 不会像经典 RL 那样带来大偏差？

形式上相同：Â=R+γV(s')−V(s)，只用相邻两个状态的价值。经典 TD(0) 偏差大是因为 V 来自一个可能很差的 critic；FOCUS 里的 Ṽ 不是裸 critic，而是 critic 与真实续跑结局的混合（κ=1 时采一条就各占一半），被分叉过的节点价值已部分由 Monte Carlo 证据决定，偏差被证据稀释。同时段数（compaction 次数）远少于 token 数，λ=0 的「短视」影响也小。代价是没被分叉的节点只能用 critic，偏差仍在——这也是为什么要按 g 把续跑投向 critic 最可能错的节点。参见 GAE。

2. 为什么价值回传用「一层一层回传子节点的修正价值」，而不是「该节点下所有叶子结局的平均」？

因为分配器只在 g 高的节点继续分叉，某节点子树中的叶子分布被选择过程扭曲：critic 估得差的分支会被过采样，叶子均值不再是该节点 on-policy 价值的无偏估计。一层回传时每个直接子节点等权（每个子节点代表从父节点出发的一次 on-policy 续跑），子树内部的过采样只影响该子节点自身的 Ṽ 精度，不改变它在父节点里的权重。

3. κ=1 时 g(c) 在 N=0 处恒为 0，N=κ 时退化为 2κ²ê²/(2κ)³。请解释这两个特例的含义，并说说异步分配时用 Neff=N+m 的目的。

N=0 时后验均值就是 critic 预测，ê² 只剩 Beta 方差项 σ̂²/(κ+1)，分子变成 κσ̂²(κ−1)/(κ+1)；κ=1 时为 0，g=0：没有任何证据时无法判断 critic 错没错，模型不认为再采有价值。N=κ 时方差项系数为 0，收益完全由「critic 与证据的偏离」驱动。异步时在途续跑尚未返回结果，若不计入，多个 worker 会同时扑向同一个 g 最大的节点；把 m 计入 N 让 g 提前衰减，起到「虚拟损失」（virtual loss，类似并行 MCTS）的作用，配合每节点 C=2 的并发上限。

4. 论文观察到 GRPO 后期 tool call 塌缩、compaction 后立即提交。从信用分配角度，为什么段级价值能抑制这种行为？

GRPO 的优势是轨迹级的：同一组里一条「早早提交恰好答对」的短轨迹拿到正优势，它的每个 token（包括「压缩后立即 submit」这个决定）都被同等强化。段级价值下，「compaction 后立即提交」这一段的优势是 R−Ṽ(压缩后状态)：如果从这个状态继续读资料的期望成功率更高（Ṽ 大），而这次提交的期望回报低，优势就是负的，哪怕个别样本碰巧答对。前提是 Ṽ 对该状态估得准——这正是在该节点分叉续跑的价值。

5. （开放题）box 玩具里按 g 选点没赢 round-robin。如果要在自己的 agentic RL 栈里决定是否上 FOCUS，你会设计什么实验来判断收益来自「主动选点」还是来自「有 critic + 段级信用」本身？

至少三臂、同一 matched 生成预算：(a) 段级 critic + 段边界均匀分叉（每个 compaction 点各采固定条数）；(b) 段级 critic + 随机选点分叉；(c) 段级 critic + g 选点（FOCUS）。再加 (d) 不分叉、只用 critic（论文的「去掉修正续跑」消融）和 GRPO 基线。(c) 与 (a)(b) 的差才是主动选点的贡献，(a) 与 GRPO 的差是「段级信用 + critic」的贡献。指标上除 held-out 准确率，还要看 critic 对 MCTS 真值的 MSE / Spearman、tool call 数曲线和每条轨迹的生成 token 数。树越深、共享前缀越多，(c) 理论上越占优；扁平任务上 (a) 可能已足够。
