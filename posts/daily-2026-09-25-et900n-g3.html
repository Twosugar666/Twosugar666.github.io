一线追踪｜ASUS ET900N G3：把 NVIDIA DGX Station 搬到桌边（GB300 / 748GB 一致内存）

2026-09-25 · 收藏夹：配件 / 显卡 · 一线追踪
来源：ASUS Blog · From AI Compute to AI Action: ASUS Zenni AI Hub and ExpertCenter Pro ET900N G3 · asus.com/blog · 2026-09-23。 交叉： NVIDIA Rubin、 Vera Rubin MLPerf、 ATX 3.1 / PCIe 5.1、 Topograph。

背景与动机

机架级 AI factory（NVL72、多机 NVLink / InfiniBand）解决「能训多大、能推多快」； 另一端是笔记本 / 工作站级本地推理，受显存与互联束缚。中间缺一块： deskside——数据不出楼、延迟可控、又不想上整机柜的超级工作站。

ASUS 2026-09-23 博客把 ExpertCenter Pro ET900N G3 定位为基于 NVIDIA DGX Station 架构的 deskside AI 超算，配套软件层 ASUS Zenni AI Hub（部署 LLM、RAG、模型路由、多 agent）。 下列性能与容量数字一律标注为厂商自报，非本站实测。

一句话：GB300 Grace Blackwell Ultra Desktop Superchip + 最高约 748GB coherent CPU–GPU memory； 厂商自报最高约 20 petaFLOPS AI、可撑约 1 万亿参数级本地工作负载； 卖点是「数据不出机房 / 延迟可控 / 对云 API 依赖下降」。

② 一致内存（coherent CPU–GPU memory）意味着什么

概念传统拆分一致内存叙事
地址空间 主机 DRAM ↔ 设备 HBM，显式拷贝 CPU–GPU 共享 coherent 空间，减少「搬了再算」
大模型瓶颈 往往卡在单卡 / 单节点显存墙 厂商用 ~748GB 统一池讲「桌边也能装下更大权重 / KV」
工程含义 PCIe 拷贝、分片、offload 脚本 仍要看驱动 / CUDA / 框架是否真正吃满一致性路径

站内 ATX 3.1 讲的是消费级供电与 PCIe 供电端子； ET900N G3 落在另一档：整机以 DGX Station 级 deskside 交付， 讨论重点从「600W 级显卡会不会熔端子」转向「统一内存池能不能撑住本地万亿级叙事」。

③ 软件层：ASUS Zenni AI Hub

能力（博客口径）作用
部署 LLM把模型装到本地 Station，而不是只调云端 API
RAG企业知识库落地；数据路径可控
模型路由按任务选模型 / 后端，降低「一个端点打天下」
多 agent 协作对接 agentic 工作流（规划 / 工具 / 多角色）

硬件给算力与内存；Hub 给「算完能干什么」。博客标题 From AI Compute to AI Action 就是在强调这一层：没有编排与 RAG / agent 壳，deskside 超算只是安静的机箱。

④ 与机架 NVL72 / 调度层对照

层站内文章回答的问题
芯片 / 机架吞吐 Vera Rubin MLPerf、Rubin NVL72 上「能跑多快」；集群级 scaling
Deskside Station 本文 ET900N G3 数据不出楼时，桌边能装多大模型、接什么软件壳
调度拓扑输入 Topograph 多机集群里谁和谁在同一 NVLink / leaf 域
消费级供电 / 配件 ATX 3.1 单卡工位能不能活、12V-2×6 风险

NVL72 与 Topograph 属于「机房里的 AI factory」；ET900N G3 属于「楼里的 deskside」。 隐私敏感、合规要求数据驻留、或对云 API 延迟 / 成本敏感的团队，会更关心后一档—— 但仍要用厂商基准与自有负载复测，不能把博客峰值当 SLA。

实践建议

  • 所有 FLOPS / 参数上限标「厂商自报」。 选型以自有模型（精度、上下文、批大小）压测为准。
  • 先定数据驻留需求，再选 deskside vs 云 vs 机柜。 合规与延迟是 Station 的主叙事；纯刷榜吞吐仍看 NVL72 类。
  • 把 Zenni Hub 当产品层，不是驱动层。 评估 LLM 部署、RAG、路由、多 agent 是否覆盖现有流水线；缺口仍要自研 harness。
  • 一致内存 ≠ 自动消除工程复杂度。 框架是否走统一地址、KV / 优化器状态如何放置，需要实测与 profiling。
  • 与机架方案分层预算。 deskside 服务「楼内试点 / 敏感数据」；集群服务「大规模训练与高并发推理」——别用一台 Station 替代拓扑感知调度。
  • 配件层对照别混。 消费级 ATX / 12V-2×6 经验不能直接外推 DGX Station 级整机。

思考题

1. 为什么 deskside DGX Station 与 NVL72 不是替代关系？

前者优化数据驻留、楼内延迟与单机大内存叙事；后者优化机架级吞吐与多节点 scaling。合规试点与刷集群吞吐的约束不同。

2. 「748GB coherent memory」解决的主要痛点是什么？

降低「权重 / KV 装不下单卡 HBM → 频繁 host–device 拷贝或粗暴 offload」的摩擦；是否吃满仍取决于软件栈。

3. Zenni AI Hub 相对「只卖硬件」多提供了什么？

部署、RAG、路由与多 agent 协作——把算力接到可运营工作流，对应博客从 Compute 到 Action 的主张。

4. 读 Topograph 文之后，为何仍可能需要 ET900N 这类机器？

Topograph 服务多机调度 locality；若工作负载根本不应出楼、或不值得上集群，deskside Station 是另一条产品线。

5. 选型时哪些数字必须自己复测？

目标模型的有效吞吐、首字 / 尾延迟、微调步时、多模态与 agent 工具调用开销，以及 Hub 路由策略是否匹配业务 SLA——博客峰值不能直接写进合同。
