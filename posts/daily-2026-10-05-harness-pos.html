学习笔记｜PoS：用显式 Belief State 管住长程 Agent，而不只是堆 Memory

2026-10-05 · 收藏夹：Harness / Agent · 学习笔记
论文：Luo, Jiang, Zuo, Wen et al. · Beyond Memory: Harnessing Long-Horizon Agents with Explicit Belief States · arXiv:2610.01415 · 项目页 / 代码见论文脚注（2026-10）。 交叉： EvoHarness-RL、 Context Compaction、 SUPO、 Growing Harness、 DENSE。

背景与动机

长程 Agent 的上下文管理，长期停在两条路：把轨迹原样堆着，或把历史压缩 / 检索 / 折叠成 memory。 两者都在优化「证据怎么存」，但不保证 Agent 对当前世界有一份可检查、可修订的估计——旧结论、冲突状态、已失效的中间判断，会跟着 history 一起漂进下一步决策。

PoS（Progression of States）把决策上下文从「memory as context」换成「belief as context」：在推理时持续维护显式 belief；用 Belief Sentinel 做一致性校验；再用三信号检测 Belief Trapping（还在动、但不朝目标推进），并按陷阱类型做因子化恢复。 这是 inference-time harness，不是再训一套策略。

机制拆解

① Belief 长什么样

任务条件化的 belief 写成四元组（论文式 (1)，此处用代码记法）：

B_t = (W_t, G, Delta_t^E, Delta_t^A)
# W_t : 任务相关世界状态 —— Entity / State / Relation（带来源、置信度、证据）
# G   : 目标与完成判据
# Delta^E : epistemic gaps —— 还不知道、证据不够的信息
# Delta^A : achievement gaps —— 相对目标态还差的动作结果

关键点不在「再发明一种 memory 结构」，而在把 还需要学什么 与 还需要做成什么 显式拆开，并选出一个 Active Gap 作为当前焦点，避免 gap 之间来回飘。

② Belief-Guided Interaction + Sentinel

步骤做什么防什么
选动作a_t ~ π(· | B_t, Δ_t, C_t)；正常时恢复约束 C_t 为空多 gap 抢焦点
候选更新观测后由 task agent 生成未提交的 ~B_{t+1}—
Sentinel审计新增/修改的 Entity·State·Relation·Gap；对照证据修订后再提交为 B_{t+1}内部冲突（如门既开又关）与外部冲突（与最新观测矛盾）

③ Belief Trapping：检测 → 诊断 → 恢复

在最近 K 步已校验转移上估计健康度（论文式 (5) 的结构）：

P_X   # gap persistence：窗口内仍未解决的 E/A gap 比例
S_t   # progress stagnation：无进展转移占比
R_t   # belief recurrence：相对 Active Gap 的世界态是否周期性重现
H_t = 1 - max_X[ P_X * max(S_t, R_t) ]
# H_t ≤ θ_H  → 判定 trapping

诊断两轴：

  • 动力学：Static（世界几乎不动）/ Cycle（周期重访）/ Drift（在动但不推进 Active Gap）；
  • 卡住的 gap 类型：E（缺判别证据）vs A（缺任务态变化）。

恢复约束 = 模式约束 ∪ gap 约束：打断无效转移 / 破环 / 重新锚定 Active Gap，并要求「新证据」或「任务相关状态变化」。健康度回升后释放约束。

LOCA-Bench 上下文从 8K 扩到 256K 时，PoS 在 96K–256K 段相对更稳，256K 上可领先最强基线约 10.67–16.00 points（作者自报）——因为决策锚定的是「当前 belief」，而不是在越来越长的历史上反复重建世界。

实践建议

  • 长程 harness 先问：决策读的是历史还是当前世界估计？ 只有 memory 时，补一层可校验的状态面往往比再加压缩更有效。
  • E/A gap 拆开写进 prompt 或结构化状态。 「还缺什么信息」和「还差哪步动作」混在一起时，最容易假忙。
  • 校验与恢复都要，不能只建 belief。 消融说明：脏更新和 trapping 是两类不同病。
  • 接受 inference 成本，监控 Task Agent token。 总 token 涨、任务侧降，才是「把算力花在维护上」的健康形状。
  • 和站内 EvoHarness 对照： EvoHarness 把 belief/progress/experience 训进运行时；PoS 是纯推理期维护。产品上可先 PoS 挂载，再考虑是否值得 RL。

思考题

1. 为什么「保留更多历史」不等于更好的长程决策？

历史混有过期事实与中间判断；没有显式当前世界估计时，模型每步都在隐式重建，错误会跨步累积。

2. Belief Trapping 和「动作循环」是一回事吗？

不是。动作重复可能仍在收集有用证据；PoS 看的是 gap 是否持续、进展是否停滞、相对 Active Gap 的信念是否复发。

3. 健康度为什么用 P·max(S,R) 而不是三者几何平均？

几何平均在 S 或 R 为 0 时会把整项打成「健康」；实践中「只停滞不复发」或「有复发但步进标签偶发为正」都应报警。

4. 何时 LongHorizon-Harness 可能够用、PoS 过重？

中间产物可独立验证、需求清单清晰的执行流；不确定假设演化为主的诊断/排查，PoS 的校验与恢复更对症。

5. PoS 不能替代什么？

工具执行能力与领域知识。论文也写明：Env.Ops 成功率仍偏低、ClinDiag 上「信息对了但解释错」仍会发生。
