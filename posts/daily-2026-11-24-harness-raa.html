学习笔记｜RAA：把「看历史有多清楚」也当成一种注意力——每条交互渲染成图，0.6B reranker 估决策相关度、GRPO 校准分辨率，视觉 token 按 s² 收；三个冻结 backbone 上每任务 token 降 51.5%–57.5% 且分数不掉

2026-11-24 · 收藏夹：Harness / Agent · 学习笔记
来源：Siqi Xiang、Zhipeng Xu、Shengrui Liu、Zulong Chen、Chunyan Miao、Shijian Lu（Nanyang Technological University；Zhipeng Xu / Zulong Chen 为 Alibaba Group；Shijian Lu 为通讯作者）· Resolution as Attention for Efficient Agent Memory Perception（arXiv:2611.24422，cs.AI / cs.CV，v1 页眉日期 2026-11-18；项目页 sxiangag.github.io/resolution-as-attention）。 数字均为论文自报：评测在 ClawGym-Bench 上、backbone 全程冻结、temperature=0；主表为单次运行。「box 小验证」一节为本文用纯 Python 写的玩具分配实验，不是论文复现。 交叉： 今日一线：DisSparse、 今日算法：量化三岔路、 Context Compaction、 Compact-Bench、 Cache Engineering、 上下文再观测、 Spine。

背景与动机

长程 agent 的记忆管理过去只问两个问题：留什么（摘要、裁剪、检索）和什么时候取回来。本站的 Context Compaction、Compact-Bench、Cache Engineering 都在这条轴上。RAA 提出第三问：每条历史要以多高的清晰度被读到？

直觉来源是人类视觉：注意力不只体现为“看哪里”，也体现为“看得多清楚”。把历史渲染成图片后，分辨率就是可调的旋钮——视觉 token 数随缩放因子平方下降，缩小一半只花四分之一 token。但已有 optical context compression 通常对所有历史用同一压缩率或固定策略（例如“最近 5 轮保原图、其余减半”），于是无关交互浪费 token，关键细节又可能看不清。

RAA 的主张：分辨率分配应逐交互、逐步重算。四十步前不起眼的配置值可能正是当前决策的依赖，而语义相似度高的段落未必真的影响下一步；因此不能拿 reranker 的语义分数直接使用，要先对齐到“下一步决策依赖度”，再对齐到“agent 实际需要看清到什么程度”。

机制拆解

① 文本渲染成图：token 数按 s² 缩放

每条历史 h_i 在首次出现时渲染成一张规范图像 I_i = R(h_i)，整段任务内不再重渲染；每一步按当前尺度 s_i ∈ (0,1] 缩放它再喂给视觉 agent。对把 P×P patch 映射成一个视觉 token 的编码器： 

Ñ_i = Resize(I_i, s_i)
N_i(s_i) = ceil(s_i·W_i/P) · ceil(s_i·L_i/P) ≈ s_i² · N_i(1)

M_t = { Resize(I_i, s_i^(t)) } for i = 1..t-1

关键点：每一步都可以用新尺度重新感知同一张图，且每次缩放都从规范图出发、不从上次缩略图再缩，避免信息逐轮劣化。最新一条交互 h_{t-1} 作为 query 保留文本形式，不参与缩放。agent 本身（Qwen-3.8-27B 等）全程冻结，不需要为感知层做额外训练。

② 相关度估计：语义相似 ≠ 决策依赖

估计器 f_θ 从 Qwen3-Reranker-0.6B 微调而来，query 是任务描述 D + 最新交互，key 是每条历史，取 yes/no logit 的 sigmoid 作为分数：p_i^(t) = σ(z_yes − z_no)。每条历史独立打分，不被长历史里其它条目稀释；query 每步更新，所以同一条历史的相关度会随任务推进变化。

③ 归一化 sigmoid 映射：把相关度变成尺度

g_φ(p) = [σ(k(p−b)) − σ(−kb)] / [σ(k(1−b)) − σ(−kb)]

φ = {k, b}: k>0 控制过渡陡峭程度，b∈(0,1) 决定中点
g_φ(0)=0, g_φ(1)=1，且单调 —— 保持相关度排序，同时铺满整个尺度范围

④ 两阶段训练：先蒸馏决策依赖，再用 GRPO 校准“看得清”

阶段学什么监督 / 奖励数据
Stage I：relevance supervision估计器 f_θ密度加权 MSE：L = E[w_i^(t)(p_i^(t) − p̂_i^(t))²]，w 与评分密度成反比1,853 个 ClawGym 训练任务的高分轨迹、12,000 条决策历史；教师 Qwen-3.8-27B 预判下一步动作后给每条历史打 0–1 依赖分
Stage II：resolution reinforcementf_θ + 映射 g_φ 联合校准GRPO over K 个采样尺度；奖励 = 决策保真 + λ·节省 token150 次更新；agent 冻结

Stage II 把 g_φ∘f_θ 当随机策略：对单条历史，从 logit-normal 采样尺度 s_{i,j} = σ(logit(s_i^(t)) + τ ε_j)，ε_j~N(0,1)，其他历史保持预测尺度，得到 K 份只在一条历史上清晰度不同的 memory。奖励是： 

R_j = [ l̄(a_t | D, M_t^(j)) − l̄(a_t | D, H_t) ]  +  λ · (1 − s_{i,j}²)
       └──────── 决策保真：冻结 agent 对原动作的对数似然 ────────┘   └ token 节省 ┘

J(θ,φ) = E[ (1/K) Σ_j A_j · log q_{θ,φ}(s_{i,j}) ]   # 组内相对优势 A_j

用 1 − s² 近似节省比例，正好对应前面的平方 token 关系；H_t（完整文本历史）作为决策保真的参考。λ 越大越省 token：论文扫 0.5×10⁻³ 到 4×10⁻³，更大的 λ 会降低平均分、增加步数，tokens/task 先降到约 33K，到 λ=4×10⁻³ 又升回约 40K——因为多出来的步数吃掉了单步节省。

box 小验证：平方缩放与“按需清晰”

纯 Python 玩具：8 条历史，相关度 [0.95, 0.15, 0.60, 0.10, 0.80, 0.20, 0.35, 0.05]；每条全分辨率按 100 token 计，缩放后的视觉 token 近似 s²×100；保真代理量取 Σ relevance·(0.3+0.7s)。这些公式沿用论文，输入是虚构的。

def report(tag, scales):
    tok = sum(max(1, round(s*s*100)) for s in scales)
    fid = sum(ri*(0.3+0.7*s) for ri, s in zip(r, scales))
    print(tag, tok, fid)

report("uniform s=1.0",      [1.0]*8)
report("uniform s=0.7",      [0.7]*8)
report("adaptive RAA-like",  [max(0.25, 0.25+0.75*ri) for ri in r])

BOX B 输出（玩具，不是论文数据）：
  uniform s=1.0     : tokens  800 (  0.0% saved), fidelity 3.200
  uniform s=0.7     : tokens  392 ( 51.0% saved), fidelity 2.528
  adaptive (RAA-like): tokens  288 ( 64.0% saved), fidelity 2.623

读法：均匀缩到 0.7 已经省 51% token，但保真代理量掉 21%；按相关度分配在更省（64%）的同时保真反而高于均匀缩放。方向和论文 Table 2 一致：均匀 s=0.70 掉到 75.81 分，RAA 用 38.2K token 拿到 78.69。玩具里的幅度更大，是因为相关度与尺度映射被我设得过于理想化。

思考题

1. 为什么不能直接用 Qwen3-Reranker-0.6B 的语义相似度来分配分辨率？

语义相似回答的是“这段文本和当前查询主题相关吗”，决策依赖回答的是“下一步动作有多依赖这条历史”。二者相关但不等价：一条语义上完全对题的历史可能早已被后续步骤覆盖，而一个不起眼的配置值（比如某次工具返回的错误码）可能直接决定下一步要不要重试。论文 Figure 3 的消融印证了这点：直接用预训练 reranker 的尺度中位数是 0.98，几乎全分辨率，只省很少 token；Stage I 用教师模型的依赖标注蒸馏后，估计器才学会区分。Stage II 再校准到 agent 真能读清的尺度。

2. Stage I 和 Stage II 为什么缺一不可？只看论文表格不够，说说机制。

Stage I 解决“估得对”：把 reranker 的语义分数对齐到决策依赖，否则 Stage II 的奖励信号再准也是在优化错误的变量。Stage II 解决“用得对”：相关度高不等于必须满分辨率，取决于 agent 的视觉识别能力；同时估计器与映射的联合校准让尺度真正铺开。只看 Stage I，映射未校准，尺度中位数被压到 0.5 以下，77.12 分；只看 Stage II，估计器仍在用语义相似，token 降到 44K 以上、分数只有 77.92。两者合起来才 78.69 / ≈38K。

3. 奖励里的 λ(1−s²) 为什么用平方，而不是线性 (1−s)？

因为视觉 token 数近似与缩放因子的平方成正比（论文 Eq. 3：N(s)≈s²·N(1)）。若写线性项，奖励会高估低分辨率的收益：把 s 从 1 降到 0.5 实际只省 75% token，线性项只给 50%。用平方项才能让“省下的 token”与奖励尺度一致。论文的 λ 扫描也显示这个代理量不是完美替代：λ 太大时 agent 要多走步数，总 token 反而回升，说明单步视觉 token 不等于任务总 token。

4. RAA 与 Compaction / A-MEM 是竞争还是互补？

互补。Compaction / 摘要 / 检索决定哪些信息还在上下文里，RAA 决定留下来的信息被看得多清楚。论文 Table 3 把 RAA 挂到 ACON（摘要）、A-MEM（检索）、Observation Masking（掩码）上，分别再省 22.5%、44.7%、54.1% token，且分数不降。值得注意的是 RAA 单独用的 token 已少于三者中的任何一个，说明“看得清楚”这一维度此前确实被系统性忽略。本站 上下文再观测 和 Spine 分别从“何时再看一次”和“按子任务树组织”切入，可以和 RAA 组合。

5. （开放题）把 RAA 用于纯文本 backbone 需要改什么？

需要换掉感知介质：纯文本模型没有视觉 token 的平方缩放，可以把“清晰度”实现为不同程度的文本压缩粒度（保留原文 / 保留关键句 / 保留关键词），并按 token 数建立类似的成本项；估计器与两阶段训练仍可复用，但要重新定义“决策保真”的可微代理。另一个思路是让文本 backbone 读 OCR 后的多尺度图，但那会引入识别误差——论文 Table 2 里 top-k 文本版 k=5 比 RAA 高 0.29 分却多花 61% token，作者明确把这点归因于图像读字的误差，纯文本路线未必更差，值得单独验证。
