学习笔记｜MQA → GQA → MLA：KV cache 压缩的三代注意力——从「删掉 K/V 的 head 维」到「低秩 latent + 矩阵吸收 + decoupled RoPE」

2026-10-19 · 收藏夹：算法 / Infra · 学习笔记
经典来源：Noam Shazeer · Fast Transformer Decoding: One Write-Head is All You Need（arXiv:1911.02150，2019）； Joshua Ainslie、James Lee-Thorp、Michiel de Jong 等 · GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints（arXiv:2305.13245，EMNLP 2023）； DeepSeek-AI · DeepSeek-V2 §2.1 MLA（arXiv:2405.04434）。 公式与实验数字按原文；每 token KV 元素数为按原文配置自行计算；numpy 小实验为本文在 box 上实跑。 交叉： Attention 基础、 KV cache 的一生、 RoPE、 FlashAttention、 MoE 路由、 今日一线：远端 KV tier。

背景与动机

训练时 attention 可以沿序列并行，算术强度很高；推理的增量 decode 却每步只来一个 query，必须把整段 K/V 从显存读一遍。Shazeer 2019 把这件事写成了一个干净的比值：在 m=n、k=v=d/h、n≤d 的简化假设下，批量 MHA 的「访存 / 计算」比是 O(1/k + 1/(bn))，而 n 步增量 MHA 是 Θ(n/d + 1/b)。1/b 可以靠加大 batch 摊掉（显存允许的话）；n/d 这一项来自每步重读大小为 b·h·m·k 的 K/V，序列一长就把 decode 钉死在带宽上。

之后五年，减少「每 token KV 字节数」成了架构设计的一阶目标。本篇把三代方案放在同一套记号里讲：MQA 删掉 K/V 的 head 维，GQA 在 MHA 与 MQA 之间插值并给出从 MHA checkpoint 迁移的配方，MLA 改走低秩联合压缩、用矩阵吸收避免还原 K/V、再用 decoupled RoPE 补上位置编码的缺口。今天一线篇里 GLM-5.3 那个「48.4 KB/token、TP 切不小」的 MLA 状态，就是本篇最后一节的直接应用。

机制拆解

② MQA：所有 query head 共用一份 K/V

# MHA（Shazeer 的 einsum 记号）
K = einsum("bmd,hdk->bhmk", M, P_k);  V = einsum("bmd,hdv->bhmv", M, P_v)
# MQA：把 K、V、P_k、P_v 里的 h 维删掉，Q 与 P_o 仍保留 h
K = einsum("bmd,dk->bmk", M, P_k);    V = einsum("bmd,dv->bmv", M, P_v)
logits = einsum("bhnk,bmk->bhnm", Q, K)

③ GQA：分组共享 + 从 MHA checkpoint uptrain

# 把 H 个 query head 分成 G 组，每组共享一个 K head、一个 V head
GQA-1 ≡ MQA        GQA-H ≡ MHA        1 < G < H：插值
KV cache 与读带宽 ∝ G

# Uptraining 配方（Ainslie et al.）
1. 转换 checkpoint：组内原 K/V 投影矩阵做 mean pooling → 新的组 K/V 投影
   （优于「取组内第一个 head」，后者又优于随机初始化——按保留预训练信息的程度排序）
2. 用原预训练配方继续训原步数的 α 比例（主实验 α = 0.05，T5-XXL 约 600 TPUv3 chip-days）
T5.1.1（论文 Table 1）T_infer（s / sample）平均分
MHA-Large0.3746.0
MHA-XXL1.5147.2
MQA-XXL（5% uptrain）0.2446.6
GQA-8-XXL（5% uptrain）0.2847.1

要点有三。其一，GQA 转换后不训也已「可用」，MQA 则必须 uptrain；两者 5% 时收益明显、到 10% 收益递减。其二，从 1 组到 8 组推理只慢一点，越接近 MHA 代价越陡，8 组是作者选的折中。其三是一条容易被忽略的系统论据：大模型做张量并行时，MQA 的唯一 K/V head 要在每个分片上复制，GQA 让 KV head 数与分片数对齐，去掉这份浪费。论文只把 GQA 用在 decoder self-attn 与 cross-attn 上，encoder self-attn 并行计算、不是带宽瓶颈。

④ MLA：低秩联合压缩 + 矩阵吸收

# DeepSeek-V2 式 (9)–(11)：h_t ∈ R^d 为该层输入
c_t^{KV} = W^{DKV} h_t            # ∈ R^{d_c}，d_c ≪ d_h·n_h —— 推理时只缓存它
k_t^C    = W^{UK} c_t^{KV}        # 上投影还原每头 key
v_t^C    = W^{UV} c_t^{KV}        # 上投影还原每头 value

# 吸收（absorb）：对第 i 个头
q_{t,i}^T k_{j,i}^C = q_{t,i}^T W_i^{UK} c_j = (W_i^{UK T} q_{t,i})^T c_j
  ⇒ W^{UK} 可并入 W^Q：query 直接投到 d_c 维 latent 空间与 c_j 点积，不必还原 K
o_{t,i} = Σ_j p_{ij} W_i^{UV} c_j = W_i^{UV} (Σ_j p_{ij} c_j)
  ⇒ W^{UV} 可并入 W^O：先在 latent 上加权求和，最后再上投影

# 另对 query 做低秩压缩（d_c' = 1536），只为省训练激活，不影响 KV cache

吸收之后，decode 时每个头都在同一份 d_c 维 latent 上做 attention——从计算形态看，它等价于一个「head 维为 d_c(+d_h^R)、所有 query head 共享 K/V」的 MQA，只是每个头带着自己的吸收后投影。这解释了为什么它的 cache 体积像 GQA-2.25、而表达力不输 MHA：缓存的是共享 latent，「多头」被搬进了 query/output 侧的投影里。 

# numpy 小实验（box 上实跑；d=512，n_h=8，d_h=64，d_c=128，T=16，随机权重）
max |score_naive − score_absorbed| = 2.78e-17
max |out_naive   − out_absorbed|   = 2.43e-17     # 浮点误差级，吸收是精确等价变换

⑤ Decoupled RoPE：为什么 RoPE 和吸收打架

# 若直接对 k_t^C 加 RoPE：q^T R_t^T R_j W^{UK} c_j —— 一个与当前位置有关的旋转夹在 W^Q 与 W^{UK} 之间
#   矩阵乘不交换 ⇒ W^{UK} 无法再并入 W^Q ⇒ 推理时要为全部前缀重算 key，吸收的收益全丢

# DeepSeek-V2 式 (14)–(18)：另开一条专门承载位置的小通道
q_t^R = RoPE(W^{QR} c_t^Q)          # 每头 d_h^R 维
k_t^R = RoPE(W^{KR} h_t)            # 所有头共享一个 d_h^R 维 key —— 也要缓存
q_{t,i} = [q_{t,i}^C ; q_{t,i}^R],  k_{t,i} = [k_{t,i}^C ; k_t^R]
o_{t,i} = Σ_j softmax_j( q_{t,i}^T k_{j,i} / sqrt(d_h + d_h^R) ) v_{j,i}^C
总 KV cache = (d_c + d_h^R) · l     # DeepSeek-V2：d_c=512，d_h^R=64

这其实是把 RoPE 的「相对位置只出现在 q·k 内积里」这一性质，限定在一个小的、MQA 式共享的子空间里：内容部分走可吸收的 latent，位置部分走 64 维共享 key。DeepSeek-V2 后续用 YaRN 做长上下文外推，也只需作用在这条 RoPE 通道上（RoPE 篇已讲）。

⑦ 与并行策略的相互作用（系统视角）

方案张量并行（按 head 切）上下文并行（按序列切）
MHAKV head 随 query head 一起切，各 rank 各存 1/TP各 rank 存自己那段，按需交换
GQATP ≤ n_g 时干净切分；TP > n_g 时 KV head 需复制同上
MQA唯一 K/V head 在每个 rank 上复制（GQA 论文指出的浪费）同上

实践建议

  • 评审模型先算「每 token 全层 KV 字节」。 用 ① 的公式乘以存储位宽；它和参数量一样是一阶指标，直接决定并发、最长上下文和远端 cache 的断点带宽（一线篇 B* = sR 里的 s）。
  • 已有 MHA checkpoint 想提速，优先 GQA uptrain。 mean pooling 转换 + 约 5% 原预训练步数；组数按「TP 度的整数倍」选，避免 KV head 复制。
  • MLA 实现区分 prefill 与 decode 两条路径。 常见做法是 prefill（compute-bound）显式上投影出 K/V 走标准 attention kernel，decode（memory-bound）走吸收形式直接在 latent 上算；两条路径要做数值一致性测试，否则训推不一致会进 RL 的 IS 比值。
  • RoPE 通道单独对待。 长上下文外推（YaRN 等）、KV 量化时，d_h^R 那 64 维与 latent 的数值分布不同，宜分开设定 scale。
  • MLA + TP 不要指望省 KV。 每 rank 都是全量 latent；要扩并发，靠 DP / 上下文并行 / 远端分层，而不是加 TP。
  • 别把「KV 小」当成万能。 MLA decode 时每头的点积维度变成 d_c + d_h^R（576），算术强度上升；在 batch 很大、已 compute-bound 的场景，收益会收窄。

思考题

1. 用 Shazeer 的比值说明：为什么「把 batch 开大」能解决 MHA decode 的 1/b 项，却解决不了 n/d 项？MQA 如何改变后者？

1/b 来自每步都要读一遍投影权重（nd² 量级访存被 b 条序列共享），batch 越大摊得越薄。n/d 来自每条序列自己的 K/V（b·h·m·k 量级），它随 batch 线性增长，不能被摊薄；batch 开大反而让 K/V 总量更大、更受显存容量约束。MQA 删掉 K/V 的 h 维，使这项变为 n/(d·h)，即每条序列的 K/V 读取量除以 h。

2. GQA 的 mean pooling 转换为什么比「取组内第一个 head」好？从函数近似角度给一个直觉。

组内各 head 的 K/V 投影捕获的是不同子空间的特征；取第一个 head 等于丢掉其余 head 的全部信息，模型要在 uptrain 中重新学习；mean pooling 得到的投影是组内投影的线性平均，在「组内 head 相似」的程度上近似保留了每个 head 的输出（对线性层而言，平均投影的输出就是各 head 输出的平均），给 uptrain 一个更接近原函数的初始化。论文的排序 Mean > First > Random 正对应保留信息的多少。

3. 写出 MLA 中 W^{UV} 被吸收进 W^O 的推导，并说明为什么吸收在 prefill 阶段不一定划算。

o_{t,i} = Σ_j p_{ij} W_i^{UV} c_j = W_i^{UV}(Σ_j p_{ij} c_j)，输出 u_t = W^O[o_{t,1};…] = Σ_i W_i^O W_i^{UV} (Σ_j p_{ij} c_j)，故 W_i^O W_i^{UV} 可预先合并。prefill 时 query 数等于序列长度，吸收形式要求每个头都在 d_c(+d_h^R) 维上做 n×n 的点积与加权和，比在 d_h 维上计算的 FLOPs 更多；prefill 是 compute-bound，多出的 FLOPs 直接变成时间。所以常见实现 prefill 时显式还原 K/V，decode 时（memory-bound、只读 latent 更省带宽）用吸收形式。

4. 为什么 decoupled RoPE 的 k^R 设计成所有头共享，而 q^R 是每头一份？如果 k^R 也每头一份，KV cache 变成多少？

k^R 需要缓存，每头一份会让缓存增加 n_h·d_h^R；共享一份只增加 d_h^R，等价于在位置通道上用 MQA。q^R 不缓存，每头一份不增加 KV 代价，还保留了各头在位置敏感性上的差异。若 k^R 每头一份，按 DeepSeek-V2 配置每层每 token 为 512 + 128×64 = 8,704 个元素（本文推算），是 576 的约 15 倍，MLA 的优势大半消失。

5. （开放题）一个 32B dense 模型要服务 128k 上下文的 Agent 负载，在 MHA / GQA-8 / MLA 之间选型，你会看哪些量？与今天一线篇的远端 KV tier 有什么联系？

可讨论方向：(a) 每 token KV 字节 × 上下文 × 并发 → 单卡能容纳的会话数；(b) 质量：自己的评测上 GQA 与 MHA 的差距是否显著（GQA 论文与 DeepSeek 消融结论强弱不同）；(c) 并行：计划的 TP 度与 n_g 是否对齐，MLA 下 TP 不省 KV；(d) 是否已有 MHA checkpoint（GQA 可 uptrain，MLA 通常需要从头训或专门转换）；(e) 远端 cache：s 越小，B* = sR 越低，同样的存储带宽越容易回本——KV 架构选型会改变整个 cache 分层的经济性；(f) RL 训练时 prefill/decode 两条 kernel 路径的数值一致性。
