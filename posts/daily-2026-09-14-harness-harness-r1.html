学习笔记｜Harness-R1：用在线 RL 训练「会改可执行运行时」的 harness 工程师

2026-09-14 · 收藏夹：Harness / Agent / RL · 学习笔记
Shao, Zhang, Li 等 · Harness-R1: Learning to Edit Executable Runtime Harnesses from Agent Failure Trajectories · arXiv:2608.02276 · 代码 DeepExperience/Harness-R1 · 模型 HF。 交叉： EvoHarness-RL、 HarnessEvolve、 HarnessDev、 Harness 运行时、 GRPO。

背景与动机

部署中的 Agent 不断产出轨迹，但行为往往停在「权重固定」：要么再训模型，要么手改 / 提示大模型去改 harness。 站内最近几篇（HarnessDev、HarnessEvolve、EvoHarness-RL）分别在谈「评测可运行 harness」「自演化信用」「学 harness 使用策略」。

Harness-R1 换了一个学习目标：不训目标 Agent，而是后训练一个独立的 harness engineer——读失败轨迹批次，生成可验证的可执行 patch，用「同一批任务重跑后的回报差」做 outcome reward，在线 GRPO 只更新工程师。

一句话：失败包 → 生命周期四处 hook 的可执行 overlay → 冻结目标同批重跑得 ΔR → SFT 冷启动 + GRPO；改的是编辑策略，不是任务答案。

机制拆解

① 问题形式：batch-conditioned、同批重跑

# 冻结目标 Agent A（模型 + 基座运行时）
# 批次 B = {x_i}，先跑基线得 R_i^0 与失败包 s_B

工程师 H_θ(s_B) → 可执行 overlay P
安装 P 后，同一批 B 全部重跑（含原本成功的题）→ R_i^P

Δ_B(P) = mean_i (R_i^P − R_i^0)
r(B,P) = Δ_B(P)  if P 合法且评估完整 else 0

同批前后对照控制了任务组成，但是转导式目标：优化的是这批任务上的增益，跨批持久 patch 记忆不在本文设定里。 非法 / no-op / 未完成评估一律奖励 0——逼工程师产出能装上、能跑完的真实干预。

② 可编辑表面：四个生命周期 hook

Hook时机典型效果
on_init首轮决策前注入可复用技能 / 工具提示
make_pre_hint每次决策前按状态加消息，不直接执行动作
on_before_action动作出模型后、进环境前拦截重问 / 改写 / 强制动作（视环境）
on_post_step环境反馈后注入恢复提示；部分环境可调度下一步

Patch 只碰冻结策略的输入输出，不改权重。安装前校验；无效 patch 等价无干预。 消融（论文 Figure 4b）显示：去掉 pre-action 或 post-feedback 掉分最大（约 −3.9 / −3.3 pp），且主导位置随环境变——WebShop 偏动作门控，ALFWorld 偏反馈后恢复。

③ 训练：SFT 冷启动 → outcome-grounded GRPO

# 冷启动：强教师（论文用 GPT-5.5）对失败包提 patch
# 校验 + 同批重跑后保留「可执行、完整、非回归」样本 ≈1K

# 在线 GRPO：每个失败包采 K=8 候选
# 各自独立安装并重跑冻结目标 → 组内 (r−μ)/σ 作优势
# 序列级优势广播到响应 token；带 TIS 截断权重（上限 2）
# 无 format bonus、无显式 KL loss；只更新工程师 θ

关键点：奖励不可微，且只有「改完再跑」才观测得到——所以必须把工程师从固定 proposer 升级成可学习策略。 对比：多数 harness 搜索管线（Meta-Harness / AutoHarness / AEGIS 等）用结果筛选候选，但不更新 proposer 参数；HarnessX 的 cross-harness GRPO 训的是任务模型。

⑤ 与 EvoHarness-RL / HarnessEvolve 的分工

学什么目标是否冻结
EvoHarness-RL如何读/写外部 BPE 状态（harness 使用策略）训任务策略
HarnessEvolve脚手架自演化 + 双门控改 harness 工件

实践建议

  • 先把 hook 契约写死：init / pre-hint / pre-action / post-step 的返回类型与「能否改写动作」按环境分档（DBBench 论文里禁止改 SQL / 强制 commit）。
  • 奖励必须 outcome-grounded：只看 patch 文本是否「看起来合理」会学到有害干预；同批重跑 ΔR（含负值）才是监督。
  • 非法与未完成一律 0：与「小负分」不同，0 避免鼓励半吊子 patch，但也要靠校验覆盖率保证组内仍有可区分信号。
  • SFT 过滤要严：教师候选需可执行、跑完、非回归；否则 GRPO 起点全是会编译但不提分的噪声。
  • 共演化是产品路径：先 Agent SFT 再训目标专用工程师（+5.0）说明 harness 编辑不会在「模型变强后」自动失效——两条改进轴应交替迭代。

思考题

1. 为什么同批重跑要包含原本已成功的任务？

只优化失败子集容易引入回归：patch 可能用过宽规则伤害原已成功轨迹。全批 ΔR 把回归直接写进奖励。

2. 固定 Self-Refine 为何可能掉分？

统一手写规则忽略具体失败模式与是否真有收益；论文匹配基线显示 Self-Refine 在三环境平均掉分。失败条件生成 + 重跑验证才是自适应编辑。

3. Harness-R1 的「转导式」目标有什么局限？

奖励绑定挖掘失败的那批任务，不显式优化 held-out 或推理成本。论文讨论可把 held-out 表现与效率项并入奖励。

4. 为何 9B 工程师能打过更大的前沿「提示式编辑器」？

前沿模型优化的是「补丁看起来对」；Harness-R1 优化的是「重跑后任务是否真涨」。尺度换不来 outcome 闭环。

5. pre-action 与 post-feedback 哪个更重要？

没有普适答案：WebShop 上动作门控关键，ALFWorld 上反馈后恢复关键。多 hook 协同，消融数字不可简单相加当成全局重要性排序。
